**Write chain (uniform, verified in every impl).** (1) canonicalize timestamps (`canonicalize_utc_timestamp` / `canonicalize_task_timestamps`), (2) pure `validate_*` preflight, (3) build aggregate JSON with `canonical_json`, (4) `BlobStore::put(workspace, BlobPurpose::AggregateState, bytes, media-type)`, (5) **read back and byte-compare** (`blobs.get(...) != bytes → StoreError::Integrity`), (6) build `AggregateStateRef { blob, entity_revision: <version>, record_schema_version: 1 }`, (7) submit `Command`, (8) writer thread opens `TransactionBehavior::Immediate` and revalidates the same facts before insert, (9) `request_dedup` receipt row in the same transaction. Blob bytes are written *outside* the SQL transaction; the SQL step re-checks the expected version, so a racing writer fails CAS and the orphaned blob is collected later by the `*_blob_registry` GC paths.

**Writer engine.** `writer_loop` (line 19577) opens+migrates on the writer thread, sends readiness once, then `while let Ok(command) = receiver.recv()`; `Command::Operation` executes the closure with `&mut Connection`; typed variants wrap `transaction_with_behavior(Immediate)` + commit; `Command::Shutdown => break`. Each migration is recorded by name *and* re-executes the DDL text, so the DDL files must be re-runnable/idempotent up to their version.

## Cross-cutting observations

**Implemented architecture.** Event-sourced aggregates with state snapshots in an encrypted `BlobStore`; SQL holds only indexes, receipts, and event metadata. Strictly one writer thread per `SqliteWorkspaceStore`, `IMMEDIATE` transactions, CAS on `version`/`progress_version` at the SQL layer, receipt-before-effect idempotency, and blob durability verified by read-back. This matches ARCHITECTURE.md's "Workspace is the security/resource boundary" and "Reported/observed/committed/verified are different" (commit is only claimed after `blobs.get` equality and the SQL commit).

**Divergences / tensions visible in code.**
1. **Task planning is closed, not merely unqualified.** `require_task_planning_isolation_admission()` returns `TASK_PLANNING_ISOLATION_UNAVAILABLE` and is called at the top of *both* `start_task_planning_session` and `activate_task_planning_session`, before blob writes, receipts, or event insert. So `AgentSessionScopeKind::TASK_PLANNING` can never reach `ACTIVE`, and the `READY → RUNNING` transition (`LEAD_PLANNING_SESSION_READY`) is dead code in this revision. If `docs/STATE-MACHINES.md` or the release contract describes planning sessions as reachable, that is a docs-vs-code divergence to record; I did **not** read `docs/STATE-MACHINES.md` (out of bucket), so the doc side is unverified.
2. **Two command-extension mechanisms.** The `Command::Operation` doc comment says new aggregates should add no central variant, yet ~150 typed variants exist and both are live. Readers cannot enumerate writes from the enum alone.
3. **Storage re-validates event payload shapes.** Full `json!` equality checks per event type put payload schema in `lib.rs`, competing with `docs/schemas/` as the single schema authority — a "parallel schema authority" risk relative to the repo rule.
4. **Planning session status vocabulary is incomplete.** Only `STARTING`, `ACTIVE`, `LOST` appear; there is no `CLOSED`/`FAILED` transition in this file, so session terminal states beyond `LOST` must live in `conversations.rs`/`coworkers.rs` (not in bucket).
5. **Reads are serialized behind the single writer connection** — no read-only pool. Under the 64-deep bounded queue this makes search/materialization latency a global write-path concern (`MAX_SCAN_CANDIDATES = 200`, `MAX_SCAN_BYTES = 64 * 1024 * 1024` bound the blast radius).
6. **`#[allow(dead_code)]` reserved command** and `PACKAGE_SERVICE_NOT_QUALIFIED` re-export indicate deliberately unreachable V1 surfaces; these should not be read as SERVED.

**Load-bearing invariants (quoted).**
- `"BlobStore did not durably verify aggregate state"` — put-then-get byte equality before any state ref is published.
- `"Workspace event revisions are not contiguous"` — `event.entity_revision != state_ref.entity_revision || != previous_revision + 1`.
- `"Resource content does not match its immutable revision"` — `content.len() != summary.size_bytes || digest(&content) != summary.content_digest`.
- `"Resource revision content changed during read admission"` — re-read under the digest lock must return the same blob.
- `"SQLite did not enable WAL mode"` / `"foreign-key enforcement is unavailable"` / `"SQLite {version} is older than the required 3.38"`.
- `"archived Workspace is read-only"`.
- `"unchanged Task must not append a status event"`.
- `"PlanRevision must be positive"` (`plan_revision == Some(0)` rejected).
- `"Resource index has too many retained key versions; reindex before writing"`.
- `"writer queue capacity must be greater than zero"`.
- `"SQLite state directory grants group or other access"`.
