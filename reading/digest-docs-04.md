## Cross-cutting observations
- **The bucket is dominated by one admission gap.** Three independent owner docs converge: ARTIFACTS-EVIDENCE ("Effect proposal persistence is not dispatch admission"; `STARTED` rejected with `TrustDecisionUnavailable`/`InvocationTransitionWriterUnavailable`/`ApprovalUseConsumptionUnavailable`), CAPABILITY-INVOCATIONS ("external provider dispatch is unavailable"; no creation/dispatch op, no atomic `ApprovalUse` consumer), and the DESKTOP audit (Task/Attempt drain, Effect reconciliation and lease fencing "not integrated"). The design is consistently fail-closed rather than optimistic — the honest claim is TARGET, not CODE.
- **Lifecycle identities as this bucket states them.** `Runtime` / `RuntimeIncarnation` appear as fenced identity (Effect/lease/descriptor checks, `runtimeIncarnationId` in the catalog projection, `bootstrapOperatorIpc(osPeerIdentity, RuntimeIncarnation)`, ADR-0021 "installation-scoped Runtime and each lock-holder incarnation"). `AgentSession` is the only session identity, always Attempt- or Conversation-scoped, never revived (`CLOSED`/`LOST`, replacement gets a fresh projection). `Environment` splits into lifetime vs `EnvironmentSharingScope`, with `EnvironmentControlLease` as the single-actor fence and `USER_SHARED` reserved. **`AgentHostInstance` is never named as a record in this bucket** — only `AgentHostSupervisor` as its owner (DELEGATION warmth section, ADR-0015, IMPLEMENTATION crate map). Its record shape must come from AGENT-FABRIC.md (outside this bucket); do not infer it here.
- **Readiness is decomposed, never a boolean.** Agent discovery carries five independent axes plus `AgentReadiness`; Delegation has 8 hard admission predicates and a separate `WorkerPerformanceProjection` confidence labels; `EnvironmentReadiness`/prewarm explicitly "never implies a warm native session, valid grant, lease, authenticated browser". Repeated phrasing: reported ≠ observed ≠ verified; unknown is not zero, not success, not cheaper.
- **Delegation ceilings are consistent across three docs**: platform depth 2, ≤8 live child Attempts, profile `max_concurrency` 1..8, `max_host_delegation_depth` 0..2, escalation 1..8 attempts, ≤3 failover bindings / ≤3 lead changes, 1 MiB envelope, 64 options / 64 KiB. Profile is always a *restrictive ceiling*, and no parent credential/subscription/transcript ever crosses a binding.
- **Duplication risk**: `DelegationProfile`/`DelegationProfileRevision` are specified in DELEGATION.md (owner), restated as signatures in V1-FUNCTION-FILE-CATALOG F02, and re-tabulated in the ledger — three maintenance points for one schema. Same for `AgentCatalogProjection` (LLD) vs F13 functions vs ledger rows. No contradictions found, but drift is one edit away.
- **Version/layout drift worth recording** (not resolved here): storage schema `v22` (ARTIFACTS-EVIDENCE) vs `v16` (IMPLEMENTATION.md agent-module map); capability/environment crates shown under `crates/` in IMPLEMENTATION.md while repo guidance names a root `capabilities/` tree; LEARNING.md explicitly forbids the `crates/domain-learning/` name that older sketches used.
- **Product claim with an unimplemented prerequisite**: PRODUCT.md #11 allows `MANUAL`-mode daemon stop "after safe drain", but the DESKTOP audit records that safe drain does not yet cover Tasks, Effects or leases. The product statement is directionally correct and currently unsatisfiable — a documented gap, not a silent contradiction.
- **Evidence labels actually present**: `TARGET`/`NORMATIVE TARGET` (ARTIFACTS-EVIDENCE partially, CAPABILITY-INVOCATIONS dispatch gate, all V1-* catalogs, AGENT-DISCOVERY LLD), `ACCEPTED for vNext` (ADR-0007/0011/0015/0021), `COMPLETED`/`ACCEPTED/LOCKED` (BT-0.6, SDD 001), `current`/`the current source mounts` (ARTIFACTS-EVIDENCE Library commands, immediately qualified as "unverified pending the deferred system/user gates"), `proposed` (F11–F14, candidate routes, new error classes), `BLOCKED` (all 11 product journeys per REFERENCE-IMPLEMENTATIONS). No `SERVED` or `QUALIFIED` claim appears for dispatch, delegation, or any connector.
