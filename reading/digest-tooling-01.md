## Cross-cutting observations

- **The gate is `check.sh`, nothing else.** It is the only entry point CI runs, and it owns ordering (coverage `--write` before the markdown recheck, since coverage rewrites a document the inventory hashes), with `run_freshness_check` restoring snapshots so a stale generator fails CI without dirtying the tree. Everything outside it is manual.
- **Unenforced surfaces.** `scripts/check.sh` never runs `.specify/scripts/validate_feature_package.py`, so the `specs/` SDD packages of AGENTS.md §3 are not gated at all; nor does it run `capabilities/zip_intake/tests` (only `tests/`) or the packaging/secret/qualification probes. `deep_semantic_snapshot.py`, `build_v1_*_ledger.py`, `sync_audit_inventory_v1.py`, `v1_packaging_check.py`, `v1_secret_scan.py`, `v1_platform_matrix.py`, `v1_soak_harness.py`, `v1_resilience_matrix.py`, `qualify-*.sh` are all off-gate. The "pytest suite" is stdlib `unittest` and several tests shell out to `bash`.
- **Four enforcement styles, only one semantic.** (a) generated-artifact freshness, (b) machine-contract parity across `SCHEMAS.md`/OpenAPI/`domain-event`/`sqlite-v1..v19`, (c) live SQLite constraint fixtures with exact error codes, (d) prose substring presence. (d) is brittle: a doc can contain the required phrase while contradicting the contract, and `contract_assertions: 34` is a literal, not a count.
- **"One normative definition" is mechanised.** Event payload field sets must equal the `EVENTS.md` table; error codes must match in four places *and* every `operator_error*` literal in `apps/litecoworkd/src`; every table/column/FK/CHECK/trigger/index gets a coverage row; every tracked Markdown doc needs an explicit owning story (`fail("architecture document needs an explicit story owner")`). New FLOW/BENCHMARK headings cannot appear without an explicit story mapping.
- **Real cross-artifact contradiction.** `scripts/packaging/systemd/litecoworkd.service` sets `TimeoutStopSec=60` while `qualify-linux-systemd-runtime.sh` requires ≥90 s, and the packaged unit lacks the `# Managed by LiteCowork;` marker the qualifier greps for — the shipped unit fails its own qualifier twice, and `v1_packaging_check.py` (string presence only) would not notice.
- **POSIX assumptions leak into a Windows checkout.** `v1_soak_harness.py`, `v1_resilience_matrix.py`, `v1_platform_matrix.py` default reports to `/tmp/litecowork-release-evidence/…`, and `deep_semantic_snapshot.py` writes `/tmp/litecowork-first-party-semantic-snapshot-2026-10-13.md` — on Windows these land in `C:\tmp`, outside the preservation boundary. `v1_resilience_matrix.py` cannot even import on Windows (`fcntl`, `SIGKILL`), documents a `BLOCKED` row state it never emits, and carries dead `schema_files()` referencing undefined `SCHEMA_DIRECTORY`.
- **Duplicated pin literals.** `uv 0.12.23` / `Python 3.13.12` / `Rust 1.98.1` live in `.uv-version`/`.python-version`/`rust-toolchain.toml` *and* as hard-coded expectations in two test modules; a bump must edit both sides.
- **Hard-coded organisation values.** `check_gateway_and_names` freezes the LiteSPM endpoint `https://litepsm.sarveshbh-2022.workers.dev/` in two docs (changing deployment means editing the validator), while `check_error_registry` freezes 5 blocker codes and `validate_implementation_plan.py` freezes 10 audit-inventory paths plus the `SCOPE.md` vocabulary.
- **`zip_intake` is the most honestly-scoped component here.** Layered fail-closed design (hand-parsed central directory → `ZipInfo` cross-check → parent re-validation of the child → provider re-derivation of every path), `type(x) is bytes` immutability, sentinel-byte budgets so declared sizes are never trusted, and a README that states exactly what is *not* qualified (`ISOLATED_WORKER_NOT_QUALIFIED`, SP06 unperformed, no Core transaction, Linux/Bubblewrap only). Consistent with the TARGET/CODE/SERVED/INTEGRATED/QUALIFIED tiers; nothing claims INTEGRATED or QUALIFIED.
- **Divergence from ARCHITECTURE.md invariants** in this bucket is confined to the systemd stop-deadline/marker defect and unenforced surfaces; the tooling layer otherwise *is* the enforcement of those invariants (no parallel schema, no duplicated state machine, derived counts not stored, provider handles never in shared rows/events/OpenAPI).
