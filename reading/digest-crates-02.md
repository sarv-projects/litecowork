## Cross-cutting observations

**Implemented architecture.** A consistent hexagonal shape: `domain-*` crates hold pure decisions (`decide_*`, `settle_*`, validators) with no clock/storage; `storage-core` declares narrow ports (`*Store` traits) plus wire records with `deny_unknown_fields` and SCREAMING_SNAKE_CASE tokens; `storage-sqlite` is the only SQL, always inside `TransactionBehavior::Immediate`, with optimistic `WHERE version=?` CAS, `request_dedup` receipts (request digest + response digest), `domain_events` + `workspace_origin_sequences`, and aggregate snapshots as `BlobPurpose::AggregateState` blobs verified by re-read. Error taxonomy observed: `StoreError::{NotFound, Conflict{expected,actual}, Invalid(String), Integrity(String), IdempotencyConflict, Busy, Blob, CorruptSchema, Database, Io}`.

**Concept ownership (vs ARCHITECTURE.md §3).** `domain-task` owns Task, Attempt, PlanRevision/Step consumption, DelegationProfile and `Task.lead_agent_binding_id` (lead handoff/failover) — but it imports `storage_core` for `TaskStore/EventDraft/StoreError`, so the "pure domain" layer depends on the persistence-port crate. `domain-responsibility` owns Coworker, Routine/Automation, AutomationOccurrence, TriggerHost cursor and notification policy. `domain-environment` (only its pointer test here) owns Environment viewport/pointer mapping. `storage-core` owns the Effect/Evidence, CapabilityInvocation, Trust/Approval/Grant/SecretLease, NeedsYou and UserRequest read-model ports. `storage-sqlite` owns World Index search (Resource/ResourceLocation/freshness), Automation trigger-host state, RichPresentation, DelegationProfile, Agent registry cache and WorkspaceRoot census. `linux-process-scope` is a process/cgroup primitive for RuntimeIncarnation-scoped workers, explicitly *not* an Environment.

**Divergences / risks found (verified in source).**
1. `decide_occurrence_transition` sets `claim_expires_at = Some(facts.now)` on every move to `Claimed` — the claim is born expired, which contradicts the "a live claim is never silently dropped" guard it protects.
2. Five parallel event-context shapes for one concept: `EventContext` (domain_workspace), `EffectEvidenceEventContext`, `CapabilityInvocationEventContext`, `DelegationProfileEventContext`, `AutomationHostContext`; and `storage-core` re-exports domain types (`pub use domain_responsibility::…`, `domain_invocations::…`), letting consumers obtain domain semantics through the port crate.
3. `coworker_learning` (storage-core) owns learning *policy* semantics while its own doc says those belong in a `domain-learning` crate (absent) — a self-declared ownership deviation, not a doc/code conflict.
4. Fail-closed is uneven: strict `Integrity`/`CorruptSchema` in `agent_registry_cache`, `resource_index`, `automation_host::occurrence_for_slot`, but `parse_instant(..).unwrap_or_default()` / `u64::try_from(..).unwrap_or_default()` in `automation_host` list/health/cursor paths coerce malformed durable values to 0 — "unknown is not success" is not uniformly upheld.
5. `EscalationBlocker::VerificationPassed` is unreachable; `create_cursor` returns one error class for two different conditions and commits an empty transaction; `cursor_digest` is a fixed all-zero digest placeholder.
6. `delegation_profiles` runs the caller's decision closure twice (before and after blob publication) — correctness depends on an undocumented determinism requirement; plus duplicate loaders (`load_profile` JSON vs `load_profile_typed`) that can drift.
7. `coworker_learning` has dead code (`let _ = bytes;`) and one vacuous test assertion (`hunter2secret` is not in the input).
8. No `unwrap`/`expect` in the non-test load-bearing paths read here except inside test modules (the `CaptureStore` mock in `lead_failover_service` uses `unimplemented!()` for 12 methods — never invoked).

**Evidence tier.** Everything in this bucket is **CODE** (unit/integration tests over real SQLite + `FileBlobStore`, plus injected `BlobStore` failures and thread barriers). Nothing here demonstrates SERVED (no authenticated route/mount), INTEGRATED (no daemon, IPC, native harness or provider) or QUALIFIED (no OS/build/provider/user evidence, no WSL2-vs-native proof). Claims such as "fails closed", "no provider bytes in events" and "cursor never rewinds" are code-enforced and test-asserted here, not product-qualified.
