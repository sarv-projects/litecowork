## Cross-cutting observations
- **One auth idiom everywhere**: `authenticate` middleware inserts `AuthenticatedLocalPeer`; handlers then require `X-Workspace-ID` (`selected_workspace`) and `ensure_workspace_owner`/`ensure_workspace_owner_for`. Mutations additionally require `idempotency-key`, usually `If-Match`. Every response is `no-store`. Matches ARCHITECTURE.md's "Workspace is the boundary" and "never accept a caller actor".
- **The effects surface is much thinner than the docs imply.** `local_filesystem.rs` has no write/rename/delete primitive; `environment_action_batch.rs` only *plans* batches; `opencode_server.rs` is transport-only and says so. There is no mediated write-Effect executor in this bucket, so a Task cannot mutate a Workspace root through code read here.
- **Fail-closed stubs are the dominant pattern**, and they are honest: agent credential writes (503), local models (`NOT_CONFIGURED`), capability connect-or-install (`LITESPOM_PACKAGE_SERVICE_NOT_QUALIFIED`), cloud/container Environments (`budget_enforcement: Unavailable`, checkpoint/restore false). That matches the documentation-first reset posture and the "unknown is not success" invariant.
- **Isolation is unattainable by construction in this build**: `probe_local_provider` → `facts_from_probe` sets all four dimensions `Unknown`, so `evaluate_isolation_admission` always refuses. Task/Attempt admission therefore cannot pass even on Linux with bubblewrap present, which is consistent with runtime blockers but means the Environment gate currently blocks all execution rather than gating it.
- **Presentation is the most mature surface**: bounded frames, cursor-scoped replay, explicit `stream.resync_required`, retention-gap detection at two checkpoints, and admission semaphore. It correctly refuses to invent progress: artifact status is `UNKNOWN`, `last_activity_source` is an allowlist, and reads append no events.
- **Windows is explicitly second-class** despite being the stated V1 desktop: directory scanning has no Windows implementation (`openat2`-based, Linux only), macOS fails closed, `resume_workspace_root_live` returns `Unavailable` on non-Unix, and `AgentChild`/Job Object containment is documented as insufficient for descendant guarantees.
- **Trust/approval is a decision record, not authority** (matches the doc comment): resolve writes `approval.resolved.v1` and nothing dispatches; `LOCAL_STRONG` assurance is asserted by the transport rather than measured. No approval route exists for capability grants, and the supervisor performs no grant check before spawning a native agent.
- Divergences from ARCHITECTURE.md worth recording: (a) `supervisor.rs` documents "Response Streaming & Delta" but commits one final message; (b) `browser_consent.rs` declares consent-binding refusals it never evaluates, so `authorized_profile_ref` is decorative; (c) `environment_provider.rs` can never report `Created`, which hides the success case entirely rather than modelling it.
- Dead/unwired code is labelled rather than hidden (`#[expect(dead_code, reason = "…WorldIndexer…")]`, `#![allow(dead_code)]` in the OpenCode adapter, `#![allow(clippy::result_large_err)]` everywhere). No `todo!()`/`unimplemented!()`/`panic!` in load-bearing paths in this bucket; error mapping is enum-typed throughout.
- Tables confirmed by fixtures/tests: `workspaces, tasks, task_spec_revisions, steps, plan_revisions, attempts, execution_leases, agent_profiles, agent_bindings, agent_sessions, agent_host_instances, conversations, conversation_messages, rich_presentations, approvals, resources, environments, routines, routine_revisions, automations, automation_revisions, automation_test_runs, automation_occurrences, automation_cursors, runtimes, runtime_incarnations, runtime_workspace_bindings, domain_events, request_dedup`.
