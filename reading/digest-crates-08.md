## Cross-cutting observations

- **Layering vs the manifests.** `storage-sqlite` (adapter) depends on five domain crates plus `storage-core`, and `domain-workspace`/`domain-task` depend on `storage-core`, which depends on `domain-effects` (`storage-core/src/verification_run.rs` imports `domain_effects::{EvidenceRecord, VerificationRunFailureCode, VerificationRunRecord, VerificationRunStatus}`). The documented direction (domain → storage ports) holds only because `domain-effects` has no dependencies at all (`serde`, `serde_json` only). Adding any dependency from `domain-effects` onto `storage-core` (or `domain-conversation`) would immediately create a cycle through `storage-core → domain-effects → storage-core`. Same hazard for `domain-conversation`/`domain-responsibility`/`domain-invocations`/`domain-environment`.
- **No import cycles found** in dependency order: `domain-effects` ⊥, `storage-core → {domain-effects, domain-*?}` (only domain-effects proven), `domain-{workspace,task,environment,invocations,responsibility} → storage-core`, `storage-sqlite → storage-core + 5 domain crates`, `windows-local-security ⊥ tokio`, `operator-ipc` standalone (bytes/http_body/serde/tokio).
- **Authority placement is consistent within storage, weak at the domain edge.** The SQLite adapters genuinely own the atomic transaction (version CAS with `WHERE … AND version=?`, `request_dedup` receipts, `Immediate` transaction behaviour, `SELECT … EXISTS` owner checks in the same statement, post-commit blob re-verification, canonical-JSON equality against stored rows). But `domain-workspace/lib.rs` computes next versions, compares `expected_version`, mutates `Workspace`/`WorkspaceRootRecord`, and builds `EventDraft`s — so the "domain" is a write-model participant, not merely a command validator. `change_replication_policy` even does `workspace.version += 1` (unchecked) whereas every other path uses `checked_add`; that inconsistency is a real overflow hazard, not a doc mismatch.
- **Fail-closed defaults are a recurring pattern** and match ARCHITECTURE claims: `StepAttemptStore` default `Err(unsupported())`; `ChildAttemptAdmissionProofs::default()` all `Unsupported`; `evaluate_drift_state` empty ⇒ `UNKNOWN`; capability bridge requires all six mediation guarantees; `rich_presentations` refuses any source-bearing block until a binder exists; automation `Enabled` ⇒ `ReconciliationRequired`.
- **Divergence to record:** `domain-task/delegation_admission.rs` (a "pure" policy module) imports `storage_core::ChildAttemptAdmissionSnapshot` and `StepAttemptStore`, and `domain-workspace` imports `storage_core` records wholesale. That contradicts the module docs' "pure/advisory" framing and the repo rule that the canonical schema/state authority lives in the storage owner; the compensating control is that every consumer re-checks in a write transaction, and the tests assert the preview never reaches the writer (panic-on-call stub, `reads == 0`).
- **Test-as-contract culture:** SQL triggers (`RAISE(ABORT)`) inject failures to prove rollbacks; `migrate_with_failpoint` proves migration atomicity; DB-level `UPDATE … is_err()` proves immutable revision tables; `#[ignore]`d live Bubblewrap tests mark the OS qualification as not in the default suite (which matters for the QUALIFIED evidence tier — these two tests are the only real namespace proof and they do not run by default).
- **Event-name inventory actually used in this bucket:** `workspace.created.v1`, `workspace.archived.v1`, `workspace.replication_policy.changed.v1`, `workspace.default_agent_binding.changed.v1`, `workspace.primary_coworker.changed.v1`, `workspace.instructions.revision.created.v1`, `workspace.root.created.v1`, `workspace.root.status.changed.v1`, `resource.created.v1`, `resource.location.changed.v1`, `resource.upload.created.v1`, `resource.revision.observed.v1`, `artifact.version.created.v1`, `artifact.library.promoted.v1`, `artifact.library.archived.v1`, `conversation.created.v1`, `conversation.agent_binding.changed.v1`, `conversation.turn.created.v2`, `user.request.created.v1`, `user.request.resolved.v1`, `task.created.v1`, `rich.presentation.published.v1`, `delegation.result.published.v1`, `goal.created.v1`, `goal.revised.v1`, `goal.status.changed.v1`, `attempt.created.v1`, `lease.acquired.v1`, `step.status.changed.v1`, `task.status.changed.v1`, `budget.reservation.changed.v1`.
