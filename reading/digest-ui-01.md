## Cross-cutting observations

- **The "generated typed API client" is typings-only.** `operator-api.ts` exports `paths`, `components`, `operations`, `$defs` as TypeScript types with zero runtime statements (no `fetch`, no base URL, no interceptors, no auth header injection). Consequently there is *no* client-side auth-header code to audit here: auth scope exists as an OpenAPI *parameter* (`X-Workspace-ID: WorkspaceContextHeader`) and is enforced by adapters that refuse to act if `headers.get("X-Workspace-ID") !== workspaceId`.
- **Transport is Tauri IPC, not HTTP.** Every mutating feature goes through a small set of named commands: `get_task_presentation`, `get_task_progress`, `coworker_request`, `goal_request`, `list_agent_installations`, `list_agent_registry`, `refresh_agent_registry`, `list_agent_profiles`, `list_agent_bindings`, `probe_agent_profile`, `create_agent_binding`, `enable_agent_binding`, `disable_agent_binding`. Adapters synthesise `Response` objects via `operatorBridgeResponse` (base64 bodies), so hand-written API modules are testable against plain `RequestInit`.
- **Layering is consistent:** `create*Api(workspaceId, transport)` (pure, strict decoders) ← `desktop-*` adapter (finite operation enum, workspace/Idempotency-Key/If-Match validation) ← `App`/components. Decoders always allowlist keys/enums, validate `sha256:…`, and reject cross-workspace identity — the strongest instance being `artifact-api.appendTextVersion` (recomputes submitted SHA-256 and rejects a mismatched receipt).
- **"Unknown is not success" is implemented, not just documented:** `uncertain|stale` outcomes for root pause/resume, expired/future quota → `Unknown`, freshness attributes, `PROVIDER_UNAVAILABLE` instead of an answer, `INSUFFICIENT_EVIDENCE` with typed reason, `RejectedItem` fallbacks, `replayed` flag on receipts.
- **Staleness fencing is the dominant idiom** (epoch/generation refs, `emit` cursor monotonicity, `origin_sequence`==`projection_revision`, per-workspace feedback maps). Concurrency races (A→B→A, late responses, duplicate replay) are covered by unit tests rather than integration tests.
- **No mock/fixture data in this bucket.** The only hardcoded domain object is `assistantRevision` (default Coworker spec) in `HomeCoworkerOnboarding.tsx`; UI prose contains product-surface claims that are *not* in a ledger: "Worker execution is not available in this Runtime." and `SENDING_NOT_AVAILABLE` ("Conversation sending isn't available yet") — flag for the product/evidence owner, since chat-first send is a V1 promise.
- **Boundary question (unresolved, type-level only):** generated paths include `/agent-registry/{registryAgentId}/install` and `/update`, i.e. package installation/update routes on the local Operator, while ARCHITECTURE §2/§6 assigns package mutation to LiteSPM and keeps agents from self-approving. The desktop UI deliberately exposes none of them. Whether the daemon proxies LiteSPM or duplicates it cannot be decided from this bucket.
- **Divergence to note:** `artifact-api.ts` hand-declares `ArtifactSaveAsRequest`/`ArtifactSaveAsResult` instead of deriving from `operator-api` (native Save-As payload; not a schema violation but a second definition site). Conversely `/v1` prefixes are added by hand although generated path keys omit them.
- **App shell is out of bucket:** `src/App.tsx` and `src/resources/library-navigation.tsx` are only visible through the test that greps their source and the CDP script's selectors. Navigation model evidence here is therefore indirect: `#main-navigation`, `.mobile-navigation-toggle`, `.sidebar-close`, `.sidebar-backdrop`, `.main-area`, `aria-current=page`, `inert` main area while a Library draft guard is pending.
