# Computer observation and control: local laptop Workbench

Status: revision 1.1 IN_REVIEW / TARGET, 2026-11-12. The user explicitly requested a live view of the laptop computer and immediate manual takeover, superseding the browser-only interpretation as the requested design scope. This is authorization to revise design documentation, not recorded multi-owner acceptance, machine-contract promotion, implementation authorization or provider qualification. Feature 008 revision 1.0 and its historical B-32 deferral remain recorded. Environments owns substrate identity and control leases; Trust owns permission; Desktop shell owns presentation. This LLD refines those owners and must not create another lease authority. [Feature 008](../specs/008-workbench-browser-terminal-computer/SPEC.md) tracks promotion and gates.

## Outcome and boundaries

The compact right Workbench can show the selected physical laptop display, including native applications. Computer is distinct from Browser: a Chromium tab screencast does not satisfy this requirement. A user may observe locally without granting agent vision or input, continue observing during manual ownership, pause disclosure to the agent independently, and take back mediated input from a persistent control. Ordinary Conversation requires no Task. Any agent computer mutation still requires the admitted Task/Attempt and Trust/Effect authority; opening Computer creates neither.

Desktop attachment is an owner-selected human-visible OS session, with an Environment identity or an explicitly promoted observation-only attachment identity. It is not an isolated Task sandbox. Do not relabel the host desktop as an attested private filesystem/network Environment. The precise attachment mapping is an owner gate: current Environment admission supports neither a working Desktop provider nor user-shared host execution. Local-only observation can be implemented independently of agent execution after its own contract is promoted.

Non-goals: cloud desktop, unattended login, secure-desktop/UAC automation, lock-screen bypass, capture of all displays by default, audio/video recording, clipboard synchronization, credential extraction, complete interception of direct native agent tools, and arbitrary model script execution in the app renderer. Canvas in Workbench means the existing exact-version Artifact/editor surface; it is not the capture buffer and grants no execution authority.

## Authority and component HLD

```text
Workbench Computer tab + persistent shell control strip
  -> typed Computer controller -> authenticated Tauri command bridge
  -> authenticated Operator -> ComputerSessionService
       -> TrustService (local view / agent disclosure / input separately)
       -> EnvironmentManager + existing control-lease authority
       -> durable session/consent/intent/receipt + transactional outbox
       -> private capture/input broker (outside SQLite)
            -> OS capture adapter -> privacy filter -> bounded frame dispatcher
            -> OS input adapter (one serialized writer and enforced fence)
  <- redacted session/control projection + separate ephemeral frame channel
```

The Rust broker owns OS handles, pixels before redaction, geometry and delivery queues. The shell owns visible emergency controls outside captured/remote content. React owns selection and layout, never OS authorization or provider credentials. Provider-local pipes/handles and native window/display identifiers remain private. Public targets are opaque incarnation-scoped references, with user-selected non-sensitive labels. Native tools outside this broker remain reported/observed and cannot receive fictitious Core Effect receipts.

## Three independent permissions

| Permission | Meaning | Lifetime / default |
|---|---|---|
| Local observation | OS capture and display in authenticated local Workbench | Explicit system picker and Workspace consent; off initially |
| Agent observation | Disclose selected redacted frames to one compatible native AgentSession | Separate scope, destination disclosure and expiry; off initially |
| Agent input | Admit allowlisted mediated pointer/key actions | Separate Task/Attempt grant, current control lease, per-Effect policy; off initially |

OS permission is a ceiling, not Workspace consent. A local view never silently attaches pixels to chat, a model prompt, memory or Activity. User takeover changes input authority without automatically stopping permitted local observation. Agent observation while USER owns input follows its separate permit; **Hide from agent** revokes that disclosure immediately while retaining the local preview. Password, payment, CAPTCHA, MFA and other protected interaction stays human-only; agent disclosure pauses for sensitive handling. **Stop sharing** terminates capture and both disclosure subscriptions, wipes frame queues, fences agent input dependent on that observation, and records ambiguity for already dispatched actions. **Pause view** stops local frame delivery only and visibly states whether an independently consented agent observation remains active.

Current `environment_computer_use.rs::authorize_computer_action` treats captures as ComputerAction and refuses them whenever Human owns input. That helper cannot be reused unchanged: split capture authorization from input authorization with denial tests. Its current provider probe remains unsupported/unavailable and must not be flipped READY merely because a permission flag exists. Current label-based sensitive-region checks are incomplete; an unclassified pixel buffer is never proven safe by an absent label.

## Session, privacy and frame lifecycle LLD

1. Computer tab opens an idle explanatory surface with **Choose screen**, not automatic capture. The system picker selects one display or window; cancel returns idle and grants nothing. Display is available to satisfy whole-laptop observation; a narrower window is an explicit user choice, never silent substitution.
2. Record authorized scope, local-view permit, expiry, privacy policy revision and selected provider capability identity. Commit intent before opening the provider outside SQLite. Only observed successful provider binding changes STARTING to LIVE. Permission denied, source removed, locked or protected surface produces a typed status; no prior screenshot is presented as live.
3. The capture broker receives native frames, timestamps them monotonically, validates current target generation/geometry, applies fail-closed privacy exclusions, downscales and encodes within caps. Reject oversized data before allocations in the renderer. A separate frame subscription authenticates the same Workspace/window; its nonce is private, short-lived and not a reusable public URL.
4. Frame envelope: session ID, Runtime and RuntimeIncarnation, capture generation, target opaque reference, observation sequence, geometry revision, monotonic capture time/age, dimensions, content type, encoded byte length, redaction-policy revision, redaction status and stream generation. No raw desktop bytes in domain events. Input also names control epoch and source observation sequence; viewing does not require agent input ownership.
5. Only the newest eligible frame survives a slow consumer. Bound native pool, encoder queue, transport queue and decoded surfaces independently. Release superseded GPU/CPU buffers; discard before decode on Workspace/source/incarnation changes. Do not send frames through Tauri's global event API: it serializes event payloads as JSON and is not designed for large or high-throughput messages. Prototype an invocation-scoped ordered `Channel<Response>` for bounded raw-byte frame delivery (`InvokeResponseBody::Raw` to frontend `ArrayBuffer`) on the repository's exact locked Tauri/WebView versions; use an authenticated, short-lived frame resource with bounded reads if that path is unsupported. Do not base64 frames or assume shared-GPU/zero-copy. WebRTC is not a prerequisite for this same-device V1 path. See the official [Tauri channel documentation](https://v2.tauri.app/develop/calling-frontend/) and [raw response API](https://v2.tauri.app/reference/javascript/api/namespacecore/); pin and qualify the exact dependency behavior before implementation.
6. **Recommendation to benchmark, not measured promise:** visible local preview starts at maximum 8 frames/s, 1280px longest edge, one pending encoded frame per subscriber and one decode in flight. Cap compressed frame at 1 MiB and decoded dimensions at 1920x1080 for this profile; return explicit over-bound status or negotiate a documented lower profile before allocation. Agent observations are on demand, initially at most 1 frame/s with action-triggered refresh, under a separate model byte/token budget. Unchanged content uses a health heartbeat rather than repeated model images. Hidden/collapsed local preview unsubscribes; an independently active agent subscription remains visible in the shell strip. Stop capture when no authorized subscriber remains. Adaptive quality reduces frame rate/resolution under pressure, reports actual quality and never labels old frames live.
7. Recommended freshness cutoff is 2 seconds for a live badge and a stricter per-input maximum age of 1 second, both provider-calibrated before acceptance. These are prototype parameters requiring p50/p95 latency, CPU/GPU, working-set and energy measurements on the owner's laptop. Exceeding the action freshness bound rejects input and requests a new observation; it does not silently click against stale coordinates.
8. Capture stores no recording by default. Buffers exist only in memory under bounded lifetimes and are wiped/released on stop/revoke/lock/source change/restart. Explicit **Save snapshot** is a different reviewed Artifact action bound to the exact redacted frame/digest and existing Artifact retention. Screenshots never become Evidence or memory automatically. Provider-disclosed copies cannot be recalled; the sharing dialog states their destination and native provider retention boundary.

Privacy exclusions are enforced before local-to-agent delivery, transport or optional storage. Prefer provider-side exclusion of LiteCowork's own window to prevent recursive mirror feedback; if reliable exclusion cannot be established, crop/mask that region and label it. A full display can expose notifications or other apps: consent names that risk. No promise that generic OCR detects all secrets; use explicit exclusion regions, user-triggered privacy pause and fail-closed blocking when a required exclusion cannot be applied. Region masks bind geometry revision; a moved/resized window invalidates them until recomputed. Lock and secure desktop blank delivery, revoke input, release pressed synthetic keys/buttons where possible, and require explicit revalidation after unlock. Audio capture and clipboard are disabled in this design.

## Input admission and immediate takeover

One serialized broker is the last enforcing hop for every LiteCowork-mediated desktop input, including pane-forwarded human input. Lease identity is scoped to the actual physical desktop input domain, not just one tab/window: two Workspaces or a browser OS-input adapter cannot simultaneously inject into the same OS pointer/keyboard. Browser DOM/CDP-only operations retain browser authority; if they synthesize OS input they must share this desktop arbiter. Workspace separation cannot be implemented by two independent global input queues.

Agent action envelope: Workspace, ComputerSession, RuntimeIncarnation, target generation, expected session version, current control lease ID/epoch, AgentSession and Task/Attempt authorization, source observation sequence, geometry revision, allowlisted action and bounded arguments, stable idempotency key and exact request digest. Trust rechecks per-action policy and Effect approval. Coordinates transform letterboxed pane pixels through frame crop/rotation/DPI into native display coordinates; reject outside bounds, stale geometry, changed foreground target or unsupported DPI mapping. Text uses a bounded text-insertion operation with tested IME/Unicode behavior. No raw shell/CDP/general script endpoint is exposed.

A persistent, non-modal **Agent is controlling your computer · Take over · Stop run** strip lives in app chrome whenever mediated input is AGENT-owned, even when Computer is hidden or Canvas/Terminal is selected. It remains outside captured pixels, is keyboard reachable, and does not steal focus. A transient popup is insufficient: once the native target app is foreground, the LiteCowork strip is behind it.

The user must also have an out-of-app emergency path while the target application is foreground. **Target proposal, owner review required:** use a registered OS-level global shortcut as the primary fast action and a native tray menu item as a discoverable fallback; both invoke the same brokered `Take over` path and do not need to raise/focus LiteCowork before closing the input-admission latch. The exact shortcut, conflict behavior, tray availability, accessibility and per-OS API are not selected or qualified. Register the escape path before admitting AGENT input; revoke the input lease if registration is lost or the shell/runtime incarnation changes. If neither global shortcut nor tray action can be qualified on an OS/session, keep that provider observation-only and refuse mediated input. The strip remains the in-app status/control surface; a notification or popup alone never satisfies the emergency-path requirement.

If the native tray menu is implemented, expose **Take over** and **Stop run** as distinct actions there. A global keyboard shortcut maps to **Take over** only by default; it must not unexpectedly cancel a Task or Conversation. After an out-of-app Take over, leave focus on the user's target application. The user can stop the run from the tray menu or return to LiteCowork and use the persistent strip. Any global Stop shortcut requires its own explicit owner review and conflict tests.

**Take over** from the in-app strip, registered global shortcut, or native tray item immediately closes agent input admission at the broker, then cancels queued input and advances the revocation fence; it must not wait behind capture encoding, model generation or an unbounded action batch. The durable transfer transaction records TRANSFER_PENDING, expected-version/CAS and new fence; dispatch checks that fence again at the last hop. Provider acknowledgement and bounded reconciliation determine whether ownership can settle USER or must remain **Agent input blocked; previous action outcome unknown**. Never claim already sent OS input was undone. The in-memory admission latch closes first; if writing the durable transfer intent fails, keep the latch closed and report transfer unavailable/unknown rather than reopening input. The escape command must reach a nonblocking fence path independent of the normal action queue. Provider control-channel loss, shell crash and Runtime-incarnation change fail closed before another action; exact heartbeat/lease timeout bounds are provider-specific T23 evidence, not guessed constants.

**Stop run** is a separate owner command. It first closes the Computer input fence, then calls Feature 001 Conversation cancellation or the owning Task cancellation fan-out; each service fences its own mediated operations and reports its own quiescence/reconciliation result. This design does not invent one global cross-domain cancellation route. A pending OS action remains pending/unknown. It must not claim that a provider process exited unless the provider owner observed that result. **Take over** leaves agent reasoning and unrelated authorized work running; **Stop run** requests the applicable run to stop. Neither action sends a message.

The local owner can physically use their keyboard/mouse at all times; LiteCowork cannot disable that or guarantee system-wide human exclusivity. Qualified local physical-input detection may also trigger the same broker fence, excluding its own tagged synthetic events. If reliable physical-input detection is absent, show the explicit Take over path and qualify only that mechanism. In-app pointer forwarding is disabled until USER ownership is confirmed. Releasing held synthetic modifiers/buttons is a bounded cleanup action, audited separately; do not invent a successful release if the OS rejects it.

**Return to agent** is a separate explicit action. Recheck exact live AgentSession/Attempt, grants, provider health, selected source and permissions; increment epoch; obtain a fresh observation and geometry; discard all pre-takeover actions. User-edited forms or terminal buffers are never submitted on return. Takeover does not cancel Conversation generation or stop a Task: those controls retain Feature 001/012 and Task-runtime owners. A stalled input provider is terminated or its input channel revoked when supported; inability to prove that boundary means UNKNOWN with agent input unavailable, never a ready lease.

Sending a chat message is never a takeover or emergency-stop signal. While a Conversation turn is RUNNING, keep the composer behavior governed by Feature 001; do not silently treat Send as steering. A provider-qualified typed continuation or permission/UserRequest reply may be offered only for the exact correlated provider request and only through its owner contract. If no such request is active and the provider does not support concurrent steering, the user must choose **Stop run**, wait for settlement/quiescence, then send the next turn. No general queued-prompt feature is implied here.

## Target operations, transactions and events

All following names are semantic draft port names, not allocated operationIds or served routes. Promotion task 008-T23 must put exact method/path/operationId, ACL and payload into the canonical API/OpenAPI, events/errors and migration together; generated presence is not service evidence. Operator requests derive Principal from transport, enforce X-Workspace-ID, If-Match and Idempotency-Key, and keep IPC request_id for correlation only.

| Target port | Result and owner transaction |
|---|---|
| inspectComputerCapabilities | Separate capture/input availability, supported scope/action limits, OS permission state and qualification reference; no screen pixels |
| chooseComputerSource / startComputerObservation | Native picker result is a private broker binding; transaction commits exact scope/permit/session revision/outbox before start |
| subscribeComputerFrames / detachComputerView | Authenticated ephemeral stream per permitted audience; no durable frame event |
| setAgentObservationPermit | Exact destination/session/scope/expiry and policy digest; revoke flushes queued disclosures |
| requestComputerTakeover / returnComputerControl | Existing control-lease owner transaction commits fence, revision, audit and outbox; broker enforces last-hop epoch |
| dispatchComputerAction / reconcileComputerAction | Intent/Effect/admission receipt before dispatch; acknowledgement/outcome receipt after; duplicate never redispatches |
| stopComputerObservation / revokeComputerPermit | Atomic admission/disclosure revocation then out-of-transaction provider stop and buffer purge receipt |
| saveComputerSnapshot | Existing exact Artifact pipeline after explicit user review; no automatic recording |

Proposed durable metadata: ComputerSession scope/health/revision; separate observation permits for local and agent audience; existing EnvironmentControlLease reference plus session input state; ComputerActionReceipt and purge/stop receipts. Use one owning lease/state machine. No migration number is allocated here; T23 checks the next free number and does not rewrite existing migrations or overload browser v41 silently.

Proposed event semantics (names/version allocation pending EVENTS/schema promotion): observation session started/paused/stopped/lost; permit granted/revoked/expired; control transfer requested/fenced/settled; action admitted/applied/ambiguous/rejected; capture privacy blocked. Payload contains IDs, revision/epoch, actor, reason, policy digest, assurance and timestamps only. No frames, raw key text, application titles, full URLs, native handles or private locators. APPLIED means provider-confirmed mediated input, not successful external business outcome. Screenshot equality cannot prove a click's external result.

## Failure and recovery matrix

| Trigger | Required response |
|---|---|
| Picker cancel / OS denial | No session authority created; idle/permission-required with repair |
| Privacy mask unavailable / source changes | Blank frame, fence input, require new valid scope/geometry |
| Slow UI / oversize frame | Drop superseded frames, bounded quality adjustment or explicit over-bound; Operator remains responsive |
| Takeover racing admission / dispatched click | Last-hop fence rejects queued work; sent click remains pending/ambiguous until reconciliation, never automatically retried |
| Input insertion partially accepted | Receipt records partial/UNKNOWN; release held keys where supported; no repeated text/click |
| Sleep / lock / display unplug / DPI rotation | Suspend/blank, revoke input; fresh target and explicit validation after resume |
| Provider or daemon crash | Prior-incarnation streams, targets, epochs and subscriptions invalid; durable actions reconcile; no auto-input or recording resume |
| Two windows / two Workspaces | Separate authorized views; one physical input arbiter; stale actor/epoch rejected |
| Agent disconnect / grant expires | Fence input, stop disclosure after expiry; local preview may continue under its own permit |
| Stop sharing response lost | Reconcile same idempotency key and query receipt; retry never creates a new capture/session |

Reuse existing canonical errors wherever semantics match. Candidate reason extensions requiring promotion include stale observation/geometry, target lost, privacy blocked, capture over bound, transfer unknown and partial injection. Existing COMPUTER_PROVIDER_UNAVAILABLE, COMPUTER_SCREEN_LOCKED, COMPUTER_CONSENT_MISSING/REVOKED/EXPIRED, COMPUTER_CAPTURE_NOT_PERMITTED and COMPUTER_INPUT_NOT_PERMITTED map from policy helpers; they are not yet a public served API. Error repair never exposes native details or enables a denied operation.

## Provider options and qualification gates

These are recommendations to prototype, not pinned dependencies or accepted provider selections. Official documentation observed 2026-11-12; no OS integration was executed.

| Platform | Recommended capture candidate / alternatives | Independent input candidate and limitations |
|---|---|---|
| Windows laptop first spike | Windows.Graphics.Capture with the system display/window picker and capture frame pool; the documented system UI draws a visible capture border. Compare Desktop Duplication GPU/dirty-region path for performance. Keep OS capture indication. | SendInput behind broker and explicit input permit; UIPI limits insertion to equal/lower integrity, and insertion count is not external outcome. Secure desktop/elevation remain unavailable. |
| Linux native desktop | XDG ScreenCast portal + PipeWire; record compositor/backend/version and actual portal interface support. The portal may offer persistent restore tokens; LiteCowork must not restore its own consent/agent permit from layout state. No ambient X11 polling fallback by assumption. | Separate RemoteDesktop portal permission/device selection; libei/EIS only when exact portal/backend offers and qualifies it. ScreenCast alone grants no keyboard/pointer input. |
| macOS future row | ScreenCaptureKit stream with `SCContentSharingPicker` and system Screen Recording permission; exact deployment target, entitlement, prompt and permission-revocation behavior need native investigation. | Accessibility/Quartz event path is a separate permission/provider gate; no claim from screen capture permission alone. |

Windows selected-display observation can be investigated independently of B-35 Task sandbox qualification. This does not authorize an external agent to execute in a host shell or claim unrestricted desktop input meets an isolation policy. Input scope must be enforceable at the broker and every required Task/Environment policy; providers unable to enforce requested target/application/root boundaries remain observation-only or unavailable. Desktop pixel capture cannot establish filesystem/network isolation.

Before implementation: owners reconcile Desktop attachment identity, desktop-vs-browser arbitration, exact OS/provider minimum versions, model disclosure scope under read-only Conversation grants, manual terminal context, privacy exclusions and performance profile. Before release: packaged UI + daemon + authenticated IPC + persisted owner state + real capture/input provider + real native agent, including denial, race, replay, timeout-after-dispatch, physical takeover, provider termination, restart/reconnect and sustained load on exact OS/build. Record CODE, SYSTEM and owner USER evidence separately. No current computer journey is SERVED, INTEGRATED or QUALIFIED.

## Official research references

- [Windows capture](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture): system selection, visible capture border and capture frame pool support a user-selected display/window design; keep heavy processing off the UI thread.
- [Tauri calling the frontend](https://v2.tauri.app/develop/calling-frontend/): events serialize payloads as JSON and are not designed for large/high-throughput data; channels are the ordered streaming path. [Tauri core Channel API](https://v2.tauri.app/reference/javascript/api/namespacecore/) documents raw response bytes as `ArrayBuffer`; exact locked-version behavior still requires a native prototype.
- [Desktop Duplication](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api): GPU surfaces and dirty/move-region metadata motivate measuring incremental work.
- [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput): input-count and UIPI restrictions require honest partial/unknown handling.
- [XDG ScreenCast](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.ScreenCast.html) and [RemoteDesktop](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html): separate capture/input sessions and device permits; ScreenCast v6 advises targeting PipeWire `pipewire-serial` because node IDs may be reused. Deployed portal versions must be pinned later.
- [Apple ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit) and [macOS capture sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos): recommends the system content picker, per-app Screen Recording permission and stream filters; this remains a future candidate without LiteCowork compatibility evidence.
- [VS Code terminal profiles](https://code.visualstudio.com/docs/terminal/profiles): explicit platform profiles and separate automation shell are useful UX references; they do not authorize host-agent access.

No upstream source or implementation was imported. Existing pinned browser-use, OpenHands and DeepSeek references in Feature 008 remain browser/terminal research only; they do not establish a working whole-laptop provider.
