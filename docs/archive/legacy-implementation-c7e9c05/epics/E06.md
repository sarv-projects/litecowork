## E06-S01 — Bounded archive and extraction provider

Dependencies: E04-S05.

**Implement:** ZIP manifest preview and extraction limits; isolated type parsing/OCR provider; exact Resource revisions and parse provenance; run SP06.

**Acceptance:** Path traversal/symlinks/bombs refused; original immutable; PDF/page/table references retained; failures visible per file.

**Negative/race cases:** Nested ZIP, encrypted ZIP, Unicode duplicate path, zip bomb, malformed PDF, OCR timeout.

**E06-S01-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E06-S01-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E06-S01-USER:** Import mixed folder and ZIP without escape; inspect extraction report. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.

**Current implementation boundary:** The bounded Python provider supports metadata preview and bounded in-memory extraction behind the Linux `ZipWorker`. Its worker runs under Bubblewrap with private user/PID/network/IPC/UTS/mount namespaces, read-only runtime and parser mounts, a 1 MiB private `/tmp`, inherited 8-second CPU and 512 MiB address-space limits, and a 12-second parent deadline. The parent streams bounded request/response pipes, discards stderr, kills the worker process group on deadline/output overflow/cancellation, verifies returned manifests and payload hashes, and never writes member files to disk.

`litecoworkd` now mounts the read-only `POST /v1/resources/{resource_id}/archive/preview` route in `apps/litecoworkd/src/resource_archive_operator.rs`. It requires an authenticated local Operator caller and selected Workspace owner, pins an exact managed Resource revision and `sha256:` digest, reads at most 16 MiB using the verified ResourceStore path, and invokes a fixed Python CLI which calls the Bubblewrap supervisor. The response is metadata-only and `Cache-Control: no-store`; the request and route create no event, receipt, Invocation, Effect, Artifact, child Resource, or member payload. Exact API and OpenAPI contracts are in `docs/API.md`, operation `previewResourceArchive`, and schemas `ArchivePreviewRequest`, `ArchivePreviewResponse`, `ArchivePreviewLimits`, and `ArchivePreviewEntry` in `docs/schemas/operator-api.openapi.yaml`.

This is a source-tree Linux development preview, not E06-S01 acceptance or provider readiness. The bridge is compiled only with the explicit, non-default `source-zip-worker` Cargo feature; the Tauri sidecar build invokes Cargo release without features, so a release binary stays unavailable even when its build came from a checkout where the CLI file exists. Packaged Runtime use remains unavailable and ZIP readiness remains `UNAVAILABLE / ISOLATED_WORKER_NOT_QUALIFIED`. Runtime extraction, Core child-Resource creation and provenance/deletion transactions, PDF/Office/OCR parsing, an Operator cancellation API, and qualification on other Linux distributions or desktop OSes remain unimplemented. Normal ZIP uploads remain opaque immutable Resources. See the focused [`E06-S01 review packet`](../reviews/E06-S01.md) for exact verification and pending gates.

## E06-S02 — Hybrid retrieval and grounded attachments

Dependencies: E06-S01.

**Implement:** Provider chunk/embedding/rerank index with ACL filters, revision/digest references, quotas, bounded query and citation resolution.

**Acceptance:** Only authorized current/pinned content attached; exact page/span citation opens; no evidence gives explicit insufficient answer.

**Negative/race cases:** Prompt injection, poisoned chunks, no relevant hit, outdated vector model, cross-Workspace leak.

**E06-S02-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E06-S02-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E06-S02-USER:** Answer gold questions across 20 PDFs and a code folder with checked citations. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.

**Current implementation boundary:** A new `domain-rag` crate owns the provider-agnostic
retrieval boundary, the authorization scope, the grounding rules, the index state, the
local model inventory rules, and the explicit placement rules. It contains no endpoint,
transport, embedding API, or third party wire protocol. The authenticated local Operator
serves `POST /v1/resources/retrieval`, which authorizes the Workspace owner, hands an
already authorized scope to the qualified provider, and returns citations that name the
exact `resourceId`, `resourceRevisionId`, and `contentDigest` of the immutable revision
the segment was read from, plus an exact UTF-8 byte locator. A request with no
authorized evidence returns an explicit `INSUFFICIENT_EVIDENCE` outcome with a typed
reason and no citation; there is no response that reports a claim without a source
reference. Retrieved content is untrusted data: embedded-instruction text is flagged and
cannot support a claim on its own. The served provider is the deterministic local
lexical index over the Core-owned encrypted local text index. It is not semantic
retrieval, embeddings, vector recall, or reranking, and it never compares segments
produced by a different parser generation. Only the current head of a Resource is
indexed; a request that pins an older revision reports `PINNED_REVISION_NOT_INDEXED`
instead of substituting a newer revision. No answer composer, Task attachment, or
Context-used receipt exists yet. The OpenAPI, `docs/API.md`, and the desktop Tauri
bridge additions are reported to the lead and are not applied by this slice. See the
focused [`E06-S02 review packet`](../reviews/E06-S02.md) for exact verification and
pending gates.

## E06-S03 — Incremental update/delete recovery

Dependencies: E06-S02.

**Implement:** Delta indexing/watch overflow reconciliation, source revision invalidation, provider-owned replica registration and purge receipts.

**Acceptance:** Changed file invalidates stale index; revoked source blocked immediately; DELETED waits exact receipt set; index rebuild from authorized sources.

**Negative/race cases:** Offline provider, crash between chunk and index commit, deletion during query, renamed source.

**E06-S03-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E06-S03-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E06-S03-USER:** Edit then revoke/delete source and prove absence in fresh query/context. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.

**Current implementation boundary:** Core now projects the owner-visible index state of
a managed Resource. `GET /v1/resources/{resource_id}/index-state` returns `READY`,
`STALE`, `ABSENT`, or `NOT_INDEXABLE` with a typed reason, the current revision and
digest, the indexed revision, the parser identity, the index timestamp, and the number
of superseded projection rows. It exposes no extracted text, no term tokens, and no
blob digest. A changed file therefore reports `STALE` instead of being silently served:
the index candidate query only returns the current head, and the retrieval provider
re-reads the Resource detail at the last boundary and drops a segment whose revision is
no longer the head, whose Workspace changed, or whose ContextDocument is not `ACTIVE`.
A revoked or deleted Resource is never served from the index. The existing v19
ResourceIndex registry and its bounded collector continue to recover a snapshot that was
published before a failed projection commit. A superseded projection row is still
registered and still keeps its encrypted snapshot until the Resource is deleted; the
state projection reports the leftover count, but removing it needs a new writer command
in lead-owned shared storage code. There is no automatic re-index on a revision change,
no watcher, no delta indexing, and no provider-owned replica registration or purge
receipt. See the focused [`E06-S03 review packet`](../reviews/E06-S03.md) for exact
verification and pending gates.

## E06-S04 — Local-model harness UX and performance

Dependencies: E06-S03.

**Implement:** Run SP05; integrate qualified harness with local engine; endpoint/auth/model status, bounded context, tool tests, cancellation, warm hints and egress policy.

**Current support boundary:** No local inference endpoint registration/probe, model-catalog UI, local-model AgentBinding, or inference turn is implemented. Existing local lexical Resource indexing is not semantic RAG or local inference. Ollama, LM Studio, and llama.cpp remain candidates until SP05 records a selected exact protocol/version and passes its security and harness gates. Never show a candidate engine as connected or start an Agent from an endpoint-only catalog result.

**Current local model inventory boundary:** Local models are inventory only and there is
no global Providers feature. `GET /v1/capabilities/local-models` reports the fail-closed
availability for the authenticated Workspace owner: `NOT_CONFIGURED`,
`LOCAL_MODEL_PROVIDER_NOT_QUALIFIED`, `inventoryOnly: true`, `surface: AGENT_SCOPED`,
and `agentBindingPolicy: AGENT_MODULE_COMPATIBILITY_REQUIRED`, with an empty inventory.
The route never probes an endpoint, never accepts an Agent- or document-supplied URL,
never returns a credential, and never claims that an engine present on the machine is
connected. A local model becomes selectable only through an Agent whose AgentModule
reports compatibility for that exact model; the Core rule and the desktop decoder both
refuse an inventory-only model without an exact AgentModule match. The admission gate
in this story is not satisfied, so the UI reports `UNAVAILABLE` / `NOT_CONFIGURED` and
offers no silent cloud fallback. See the focused
[`E06-S04 review packet`](../reviews/E06-S04.md) for exact verification and pending
gates.

**Admission gate:** Before endpoint readiness/model discovery can ship, define an owner-controlled endpoint record and exact local service binding through the trusted Runtime broker, with authenticated local transport, strict loopback/private-address and redirect policy, bounded connect/read/body/model-list limits, cancellation, sanitized errors, and no credential disclosure. Agent- or document-supplied URLs are never accepted. If this gate is not satisfied, the UI must report `UNAVAILABLE`/`NOT_CONFIGURED`; it must not probe an arbitrary URL or silently use a cloud provider.

**Acceptance:** Airplane-mode test completes with local parsing/embedding/inference when configured; model limits explicit; Core never becomes reasoning loop.

**Negative/race cases:** OOM, no GPU, cold load, context overflow, stalled stream, tool call unsupported.

**E06-S04-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E06-S04-USER:** Run cited document task and coding edit on two recorded hardware profiles. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.

**Current placement and degradation boundary:** Placement is explicit and Core-owned. The
Workspace replication policy, the presence of a non-local Resource location, and an
explicit local-only declaration decide whether a Resource is `LOCAL_ONLY` or
`CLOUD_ELIGIBLE`; a local-only Resource blocks a cloud consumer with the typed blocker
`RESOURCE_LOCAL_ONLY` instead of being uploaded. The desktop decodes that decision and
never infers placement from a path, a Provider, or an Agent. Index state keeps "uploaded"
apart from "searchable": the desktop refuses a `READY` index that does not name its
revision, and only `READY` is searchable. Truthful degradation is part of the contract:
the served retrieval provider reports `LEXICAL_ONLY` and `LOCAL` placement, an
unserviceable provider answers with an explicit `PROVIDER_UNAVAILABLE` status and a
reason code, and the local model inventory answers `NOT_CONFIGURED`. The new desktop
modules are pure decoders and labels in `apps/litecowork-ui/src/resources/`; the Tauri
bridge, the OpenAPI definitions, and the Library component wiring are reported to the
lead and are not applied by this slice. The read-only "Context used" disclosure is not
implemented. See the focused [`E06-S05 review packet`](../reviews/E06-S05.md) for exact
verification and pending gates.

**E06-S05-USER:** Drag a ZIP, inspect readiness and citation, rebuild the local lexical index for a supported text Resource, observe a typed not-indexable result for ZIP, inspect Context used for a grounded Task, verify exact source revisions, and attempt a disallowed cloud Task. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Current local lexical-index control source:** The desktop Library submits an owner-triggered rebuild command pinned to the listed ResourceRevision ID and SHA-256 digest. The authenticated local Operator route and SQLite implementation return `INDEXED` or a typed `NOT_INDEXABLE` reason; a successful projection update and its principal-scoped idempotency receipt commit together. This is deterministic lexical indexing only. It does not implement embeddings, semantic RAG, ZIP extraction, parser expansion, or background indexing. The Library also renders source references from real content-search result spans and opens the exact pinned revision; the UI validates the preview digest and UTF-8 byte spans before highlighting and falls back to plain text if they do not match. This does not establish semantic retrieval, citation verification independent of the local preview, or a durable Task-context receipt. The lexical-index endpoint, storage transaction, packaged desktop flow, and owner acceptance still require explicit focused verification. E06 acceptance remains open.

**Desktop one-time file intake source path:** The Library exposes the WebView's native file chooser for multiple files, a directory chooser through the platform-supported `webkitdirectory` attribute, drag-and-drop, and Workspace-note creation. The intake submits selected bytes through the authenticated local IPC Operator bridge and the existing resumable upload session/chunk/commit routes; it does not send absolute selected paths to the daemon. Folder files retain only normalized relative-path provenance and remain one-time Resources, not persistent WorkspaceRoot grants. After commit, Resource metadata enters the Workspace-scoped catalog and eligible plain text can be previewed by exact ResourceRevision through the authenticated local route. ZIP files remain opaque original-byte Resources; upload completion does not mean extraction or indexing.

The UI now reports the current file being digest-checked before it starts/resumes transfer, then reports accepted byte ranges and commit status. Folder paths are validated without rewriting unsafe separators. Code-level coverage is in `apps/litecowork-ui/tests/resource-intake.test.ts` for traversal/absolute/drive/control/length rejection, secret/generated-path filtering, nested relative-name preservation, and per-file/count/aggregate-size bounds. UI TypeScript/production build and UI unit tests pass in the current development environment. These checks do not exercise an actual Tauri OS chooser, daemon IPC peer authentication, multi-chunk upload/restart recovery, real folder permissions, or owner acceptance on a packaged desktop. Those are still required by E06-S05-SYSTEM and E06-S05-USER. WorkspaceRoot watching, recursive indexing, archive extraction, PDF/Office parsing, OCR, embeddings, semantic/local-model RAG, and automatic/background indexing remain unimplemented.
