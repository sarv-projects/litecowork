# SP03 — Authenticated local Operator transport

Status: **SOURCE PARTIAL, NOT QUALIFIED**. The daemon now has an unconnected Unix
directory-handle opener in `apps/litecoworkd/src/local_filesystem.rs`. It is not called by
the native folder picker or WorkspaceRoot service, does not prove restart identity, and
is not evidence of a supported or production-safe persistent-root flow. The local IPC
qualification gates below remain open.

## Question

Can Tauri send privileged, native-only commands to `litecoworkd` over local IPC with an
authenticated OS peer on every supported desktop OS, while leaving ordinary local reads
on the existing bounded loopback HTTP bootstrap?

## Candidate

Evaluate `interprocess` 2.4.x Tokio local sockets for Unix-domain sockets and Windows
named pipes. Keep the decision behind one `OperatorLocalIpc` module interface. Do not let
transport handlers write SQLite directly; authenticated commands enter the same
application service used by other Operator transports.

The initial daemon opener uses Rustix `openat` with directory, close-on-exec, and no-follow
flags for every canonical path component, then captures device and inode from the opened
handle. Rustix documents `openat` as an `fs`-feature API and exposes `O_NOFOLLOW`;
this source still needs Linux/macOS compilation and race qualification. It records neither
a keyed public identity projection nor restart-persistent raw identity yet.

### Linux and macOS

- Bind below the private Runtime state directory and require an owner-only directory and
  socket permissions before accepting a client.
- Authenticate the connected peer using kernel effective user credentials. Reject missing
  or unsupported credentials and any peer not mapped to the local owner Principal.
- Inspect socket type, owner, and mode before stale-endpoint cleanup; never unlink a
  symlink or an endpoint owned by another principal.
- On sandboxed macOS packaging, transfer a security-scoped bookmark to the daemon and
  prove the daemon can start/stop scoped access correctly. A plain path is not enough.

### Windows

- Create the named pipe with an explicit DACL limited to SYSTEM and the current user/logon
  SID; reject remote clients.
- Determine whether the chosen Rust adapter can validate the client SID. PID-only peer
  credentials do not prove an authorized user. If necessary, add a narrow Win32 token
  impersonation adapter that validates the SID and always reverts impersonation.
- Verify pipe creation, cleanup, and reconnect behavior across logon sessions.

## Narrow command

Use native Tauri Rust to open a folder picker and retain its platform grant. The WebView
receives no path or bookmark. Send one versioned request over authenticated IPC:

```text
WorkspaceRootGrantRequest {
  request_id
  workspace_id
  expected_workspace_version
  watch_policy
  selection_grant
}
```

`selection_grant` is an IPC-only value and never enters HTTP JSON, events, logs, ordinary
Resources, or Workspace backups. The daemon verifies peer identity, Workspace ownership,
  the active `RuntimeWorkspaceBinding`, and the exact selected directory identity before
calling `WorkspaceRootService`. The response contains only the WorkspaceRoot ID and safe
display name. Root creation remains unavailable until the Runtime/Workspace enrollment
contract and atomic Resource/location/root transaction are implemented.

## Evidence to collect

- Exact Rust, Tauri, `interprocess`, Windows SDK, macOS SDK, and OS versions.
- Executed commands and minimal native client/server source revision.
- Socket/pipe ACL inspection for owner, second OS user, second Windows logon session, and
  remote client cases.
- Tests for unauthorized peer, missing credentials, descriptor replay, stale socket,
  symlink replacement, process restart, pipe reconnect, and request truncation/oversize.
- A Tauri native folder-selection run showing that the WebView, HTTP requests, logs, and
  ordinary artifacts contain no absolute path/bookmark bytes.
- On sandboxed macOS, a real signed-app run demonstrating bookmark access from the daemon
  process and balanced `startAccessing`/`stopAccessing` behavior.

## Pass/fail

Pass only when each supported OS authenticates the peer identity at the privileged-command
listener, rejects unauthorized users/sessions, and completes the folder-selection command
without exposing its raw locator outside Tauri/daemon private memory and local binding
storage. An unsupported OS fails closed and is not advertised as supporting persistent
Workspace roots. A Linux-only pass is not a cross-platform release qualification.
