# E07-S05 partial CODE review packet — Desktop computer use and opt-in observation

**Status:** Partial CODE only. E07-S05 stays `PLANNED`. This build has no qualified
computer-use provider, so the probe reports the provider as unavailable and every
action and observation is refused. The story's SYSTEM and OWNER USER gates are open.

## Implemented slice

`apps/litecoworkd/src/environment_computer_use.rs` implements the E07-S05 policy
boundary. It decides whether a requested computer action or observation may be
attempted; it performs no capture and injects no input.

**No screen capture on opening Quick Entry.** A request whose trigger is
`ComputerUseTrigger::QuickEntryOpened` and whose action is a capture is refused with
`QuickEntryCaptureRefused`, before consent is even consulted. The check is a separate
case in the fixed refusal order so that the reason is stable and reportable.

**Observation only inside an opted-in scope.** `ComputerObservationConsent` is
explicit, expiring, and revocable, and carries one or more
`ComputerObservationScope` entries that name the application, the window, and whether
screen capture and input injection are allowed. `authorize_computer_action` refuses a
missing, revoked, or expired consent (`ConsentMissing`, `ConsentRevoked`,
`ConsentExpired`), an application outside the scope (`ApplicationNotInScope`), a window
outside the scope (`WindowNotInScope`), a capture where only input is permitted
(`CaptureNotPermitted`), and input where only capture is permitted
(`InputNotPermitted`).

**Unsupported OS/action is surfaced, not simulated.** `probe_computer_provider` reports
`ComputerProviderAvailability::UnsupportedPlatform` or `Unavailable` with a stated
reason. On Linux it distinguishes "no display server is available to this session"
from "the XDG desktop portal screen-cast and remote-desktop paths are not qualified".
No platform is reported as `Available` in this build, so
`authorize_computer_action` refuses with `ProviderUnavailable` before any other check.

**No bypass of site or system security.** A request with `bypass_security` set is
always refused with `SecurityBypassRefused`.

**Negative cases.** `ScreenLocked` refuses every action while the OS session is locked.
`HumanOwnsInput` refuses every action after a human takeover. A sensitive region label
(using the same classifier as the browser module) is refused with `SensitiveRegion`,
and a scope that excludes a region refuses a request that targets it.

## Contracts

- [E07-S05](../epics/E07.md#e07-s05-desktop-computer-use-and-optional-observation) owns
  the OS-specific qualified computer provider, isolated opt-in observation, screen
  capture permissions, and privacy controls.
- [ENVIRONMENTS](../../docs/ENVIRONMENTS.md#desktop-coworker-environment-availability-target)
  requires that a Coworker has no implicit computer access and that a merely installed
  local app is not a qualified automation adapter.
- [CHROME-BROWSER-LLD](../../docs/CHROME-BROWSER-LLD.md#page-behavior-and-control-conflicts)
  requires human handling for password fields, payments, identity prompts, CAPTCHA,
  bot protection, and MFA, and forbids any bypass promise.
- [TRUST](../../docs/TRUST.md) keeps the observation consent a revocable grant rather
  than a standing permission.

## Remaining executable work and limits

- Qualify an OS-specific computer-use provider (XDG desktop portal on Linux, a
  qualified Windows capture/injection path, macOS screen-recording and Accessibility
  permissions) and record the exact OS build and provider version per platform.
- Add the real observation pipeline: bounded frame size, privacy zones, redaction, and
  source provenance for every captured frame.
- Add a real revocation path that fences in-flight effects when the user revokes
  observation consent mid-action, and record ambiguity for already external sends.
- Add the human-takeover epoch plumbing that the browser control lease already has, so
  a desktop takeover and a browser takeover share one control model.
- Keep the Quick Entry no-capture rule on the real surface, not only in the policy
  function.
- Do not present any computer-use control as active until a typed route, a permission
  gate, verified OS behavior, and a correct unknown/error state all exist.
