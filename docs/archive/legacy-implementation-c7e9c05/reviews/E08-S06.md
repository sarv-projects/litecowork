## Implemented behavior

`ConversationStreamController` reduces authenticated, Workspace- and Conversation-scoped
typed stream frames. The Conversation page now consumes the reducer's transient turn state
alongside saved messages. In-progress text is rendered as ordinary React text, never
interpreted as markup, and is explicitly labeled temporary. Reconnecting turns, incomplete
turns, stream startup, transport failure, cursor resynchronization, and empty saved history
have visible status or semantic fallback. A resync clears transient content; a later
authorized durable snapshot restores the saved-history view. Transport error details are
not exposed in the UI. Turn state changes use one polite, atomic status announcement;
individual text deltas are not live-announced.

The reducer caps active turns at 4, retained turn records at 8, any one retained transient
response at 256 KiB UTF-8, and all retained transient response text at 512 KiB UTF-8. It
rejects additional concurrent identities and fences a response whose sequence or byte
budget cannot be safely continued. These ephemeral limits do not change durable message
storage or provider execution semantics.

Rich Presentation uses the existing typed `RichDraft` event protocol and bounded draft
reducer. No generated HTML/JS execution path was added. Available items continue to use the
safe typed renderer and semantic text fallback.

### Source

  partition (outcome, activity, saved outputs, other saved items, rejected items,
  omitted count).
- `apps/litecowork-ui/src/presentation/TaskPresentationPanel.tsx`: the saved Task
  presentation now keeps a visible placeholder for an item it cannot validate instead of
  hiding it, and reports the omitted count when a snapshot exceeds the display limit.
- `apps/litecoworkd/src/presentation_operator.rs`: a new focused test asserts that
  reading a Conversation presentation snapshot appends **no** domain event.

### Behavior

- A saved presentation item that fails validation is no longer dropped from the Task
  surface. It appears under "Content not shown" with the reason, and the rest of the
  saved Task is unchanged. The earlier wording ("items were hidden") was replaced with
  "items could not be displayed safely", which matches what actually happened.
- An item with an unsupported payload version or an unsupported renderer is labelled
  rather than removed, and only revalidated source identities are shown beside it.
- A hostile payload stays inert text; an unvalidated payload cannot invent host state
  such as an "Approved" status.
- Reading the Conversation presentation snapshot three times leaves the Workspace event
  journal unchanged: transient frames are not journaled as domain events.

callback and the local reducer are still not a provider.
