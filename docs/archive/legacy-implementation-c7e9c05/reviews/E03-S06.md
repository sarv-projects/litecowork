## Implemented slice

[`module_registry.rs`](../../apps/litecoworkd/src/agents/module_registry.rs) adds a bounded
compiled-manifest index that:

- validates module IDs, semantic versions, display names, distribution-kind enums, claimed
  ACP identity syntax, and unique supported-OS/distribution/identity lists;
- rejects duplicate module IDs and invalid manifests before storing them;
- matches only an exact registry identity on a supported OS and architecture and selects
  the highest descriptor API version no greater than the host API version;
- fails closed when two modules make the same highest compatible claim; and
- returns supported manifests in stable module-ID order.

The matcher also exposes four diagnostic states: `NoAdapter`,
`NoCompatibleDescriptor`, `UnsupportedRuntime`, and `Supported`. `Supported` requires a
registered manifest to claim the exact registry identity and match the current Runtime OS,
architecture, and descriptor API. It does not imply installation, authentication, session
readiness, or qualified support.

ACP metadata remains data only. Distribution kinds are a closed enum and no registry
payload can supply an executable path, command, authentication action, or credential slot.
This matcher is not yet connected to concrete AgentModule lifecycle or runtime adapters
and does not identify the curated portfolio.

The source now also contains an ACP Registry projection parser in
[`acp_registry.rs`](../../apps/litecoworkd/src/agents/acp_registry.rs). Against the pinned
Registry document format, it bounds input to 2 MiB and 512 agents, rejects duplicate IDs,
invalid version/license metadata, and entries without an approved package or HTTPS archive
reference. It projects only ID/name/description/homepage/distribution metadata; upstream
`cmd`, `args`, and `env` fields are discarded.
It accepts the aggregate `{version, agents}` document described in the pinned
[ACP Registry format](https://github.com/agentclientprotocol/registry/blob/4d1729af836732b46840080920912dac7d5a2935/FORMAT.md);
individual `agent.json` manifests are intentionally not accepted as registry snapshots.

`agent_registry_operator.rs` fetches only the fixed HTTPS registry origin with redirects
disabled, bounded response streaming (2 MiB), a 3-second connect timeout, and an 8-second
total timeout. A completely validated snapshot is atomically persisted through
`AgentRegistryCacheStore`; expired rows remain readable and are returned as stale if the
upstream is unavailable. The daemon reloads that snapshot from SQLite, so stale metadata
survives daemon restart. Cached metadata is shape/bounds-checked before projection, and
cached claims are forced to `NO_ADAPTER`. Authenticated routes provide list, search,
pagination, and refresh. Cursors bind to normalized query, source revision, and a digest of
the immutable snapshot identity/content; the time-derived `stale` serving flag does not
invalidate a cursor. The Settings catalog can list, search, page, and refresh independently
from installation, native profile observation, authentication, and readiness. Registry
presence does not create a binding or start an agent.
