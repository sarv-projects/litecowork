## Implemented slice

`crates/domain-environment/src/browser_control.rs` adds pure control-lease decisions for
single-owner browser input. An action is rejected when its actor or epoch is stale, the
lease has expired, or the actor is not the current owner. Agent-to-user and user-to-agent
transfers advance the epoch and require no in-flight inputs. Returning to the agent also
requires the requesting user to match the current lease owner and an observation bound to
the same Environment, Task, Attempt, Runtime, Runtime incarnation, and user-control epoch,
captured after the user took control.

`crates/domain-environment/src/browser_pointer.rs` adds a pure mapper from a displayed
frame's pane coordinates to Chrome CSS viewport coordinates. It rejects a mismatched
session/tab, tab generation, control epoch, frame sequence, or transform revision; future
or caller-policy-expired captures; invalid viewport/pane/scroll metadata; non-finite
positions; and coordinates outside the displayed frame. Capture metadata carries scroll
offset and device scale factor, while mapping stays in CSS coordinates: UI pointer
positions and CDP input coordinates are both CSS pixels, so multiplying by device scale or
adding document scroll would distort the viewport point. This does not check the persisted
lease itself or dispatch input. The caller still has to recheck the current control epoch
and authorize the resulting action before provider dispatch.

The browser module is a decision function only. A caller must atomically persist the
resulting lease projection before accepting the new owner's input. The current tree now
also has a durable `EnvironmentControlLeaseStore` port and SQLite acquire, owner takeover,
and end transitions. These transactions enforce owner Workspace scope, exact current
Runtime/Environment/Attempt/AgentSession bindings, CAS on lease version and epoch,
Event/aggregate-state/request-receipt commit, and digest-only fence storage. The Agent
Session identity is recovered from the immutable Attempt binding after takeover. A
hydration constructor preserves that original AgentSession owner when rebuilding a
USER-owned in-memory projection after restart. No Operator route currently calls these
store operations; the store code therefore does not yet grant browser authority.

Admission now requires a RUNNING Task and Attempt, an ACTIVE ATTEMPT_EXECUTION session,
the current usable Runtime incarnation, a READY/BUSY Environment, and a non-expired
provider binding for that incarnation. Renew and HUMAN-to-AGENT remain fail-closed.
SQLite represents EXPIRED as a terminal state, but the current operation contract has no
eventful expiry command. Since an expired row still occupies the unique ACTIVE slot,
reacquiring that Environment can fail until an authority defines the expiry transition.
No unreceipted state mutation is used to work around this.

## Intended Browser Harness provider boundary

Browser Harness is the intended LiteSPM-managed browser capability candidate, including
default availability to compatible installed agents after package and host qualification.
Availability is discovery only: it does not grant a Task browser access, select a Chrome
profile, attach to an existing session, or authorize a site or action. LiteCowork must
retain Environment ownership, managed-profile isolation, authenticated actor identity,
control-epoch fencing, per-action Trust/Invocation/Effect and idempotency, and ambiguous
response reconciliation. The pinned upstream implementation is not safe to expose
unchanged because its generic CDP/JavaScript, profile discovery, retry, recording, and
telemetry surfaces exceed those boundaries. It must be wrapped behind a typed
BrowserActionService; agents must not receive its raw control surface.

This remains a target integration, not a live adapter. The current LiteSPM contract does
not specify the package-serving API, and the current E04 invocation path does not provide
the complete browser dispatch, Effect, and reconciliation gates. No LiteSPM endpoint or
wire format is invented here. Until those producers are available, Browser Harness
installation/dispatch and default agent availability remain unavailable, while the pure
control-fencing decisions above remain usable only as domain logic.

The E04 owner confirmed during this implementation run that no production Invocation/
Trust/Effect dispatch transaction is currently available; its DISPATCHED/STARTED path
remains fail-closed while VerificationRun evidence settlement is being implemented. E07
will not add a second invocation gateway or call Browser Harness directly around that
gate.

## Browser input control service, profile policy, and observation consent — 2026-10-20

This slice adds the two missing Runtime-side pieces of E07-S02: the input control
service that owns the single-actor/epoch rules, and the profile/consent policy that
keeps the real-Chrome restrictions and the explicit-consent requirement enforceable
in code. Neither is wired to a provider, a route, or a Chrome process.

### `apps/litecoworkd/src/browser_control_service.rs` — one input actor, epoch fenced

* The acting owner is **derived** from the authenticated principal and the lease
  (`derive_actor`). The `claimed_actor` in the request is only checked for
  consistency: a request that claims `USER` while the lease belongs to an agent
  session is refused with `ActorMismatch`, and a different agent session is refused
  with `NotTheLeaseOwner`. A request can never grant itself an actor.
* A stale `expected_epoch`, a stale `expected_session_revision`, an expired lease, a
  `TRANSFER_PENDING` lease, and a `MANUAL_ONLY` browser mode each refuse the action.
  A queued agent action that still carries the pre-takeover epoch is therefore
  discarded after a takeover, which is the "queued stale actions discarded"
  acceptance fact.
* `request_takeover` is atomic: it requires a user principal, a current epoch, a
  live lease, and zero in-flight provider inputs (`InputsInFlight`), then advances the
  control epoch and the session revision and moves ownership to the user.
* `return_to_agent` requires a fresh observation that was captured under the *current*
  user control epoch, that advances the observation revision
  (`ObservationRevisionNotAdvanced`), that is not from the future, that is not older
  than the caller-supplied maximum observation age, and that names a provider
  identity. A stale, reused, or over-age observation never releases the lease back to
  the agent, and a different user cannot return control at all.
* The recorded execution method is exact: `DomElement`, `AccessibilityNode`,
  `CoordinatePointer`, `KeyboardEvent`, `Navigation`, or `Download`. There is
  deliberately no "arbitrary script" or "raw protocol" member, so an agent cannot be
  handed a generic escape hatch.

### `apps/litecoworkd/src/browser_consent.rs` — real-Chrome restrictions and explicit consent

* `is_default_chrome_user_data_directory` recognises the default Chrome/Chromium/Edge
  user-data directories on Linux, macOS, and Windows. `decide_existing_chrome_attach`
  refuses such a directory with
  `DefaultUserProfileNotAutomatable`, because Chrome 136+ ignores remote debugging
  against the default user directory and Playwright does not support automating it.
  LiteCowork never points a provider at the default profile and never copies cookie
  material.
* `create_managed_profile` allocates a separate, LiteCowork-marked profile directory
  and refuses to use a default user-data directory.
* An attach to an already running Chrome requires a per-session
  `ChromeAttachConsent` that is unrevoked, unexpired, bound to the observed Chrome
  major version, and carries the high-trust acknowledgement
  (`HighTrustAcknowledgementMissing`). Anything below Chrome 144 is refused
  (`BrowserVersionTooOld`), and the consented version must equal the observed version.
  A candidate directory that is not LiteCowork-managed is refused
  (`ProfileNotManagedByLiteCowork`).
* `preview_profile_import` accepts only bookmarks and settings. Cookie, login-data,
  web-data, local-state, history, session, token, secret, and key files are rejected
  as `CredentialMaterial`, and an import can therefore never become a sign-in import.
  Traversal paths and oversized entries are rejected, and the preview carries a digest
  so the apply step can bind to the exact preview.
* `authorize_observation` requires an explicit, unrevoked, unexpired
  `ObservationConsent` whose scope covers the requested session, window, origin, and
  capture kind; it refuses a missing, revoked, or expired consent and an out-of-scope
  window, origin, session, or capture kind. `classify_sensitive_region` marks
  password, payment, identity, CAPTCHA, one-time-code, and clipboard surfaces as
  sensitive.
