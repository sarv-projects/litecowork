## Deterministic learning-gate engine (CODE) — 2026-10-20

`docs/LEARNING.md` is the sole owner of candidate eligibility, redaction, conflict
handling, policy and revocation. This slice implements the **deterministic** part of that
contract as a typed, tested module and adds no product claim: nothing here learns by
itself, no candidate is persisted, and no "learns automatically" wording was added to any
surface.

### Source

- `crates/storage-core/src/coworker_learning.rs` (new): typed records and rules.
- `crates/storage-core/src/lib.rs` (shared file): one `mod coworker_learning;` line and one
  `pub use` block. No other shared region was touched.

The module owns:

| Contract | Implementation |
| --- | --- |
| LEARNING.md §3 `LearningCandidate`, §4 `CoworkerLearningPolicy`, §5 `MemoryCandidatePayload`, §7 `MemoryRecordMetadata` | typed records with the contract's field names and closed enums |
| §4 memory mode / source eligibility / conversation class | `CoworkerLearningPolicy::default_for_coworker`, `allows_certainty`, `eligible_source_kinds` |
| §16 default eligible and ineligible source classes | `LearningSourceChannel::is_trusted` and the closed channel→source-kind mapping |
| §6 automatic-commit decision | `evaluate_learning_candidate` returning `LearningEvaluation { disposition, state, reason_codes, conflict }` |
| §5/§21 secret and sensitive-data rules | `redact_sensitive_content` → `RedactionReport` with `Forbidden` and `ReviewRequired` findings |
| §15 contradiction and supersession | `classify_learning_conflict` → duplicate / supersedes / supports / conflicting |
| §20 closed candidate state machine | `LearningCandidateState::is_terminal` |
| §19/§22.13 event payload without candidate text | `learning_candidate_event_payload` |

The default policy is `AUTO_CONFIRMED_PRIVATE` with eligible source kinds
`USER_EXPLICIT`, `USER_CORRECTION`, `USER_FEEDBACK`, `DEMONSTRATION`. `TASK_OUTCOME` is
**not** in the default set: LEARNING.md §16 lists only owner messages, owner feedback and
owner demonstrations as default eligible sources, so a Task-outcome source needs an
explicit owner revision.

`inferred_confidence_threshold` is an added policy field because LEARNING.md §6 requires
"candidate confidence >= policy threshold when INFERRED" and §4 has no other field that
can hold it. This is a contract detail that the lead should confirm in
`docs/LEARNING.md`.

### What the focused tests prove

- A confirmed owner preference auto-commits under the default private policy; the same
  candidate under `REVIEW_ALL` stays for review; an inferred claim stays for review under
  `AUTO_CONFIRMED_PRIVATE` and commits under
  `AUTO_CONFIRMED_AND_LOW_RISK_INFERRED_PRIVATE` only above the threshold.
- A temporary conversation never learns, and a policy that lists `TEMPORARY` still cannot
  make one eligible.
- Third-party message, imported document, web content, tool description, model output,
  worker output and connector event channels are rejected; a source kind outside the
  policy is rejected; a source kind that does not match its channel is rejected.
- Instruction, Skill, Routine and Automation proposals always require review.
- Forbidden sensitivity and a forbidden redaction finding are rejected; review-required
  sensitivity never auto-commits.
- Trust exclusion and an excluded resource label fail closed; an `OFF` policy and a
  candidate for another Coworker are rejected.
- Identical claims are deduplicated, a confirmed claim supersedes an inferred claim, and
  conflicting confirmed claims require review; a revoked memory creates no conflict.
- The secret detector finds provider access tokens, private key blocks, secret
  assignments and Luhn-valid payment card numbers, leaves an ordinary preference alone,
  flags a government identifier as review-required rather than forbidden, and the redacted
  copy no longer contains the secret bytes.
- The learning event payload carries identifiers, digests and reason codes and never the
  candidate body.

### What this slice does not prove

This is a pure rules module. It does **not** qualify a classifier, a qualified
agent-backed extraction capability, a Resource-backed candidate payload, a persisted
policy revision, a candidate queue, an automatic commit transaction, a Memory & Knowledge
surface, agent-controlled recall, or a revocation/purge receipt. There is no producer, no
extractor, no API route and no UI. The module therefore does not satisfy any part of the
E08-S03 automatic-learning acceptance.
