### Operator routes (`apps/litecoworkd/src/rag_retrieval_operator.rs`)

```text
POST /v1/resources/retrieval
GET  /v1/resources/{resource_id}/index-state
```

`POST /v1/resources/retrieval` requires the selected Workspace header and the
authenticated Workspace owner. It accepts a closed body:

```json
{
  "query": "string",
  "scope": [{ "resourceId": "...", "resourceRevisionId": "...", "contentDigest": "sha256:..." }],
  "maxResults": 10,
  "requestId": "..."
}
```

`scope` is optional. Absent means every ACTIVE Resource of the selected Workspace; an
explicit empty scope is refused with `400 INVALID_ARGUMENT`. Every response is
`Cache-Control: no-store`.

The response is one of three truthful states:

```json
{
  "requestId": "...",
  "workspaceId": "...",
  "status": "GROUNDED | INSUFFICIENT_EVIDENCE | PROVIDER_UNAVAILABLE",
  "provider": { "providerId": "...", "providerVersion": "...", "availability": "...",
                "retrievalMode": "LEXICAL_ONLY", "placement": "LOCAL",
                "reasonCode": null, "reason": null },
  "citations": [{
    "citationId": "resource-1:revision-1:0",
    "resourceId": "resource-1",
    "resourceRevisionId": "revision-1",
    "contentDigest": "sha256:...",
    "locator": { "kind": "TEXT_SPAN", "span": { "startUtf8Byte": 0, "endUtf8ByteExclusive": 5 } },
    "matchedSpans": [{ "startUtf8Byte": 0, "endUtf8ByteExclusive": 5 }],
    "excerpt": "...",
    "providerId": "litecowork.local-lexical",
    "providerVersion": "litecowork.local-lexical/1",
    "warnings": []
  }],
  "insufficientReason": null,
  "scannedCandidates": 3,
  "truncated": false
}
```

`GROUNDED` requires at least one citation. `INSUFFICIENT_EVIDENCE` carries no citation
and names the reason (`NO_AUTHORIZED_MATCH` or `PINNED_REVISION_NOT_INDEXED`). There is
no response shape that reports a claim without a source reference.

### Grounding and authorization rules

- A citation names the exact `resourceId`, `resourceRevisionId`, and `contentDigest` of
  the immutable revision the segment was read from, plus an exact UTF-8 byte locator.
- The provider never widens the authorized scope: Core resolves the scope and the
  provider only narrows it.
- The provider re-checks authorization at the last boundary with
  `ResourceStore::get_resource_detail`: a Resource outside the Workspace, a
  ContextDocument that is not `ACTIVE`, or a head that moved since the index was built
  is dropped instead of being served.
- Retrieved content is untrusted data. `detect_embedded_instructions` marks
  directive-like text with `EMBEDDED_INSTRUCTION_DETECTED`, and `validate_claims`
  rejects a claim whose only supporting citations carry that warning. A claim that
  references an unknown citation, or has no citation at all, is rejected.
- A stored segment produced by a different parser generation is never mixed into one
  result set: `parser_generation_is_compatible` fails the request with
  `PROVIDER_INDEX_GENERATION_INCOMPATIBLE` instead of comparing incompatible vectors.
- The request budget is hard: at most 20 results, 2 KiB per excerpt, 16 KiB total
  excerpt bytes, 2 KiB query.

## Remaining gaps

- No semantic or hybrid provider is qualified. The served provider is deterministic
  token equality over the local encrypted text index. It is not embeddings, not
  vector recall, and not reranking.
- Only the current head of a Resource is indexed. A request that pins an older
  immutable revision returns `INSUFFICIENT_EVIDENCE` / `PINNED_REVISION_NOT_INDEXED`
  instead of silently substituting a newer revision.
- No answer composer, Task attachment, or Context-used receipt is implemented. The
  grounding rules exist and are tested, but no component assembles a claim set yet.
- No SYSTEM run against a packaged desktop, and no owner USER case (20 PDFs, a code
  folder, checked citations).
