## Implementation

The native instruction bridge in `apps/litecowork-ui/src-tauri/src/lib.rs` now uses the
canonical `/v1/workspaces/{id}/instructions/revisions` route for both list and create. The
old formatter trimmed `/workspaces` from the collection base and produced
`/v1/{id}/instructions/revisions`; the corrected builder retains the route segment. URI
delimiters allowed by the local IPC path contract are percent-encoded as a single path
segment, while the original Workspace ID remains in `X-Workspace-ID`. IDs containing `/`,
backslash, or exact `.`/`..` path segments are rejected locally because the shared IPC
validator rejects encoded separators and path traversal. The IPC validator itself is
unchanged.

The command wrappers still call `operator_client`, which derives the client from Tauri's
trusted application-data directory and validates the Operator readiness response. Unix
connections verify the peer UID before sending request frames. Extracted client-taking
helpers allow tests to use this same client and bridge mapping without creating a fake
`AppHandle`.
