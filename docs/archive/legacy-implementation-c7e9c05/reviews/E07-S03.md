## Implemented slice

`apps/litecoworkd/src/environment_action_batch.rs` adds the decision layer for the
three E07-S03 rules that `docs/ENVIRONMENTS.md` states explicitly.

**A batch is not a transaction.** `plan_batch` admits members in declaration order and
records a per-member refusal reason (`TooManyMembers`, `DuplicateMember`,
`UnknownDependency`, `DependencyNotAdmitted`, `StalePrecondition`,
`InsufficientDeadlineBudget`, `DeadlinePassed`). `reconcile_batch` then produces
`Completed`, `PartiallyApplied`, `Ambiguous`, or `Aborted`. An applied member is never
rolled back: `BatchOutcome::applied()` reports the members whose effect is known to
have happened, and the `Aborted`/`PartiallyApplied` split follows the batch's
`AbortPolicy` (`StopOnFailure` versus `ContinueIndependent`). The member-3-fails-after-1
case is covered directly.

**No hard realtime.** The deadline is treated as a *budget*: the preflight subtracts each
member's estimate from the remaining budget and refuses a member that does not fit
(`InsufficientDeadlineBudget`). The plan records `estimated_duration_ms` and never
returns a promised completion time, so a deadline can never be presented as a hard
real-time guarantee.

**Warm state carries no authority.** `WarmHold` has no grant, lease, secret, or effect
field at all. `admit_warm_hold` only decides whether a warm Environment is *usable*:
it refuses a prewarm that performed a model call (`PrewarmPerformedModelCall`), a
prewarm with no recorded configuration (`PrewarmNotRecorded`), an expired hold
(`TtlExpired`), and a hold whose provider configuration drifted
(`ProviderConfigDrift`). `warm_hold_satisfies_authority` always returns
`WarmHoldCarriesNoAuthority`, which is the explicit statement that a warm Environment
can never stand in for a grant or a lease. `evict_under_pressure` evicts the oldest
usable hold first so the most recently prepared Environment survives.

## Contracts

- [E07-S03](../epics/E07.md#e07-s03-actionbatchdeadlinewarm-lifecycle) owns bounded
  per-member invocations/effects, preconditions/abort/fallback, deadline preflight, and
  WarmHold TTL/pressure eviction/config recheck.
- [ENVIRONMENTS](../../docs/ENVIRONMENTS.md#provider-result-and-isolation-rules) requires
  provider-mediated mutations to reject a stale fence and to keep provider state out of
  Task/Attempt state.
- [ARTIFACTS-EVIDENCE](../../docs/ARTIFACTS-EVIDENCE.md) owns Effect recording and
  reconciliation; this module records no Effect and dispatches nothing.
- [TRUST](../../docs/TRUST.md) keeps capability grants and leases out of warm state.

## CODE evidence

Exact commands from this working tree (Linux, Rust/Cargo 1.98.1, 4 CPUs, `--jobs 2`):

```sh
/tmp/opencode/cargo-lock.sh cargo test --locked --offline --jobs 2 -p litecoworkd environment_action_batch -- --test-threads=1
```

Result: **13 passed, 0 failed, 0 ignored.**

Covered cases: deadline-budget admission, member that does not fit the budget, a batch
whose deadline has passed, a stale precondition, a dependency that was not admitted,
partial success with an applied prefix (not a transaction), an ambiguous member result
that is never treated as complete, `ContinueIndependent` partial success, a prewarm that
called a model, hold expiry, provider-configuration drift, pressure eviction order
(oldest usable hold dropped first, and an unusable hold dropped before any usable one),
and the explicit "a warm hold carries no authority" assertion.
