# Errors and recovery - Safe Task Path

**Status:** Revision 1.0 ACCEPTED/LOCKED; revision 1.1 IN_REVIEW with owner-directed implementation authorization; not a claim of implementation or qualification.

## Target recovery rules

- A Task-create retry with the exact same idempotency identity/payload returns the original Task receipt. Reusing the same request identity with a different payload is a conflict.
- A stale Task aggregate or TaskSpec head blocks plan acceptance. A producer who is no longer the authorized planning session/leased lead cannot commit a plan.
- Plan acceptance is distinct from Task creation and Attempt admission. A Task record, readiness preflight or READY status does not start execution.
- Isolation attestation must be from the current Runtime incarnation and match the exact Environment, Workspace, Task, normalized policy, pinned input set and readable/writable roots. Any UNKNOWN/NOT_ENFORCED enforcement field fails closed. The attestation must come from the live held scope that will receive the native harness; capability-probe output and detached probes do not qualify.
- Planning uses a Task-scoped read-only Environment; every execution/child/verifier Attempt uses a fresh ATTEMPT_PRIVATE Environment. Before provider creation, Runtime durably journals a private preparation intent. The provider may start only a trusted idle supervisor before admission; the native harness, tools, credentials and user code wait for the resolved admission receipt. Failed or ambiguous preparation creates no admitted Attempt and is cleaned only after exact provider identity and quiescence are observed. If storage may have committed, resolve the original idempotency receipt before launch or cleanup. The admission transaction commits Environment metadata, Attempt, Step binding, lease and STARTING AgentSession; the one-time native-harness launch handoff follows commit. Before a file call, the separate canonical mediated-dispatch transaction rechecks the exact live Attempt/session and lease fence, durable grant, activation, Trust decision, Approval and action/content digests while atomically committing Invocation DISPATCHED, Effect STARTED, ApprovalUse, events and receipt. Attempt admission and dispatch are distinct; no `invocation_intent` record is used. Every provider/filesystem call runs outside SQLite. An unknown external result is reconciled against the exact pinned ResourceRevision digest before retry.
- Cancellation fences late work. Writer lease release and Environment destruction require a positive QUIESCENT observation bound to the exact Runtime incarnation and process scope. Unknown quiescence leaves the Attempt fenced.
- Runtime restart must recover durable receipts and reconcile unfinished Effects. A new Runtime incarnation cannot renew an old lease. An ambiguous write is never automatically reissued.
- Candidate-output framing is transient and fail-closed: absent, duplicate-conflicting, malformed, truncated, oversized or identity-mismatched frames create no Resource, grant or Effect. If the runner, frame reader, process scope or quiescence proof fails, retain the Attempt fence and discard partial in-memory bytes; restart does not replay a frame or infer a candidate from scratch files.
- Verification success requires independently generated Evidence pinned to the exact TaskSpec/plan/write subject. A worker response or process exit is not verification.

## Current implementation gaps

- Task create/spec revision are served; plan submission and Attempt admission are not served.
- The planning preflight always reports dispatch unavailable and its `require_dispatch()` always fails closed.
- Environment provider detection is not provisioning. Windows Job Object support is only process-tree evidence; Linux bubblewrap presence is not attestation. Budget enforcement is unavailable.
- IsolationAttestation and QuiescenceObservation types/checks are not wired into a production Task Attempt path. The preparation journal and held-scope adapter are CODE primitives; neither is called from Task preparation or startup recovery.
- T04 has a daemon-private launcher/capture-session CODE seam with fake-scope tests for quiescence retry, failed exchange, nonzero exit and cancellation. A nonzero exit is terminal for candidate collection: its frame is drained/discarded, and a retry on the retained error session cannot release it. A quiescence timeout before a known exit result keeps the same in-memory scope handle for retry. Separate opt-in WSL integration tests exercise the built runner as PID 1 and the production Bubblewrap command builder directly; both bypass `ManagedScope` and systemd/cgroup supervision. The current helper launches the candidate-producing harness and has no production Task Runtime caller. The held runner now performs a CODE-only same-scope filesystem observation of tmpfs type/capacity, writable aliases, root/input read-only behavior and tiny writable canaries before readiness; separate disposable-scope evidence proves `ENOSPC` without filling production-sized tmpfs. `RuntimeLocalPreparationJournal` validates bounded no-follow regular-file reads, canonical Attempt keys and Unix owner/private mode, rejects oversized/corrupt entries, and serializes phase operations across processes. The native-Windows journal filter passes 6/6; the WSL Ubuntu 24.04 filter passes 7/7, including the Unix symlink denial. Linux `O_NOFOLLOW` returns `ELOOP` for a symlink, which the journal now maps to the same typed `InvalidRecord` refusal as the Windows path. These are CODE regressions only. Neither primitive is called by Task preparation or startup recovery. Same-scope process/network probes, exact SQLite receipt lookup, attestation production, Attempt correlation, Resource persistence and startup reconciliation are not implemented. The held and capture helpers are CODE only and cannot satisfy the complete target pre-admission sequence.
- CODE update (2026-11-25): `ManagedScope`/`HeldEnvironmentScope` provide process/cgroup identity capture and recheck, and the daemon adapter persists the exact held unit/PID/start/digest into `HeldProviderScopeIdentity` and reloads/rechecks it only from the pre-admission `ScopeHeld` phase. Three fake-scope tests pass for exact persistence/recheck, wrong-phase refusal and changed live identity. The adapter has no Task Runtime caller, so it does not yet fence the admission transaction or connect journal recovery to a provider. These are CODE plumbing tests, not native systemd/cgroup qualification.
- AC-022 target recovery remains incomplete: the journal recovery classifier is not wired to exact Attempt admission receipt queries or provider scope/process reconciliation after crash. Unknown identity/quiescence must block; do not infer cleanup or success.
- Capability grants are presently limited to Task-planning Resource reads. There is no admitted write grant, Effect dispatcher/reconciler or independent write-verification pipeline connected to an Attempt.
- UI only exposes Task creation, spec editing, read-only readiness, Task/Step/progress/Artifact read views. No plan/Attempt/Environment/cancel/recover actions are live.
- Owner-directed revision 1.1 resolves A-70/A-87/A-88/A-90 for implementation: Environment roles are distinct, exact bytes are pinned by managed ResourceRevision, Attempt admission is separate from atomic mediated dispatch, and FileWriteScopeRequest is untrusted while Trust is the only durable grant issuer. Review is pending. These code gaps remain: no Task Environment session binding, no real attestation-producing provider, no Task Attempt dispatch caller, no write proposal/Effect UI, and no end-to-end recovery path.

## Platform availability

- On a platform with no qualified Environment provider (the Windows row until B-35 qualifies), planning dispatch and Attempt start return `DEPENDENCY_UNAVAILABLE` with a provider-unavailable reason and create no session, plan, Attempt or Environment. Task create and read views keep working.
- Crash between temp write and rename leaves the Effect AMBIGUOUS; restart reconciles the target digest and removes the orphaned temp file; it never rewrites automatically.

## Canonical errors

Use the error codes already owned by `docs/SCHEMAS.md` and `docs/schemas/error-codes.schema.json`, including `AGENT_UNAVAILABLE`, `STALE_TASK_VERSION`, `STALE_SPEC_REVISION`, `FORBIDDEN`, `CONFLICT`, `DEPENDENCY_UNAVAILABLE`, `STALE_FENCE` and `INTEGRITY_FAILURE` where applicable. Do not create a feature-local error vocabulary.

## Qualification gate

Exercise denial, stale versions, idempotent receipt replay, changed-payload conflict, grant expiry/revocation, provider refusal, isolation mismatch, timeout-before/after-write, AMBIGUOUS effect, cancellation, quiescence unknown/confirmed, runtime crash/restart, recovery and independent verification on the exact declared OS/provider/agent/auth route. No current end-to-end Task execution was run in this audit.
