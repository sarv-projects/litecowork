# Data model - Safe Task Path

**Feature:** 005 | **Status:** Revision 1.0 ACCEPTED/LOCKED; revision 1.1 IN_REVIEW with owner-directed implementation authorization; not a claim of implementation or qualification.

Identities and lifecycles stay in the canonical owner documents. This file lists the records this slice reads or commits. It does not authorize new tables by itself.

## Records

- Task and TaskSpecRevision.
- PlanRevision and Steps.
- AgentSession with exact Environment identity for Task scopes; Conversation sessions keep `environment_id` null.
- Task-scoped read-only planning Environment; fresh ATTEMPT_PRIVATE Environment for each execution, child and verifier Attempt.
- Attempt, ExecutionLease, Trust-issued scoped grant/use, Effect, Evidence and VerificationRun.
- The T07 Trust-issued Attempt grant uses the closed `CORE_BUILTIN` CapabilityRef `workspace.file.replace`; it is a capability record, not a package, MCP Skill, activation or native-agent tool.
- Exact B-18 candidate bytes as a managed immutable ResourceRevision, created by the Runtime's bounded post-quiescence output capture and marked with existing `Resource.provenance.created_by_attempt`; the closed `FileReplacementTarget` in `Effect.target_json` pins that exact revision. No new proposal aggregate or table is introduced.
- Before Resource creation, the candidate exists only as an ephemeral file at the fixed `/workspace/outputs/proposal` path inside the Attempt-private capped tmpfs, then as one bounded in-memory frame held by the Runtime. The inner runner waits for the native harness and its reparented descendants before reading the file; the Runtime does not expose or persist the frame until the exact process scope is observed quiescent. The frame carries no target path, digest, ResourceRef, Attempt authority or provider handle. It creates no persistent record/event and is discarded on timeout, cancellation, mismatch, restart or unknown quiescence.
- The staging library's ephemeral `PreparedEnvironment` is `PREPARED_ONLY`, not a persisted Environment or attestation. It carries the Workspace ID, sorted exact source Resource/revision/content-digest identities, private input/output roots and root/input-set digests so the daemon launch-plan mapper can reject a staged set that only matches by count. Host paths remain Runtime-private; the prepared value carries no authorization.
- Idempotency receipt.

## Relations

Workspace is the security boundary. Child records carry workspace id. Runtime-local secrets, handles and private locators are excluded from replicated events and ordinary backups.

The planner AgentSession binds to a Task-owned, read-only `TASK_SHARED` / `TASK_RETAINED` Environment scoped to its exact TaskSpec revision, Resource set, Workspace and Runtime incarnation. It is never attached to an execution Attempt. Every execution, child and verifier Attempt uses a new `ATTEMPT_PRIVATE` Environment. Before provider creation, Runtime writes an owner-only private preparation-journal intent; the provider starts a trusted idle supervisor and the Runtime observes enforcement in that same held scope. The supervisor starts no native harness, credentials, tools or user code. The owner transaction commits the public Environment identity with the session reservation and, for execution, Attempt/lease; only a resolved durable receipt permits the private one-time native-provider launch handoff. The journal is a recovery aid, not a domain aggregate, event, API, backup item or authority source. Exact receipt lookup distinguishes committed from unbound preparation after a crash; unbound cleanup requires exact provider identity and positive quiescence, with unknown evidence retaining a blocker. No cleanup uses PID or process name alone.

2026-11-25 CODE note: `linux-process-scope::ManagedScope` and `HeldEnvironmentScope` can capture and recheck the outer Linux launcher identity that is already represented by `HeldProviderScopeIdentity` (unit, PID, start ticks and process-scope digest). The digest includes boot/process identity, cgroup path and inode, executable inode, effective UID and exact observed memory/pids/cpu values. The API is not called by Task preparation, does not persist the held identity, and does not create or validate an `IsolationAttestation`; the journal remains a private recovery aid rather than an authority source.

The B-18 Effect target pins one confined WorkspaceRoot/path, base digest, exact managed ResourceRef/revision, content digest/size, accepted plan-action digest and approval binding. Bytes remain in the existing managed Resource/BlobStore lifecycle; Effect and Approval records carry only exact references and digests. Resource deletion/blob collection is blocked while an unresolved Effect or verification needs that revision. `FileWriteScopeRequest` is untrusted and contains Attempt/Step selectors, root/path/base/size and a pinned candidate ResourceRef only. Trust derives Task/plan identity from the admitted Attempt and issues the grant through a separate idempotent transaction that rechecks the active session/current incarnation/live lease, accepted Step, active root and exact locally managed candidate. A narrower positive byte bound is allowed, but may not exceed the Step maximum; the candidate size may not exceed that narrower bound, and the grant expiry may not outlive the current lease. The request digest excludes generated grant/event identifiers; exact retry returns the original receipt before mutable revalidation, while changed request payload conflicts. The grant issue commits the existing `capability.grant.created.v1` event, aggregate state, audit and receipt, and consumes no ApprovalUse. Invocation dispatch later revalidates the current Attempt/session and lease fence while atomically committing Invocation, Effect STARTED, Trust decision, ApprovalUse and receipt. Private `IsolationAttestation` values remain in an incarnation-scoped Runtime store; no attestation body or provider handle enters events, backups, public projections or requests.

## Current implementation boundary (execution cross-checked 2026-11-19; promotion cross-checked 2026-11-23)

- Task and TaskSpecRevision are the only records committed by the current Task-create flow. The Task envelope is not a persisted Plan, Step, Attempt, Environment, Grant, Effect or Evidence record.
- Explicit Conversation promotion is CODE/SERVED through `create_task`: it commits the Task's existing `conversation_id`, the initial TaskSpec's exact ordered source message IDs, `task.created.v1`, and the existing idempotency receipt in the single Task transaction. Storage revalidates the source pair and source Resource pins there. This adds no entity, migration, event type or Conversation mutation. Its UI request cache is in-memory only, and the packaged restart journey is not qualified.
- PlanRevision/Step, Attempt/ExecutionLease, CapabilityGrant, Effect and Evidence records are canonical target owner records and have storage/domain code, but the production Task admission/Execution pipeline is not connected in the daemon.
- The current planning-readiness projection is derived, read-only and not persisted as a Task lifecycle transition. It is not an approval, PlanRevision, session reservation or Attempt receipt.
- The current Task-planning Resource-read grant is scoped to exact Resource refs and `workspace.resource.read`; it is not a write grant or Environment execution authority.
- Runtime-local Environment handles, process identities, isolation evidence and quiescence proofs must remain private/runtime-local and must not be copied into ordinary replicated Task events.
- The inner runner's framed stderr channel and pending candidate bytes are Runtime-private transient state. Agent stdout retains its native protocol; agent stderr is encoded only as log frames. An untrusted child cannot write directly to the runner's parent stderr frame stream, and the kernel cgroup observation remains the final quiescence evidence.
- Current UI projections may show Task/spec/Step/Artifact/readiness records only as committed owner data; they must not infer Attempt liveness, Environment security or verified write success from those records.
- The Environment provider probe is discovery evidence only. On Windows it reports no Task-capable `LocalWorkspace` class or Task lifetime; on Linux a trusted Bubblewrap candidate is necessary for the capability observation but does not provision an Environment or produce an attestation.
- The daemon's Linux launch-plan mapper is CODE only: it verifies the ready Attempt-private Environment identity and exact prepared Resource pins, then creates an in-memory Bubblewrap request. It creates no Environment record, admission, attestation, Resource revision, Effect or durable receipt.
- A daemon-private candidate-capture session now connects that launch request to `spawn_bubblewrapped`, keeps the harness's native stdin/stdout exchange separate from the candidate stderr channel, and withholds parsed bytes until the exact scope reports recursive quiescence and reaps the launcher. Three fake-scope CODE tests exercise timeout retry on the same scope, failed exchange/nonzero exit, and cancellation. No production Task Runtime caller starts it; no Resource or attestation is produced.
- A Runtime-private `RuntimeLocalPreparationJournal` code primitive stores durable intent, held-scope identity, admission-receipt and one-shot-handoff phases across Runtime incarnations. Reads are capped at 16 KiB, use no-follow regular-file opens, validate Unix owner/private mode and canonical Attempt-key filenames, and fail closed on malformed entries; one exclusive lock serializes reads and phase transitions across processes. Native-Windows tests pass 6/6 for persistence/reopen, exact transition and receipt checks, unknown-lookup blocking, canonical-key and oversized-entry refusal, and cross-process lock blocking. A Unix-only symlink denial test is present but was not run in this Windows session. It is not called by provider preparation or startup recovery.
- Two opt-in direct Bubblewrap tests pass on WSL Ubuntu 24.04: the trusted runner/PID-1 frame-isolation test and a production-builder 1 MiB `/workspace` tmpfs test that shares quota with the in-sandbox `/tmp` symlink and observes `ENOSPC`. They bypass `ManagedScope` and systemd/cgroup; the fixed-cap probe does not demonstrate EnvironmentConfig-to-provider mapping or create an attestation.
- The 2026-11-25 held-runner probe checks the exact live tmpfs capacity with `fstatfs`, checks writable aliases share its device, tests root/staged-input create denial with `EROFS`, and uses only small removable canaries. The requested storage maximum is rounded down to a kernel page so the actual mount cannot exceed it. Full-cap `ENOSPC` is deliberately tested only in a separate small disposable scope to avoid consuming a production Attempt's memory budget. This is CODE in WSL, not managed-provider attestation or qualification.
- `IsolationAttestation` is Runtime-local private evidence and cannot be accepted from a UI, Operator, Agent, or provider request.
- Owner-directed revision 1.1 resolves A-70/A-87/A-88/A-90 for implementation; review remains pending. Source has not yet been updated to bind Task AgentSessions to an Environment, persist the typed Effect target, or connect Task Attempt admission to mediated file dispatch.
