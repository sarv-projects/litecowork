## Contract and behavior

The desktop owner may begin editing Workspace instructions before any instruction revision
exists. The first immutable revision therefore has an empty `parent_revisions` array; later
ordinary edits name the current revision, and an explicit merge may name multiple existing
parents. This follows [F87/F88](../../docs/FLOWS.md), the durable instruction boundary in
[CONTEXT](../../docs/CONTEXT.md), and the `CreateWorkspaceInstructionRevisionRequest`
schema in [operator-api.openapi.yaml](../../docs/schemas/operator-api.openapi.yaml).
Workspace ownership, ACTIVE status, expected version, Resource scope/revision/digest,
UTF-8/media/size checks, and parent existence remain enforced by the Operator and storage
transaction. The Tauri bridge only validates bounded request shape before forwarding the
authenticated command.

A new instruction revision must pin the Resource's current head at commit. SQLite checks
the persisted head inside the immediate write transaction, closing the interval between
the Operator's content read and the commit. The check runs after durable request-receipt
lookup, so an exact retry still returns its original result after Workspace or Resource
advancement. Existing instruction revisions keep their immutable historical Resource pin.

Before this change, Settings sent an empty parent list for the initial save, but the Tauri
bridge rejected it locally. The bridge now permits the empty list and continues to reject
zero-valued parent IDs and more than 256 parent IDs. The adjacent Workspace policy
allowlist also accepted `ACTIVE_TASKS` even though the API defines `ACTIVE_TASK_INPUTS`;
it now accepts the API spelling and keeps `SELECTED_FOLDERS` unavailable until the desktop
has validated WorkspaceRoots. No storage, event, migration, Trust, Effect, Secret, or
Resource authorization behavior changed.

## Workspace archive fail-closed slice (2026-10-11)

The desktop Settings surface now offers a two-step archive confirmation and presents an
archived Workspace as read-only. Its Tauri command calls the authenticated local Operator
route with `If-Match` and an idempotency key. Exact retry identity is retained for an
ambiguous response at the same Workspace version. Typed `WORKSPACE_NOT_QUIESCENT` errors

`POST /v1/workspaces/{id}/archive` checks selected Workspace/path identity, owner scope,
`If-Match`, and a bounded idempotency key. WorkspaceService validates that the canonical
request payload describes the command. SQLite rechecks the owner, exact archive event and

live persistent Environments, active WorkspaceRoots, ACTIVE/DRAINING channel hosts,

have no durable stop-acknowledgement path, so the gate is intentionally fail-closed. The
archive operation does not stop or destroy provider state, roots, Environments, or files.

Real-SQLite regressions prove atomic terminal archive and exact replay, reject nonterminal

## WorkspaceRoot overlap and SQLite rollback slice (2026-10-12)

The WorkspaceRoot contract now defines overlap within one Workspace: canonical absolute
directory paths conflict when equal or when one is a component-wise ancestor of the other.
`ACTIVE`, `PAUSED`, and `UNAVAILABLE` roots reserve their scopes; only `REVOKED` releases
one. Siblings remain independent even when their path strings share a prefix. The contract
keeps the absolute path in the private Runtime-local locator only.

SQLite decodes and validates the candidate locator and every persisted non-revoked folder
locator under the existing `BEGIN IMMEDIATE` root-create transaction. The check runs after
exact RequestId receipt replay and before any SQL projection writes. It rejects unsupported,
oversized, NUL-containing, relative, parent-traversal, and noncanonical locators with safe
integrity errors; a scope conflict returns a generic version conflict. The existing keyed
directory identity duplicate check remains in place. No schema migration was required.

Fourteen real-SQLite regressions pass. They cover both parent/child insertion orders, a real
temporary directory tree, a sibling whose spelling shares the parent's prefix, PAUSED and
UNAVAILABLE scope retention, scope release after terminal revocation, identical paths
accepted in separate Workspaces, malformed and oversized persisted locators, noncanonical
candidate paths, concurrent parent/child creates through two independent SQLite writers,
exact duplicate-identity replay, and no partial SQL writes on overlap. Trigger-injected
SQLite aborts at Resource, location, private-locator binding, file-identity binding,
WorkspaceRoot, each of the three domain events, and RequestDedup leave no root projection,
event, or receipt rows.

The store writes encrypted Resource and WorkspaceRoot aggregate-state blobs before entering
the SQL transaction. A later SQL conflict/abort can therefore leave unreferenced immutable
