## What was implemented

### Explicit local/cloud placement (Core-owned rule, UI-decoded)

`crates/domain-rag/src/placement.rs` owns the placement decision:

| Workspace policy | Remote location | Explicit local-only | Result |
|---|---|---|---|
| any | any | yes | `LOCAL_ONLY` |
| `LOCAL_ONLY` | any | no | `LOCAL_ONLY` |
| `METADATA_ONLY` | any | no | `LOCAL_ONLY` |
| `ACTIVE_TASK_INPUTS` / `SELECTED_FOLDERS` | yes | no | `CLOUD_ELIGIBLE` |
| `ACTIVE_TASK_INPUTS` / `SELECTED_FOLDERS` | no | no | `LOCAL_ONLY` |

`evaluate_task_placement` refuses a cloud consumer for a `LOCAL_ONLY` Resource with the
typed blocker `RESOURCE_LOCAL_ONLY`. The UI never infers placement; it decodes the
Core decision.

### Index state that keeps "uploaded" apart from "searchable"

`GET /v1/resources/{resource_id}/index-state` returns `READY`, `STALE`, `ABSENT`, or
`NOT_INDEXABLE` with a typed reason. The desktop decoder refuses a `READY` state that
does not name its revision, and `indexStateIsSearchable` is true only for `READY`.

### Truthful degradation when no qualified provider exists

The served retrieval provider is the deterministic local lexical index. Its status
reports `retrievalMode: LEXICAL_ONLY` and `placement: LOCAL`. When no qualified
provider can serve a request, the route answers with an explicit
`PROVIDER_UNAVAILABLE` status and a reason code; it never falls back to a cloud
provider and never returns an unreferenced answer. The local model inventory reports
`NOT_CONFIGURED` with the Agent-scoped surface.

### New desktop modules

| File | Contents |
|---|---|
| `apps/litecowork-ui/src/resources/retrieval-grounding.ts` | Grounded retrieval decoder, citation pin, poisoned-content flag, answer view state |
| `apps/litecowork-ui/src/resources/knowledge-index-state.ts` | Index state decoder, searchable check, owner-visible labels |
| `apps/litecowork-ui/src/resources/knowledge-placement.ts` | Placement decoder, cloud blocker, owner-visible labels |
| `apps/litecowork-ui/src/resources/local-model-inventory.ts` | Local model inventory decoder, AgentModule compatibility check |

The decoder rules are the truthfulness boundary: a grounded answer without a
revision-bound citation is refused, a citation without a valid digest or a valid UTF-8
byte span is refused, insufficient evidence without a typed reason is refused, and a
result for another Workspace or another request is refused.
