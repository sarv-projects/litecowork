## Source slice

`CoworkerSettings` now fences roster, detail refresh, primary-selection, revision, and
status responses to the Workspace request epoch that admitted them. A response from a
previous Workspace cannot overwrite the newly selected Workspace view. Paginated roster
append validates that every item belongs to the selected Workspace, de-duplicates stable
Coworker IDs, and rejects a cursor that does not advance. Quick Create starts with no
implicit purpose and requires both a name and a short plain-language purpose. Edit/status
semantics are unchanged; this slice creates, selects, or starts no Conversation.

The implementation is in `apps/litecowork-ui/src/coworkers/CoworkerSettings.tsx` and
`apps/litecowork-ui/src/coworkers/coworker-roster-request-epoch.ts`. Focused pure tests are
in `apps/litecowork-ui/tests/coworker-roster-request-epoch.test.ts`.

## Chat-first contract verification and Quick Create keyboard contract — 2026-10-20

### Contract verification against `docs/COWORKERS-TARGET.md` and `docs/COWORKER-FLOWS.md`

The target requires that Coworkers are optional, that an ordinary Workspace conversation
works with zero Coworkers, that selecting a Coworker opens its most recently active
same-Workspace Conversation, and that Quick Create needs only a name and purpose
(COWORKERS-TARGET §0.1, §0.2, §1; CF01/CF02 in `docs/COWORKER-FLOWS.md`).

What the current source already honors:

- The Home onboarding card states "Coworkers are optional" and "A primary Coworker only
  prefills future Task settings. It is not required for ordinary conversations and never
  starts an agent by itself." A Task can be saved with an explicit Workspace-default
  choice and no Coworker; a stale, archived or unavailable selection is refused with the
  draft preserved and never silently falls back to another Coworker.
- Quick Create requires only a name and a short purpose
  (`validateQuickCoworkerIdentity`). Every other stage — chief agent, worker profiles,
  interaction defaults, context policy — is an optional collapsed disclosure, and no
  connection, monitor, or trigger is created.
- Creating and making primary are separate owner actions, and an unchanged retry keeps
  its original RequestId.

What is **not** implemented, and this is the honest gap:

- There is no Coworker-owned Conversation. `owner_coworker_id` and `last_activity_at` do
  not exist anywhere in the Rust source, so "selecting a Coworker opens its most recently
  active Conversation" cannot be true yet, and there is no last-active pointer that could
  go stale.
- There is no native Conversation turn admission, so the ordinary-chat path cannot be
  exercised as a real conversation.

### Quick Create keyboard contract

`implementation/UI.md` requires "+ Create Coworker → Open Quick Create with focus on name,
role hint and optional Customize" and "Escape/cancel restores previous focus". This slice
implements that with the pure rules in
`apps/litecowork-ui/src/coworkers/coworker-focus-plan.ts`:

- Quick Create and Edit move keyboard focus to the name field.
- Cancelling returns focus to the control that opened the editor (the roster row of the
  edited Coworker, or the "+ New Coworker" action).
- A successful save moves focus to the Coworker heading because the form is removed.
- Escape closes the editor only when the draft is unchanged; a dirty draft keeps its
  values and reports how to discard them explicitly.
- The archive confirmation takes focus, and Escape or "Keep Coworker" returns focus to
  the Archive action.

### Blockers for E08-S01

1. **Coworker-owned Conversation and last-active projection.** These need a
   `Conversation` ownership column and a server-derived `last_activity_at`, i.e. changes
   to `crates/storage-core/src/conversation.rs` and
   `crates/storage-sqlite/src/conversations.rs`, plus a migration, plus a
   `CoworkerConversationService` route in `apps/litecoworkd/src/conversation_operator.rs`.
   All four are outside this agent's write surface and the migration is lead-owned, so
   this was not attempted. The needed DDL is reported to the lead.
2. **Native Conversation turn admission** stays open; nothing here changes that.
3. **Owner USER acceptance** (create Research Assistant with name and purpose, create two
   chats, restart, and confirm the authoritative most-recent chat reopens) cannot run
   before items 1 and 2 exist.

### Required DDL for the lead (not applied here)

```text
ALTER TABLE conversations ADD COLUMN owner_coworker_id TEXT;   -- immutable at creation, NULL for ordinary sessions
ALTER TABLE conversations ADD COLUMN last_activity_at TEXT;     -- server-derived, not client clock
CREATE INDEX conversations_owner_activity ON conversations(workspace_id, owner_coworker_id, last_activity_at DESC);
```

The `owner_coworker_id` must be same-Workspace and immutable after creation, and
`last_activity_at` must be derived by the server from committed activity rather than
supplied by the client.

## Same-Workspace Coworker switching and receipt identity fences — 2026-10-17

Coworker detail and presence reads now bind both the selected Workspace and selected
Coworker identity, including a per-detail generation for same-identity refresh races.
Late responses cannot replace another Coworker's settings, presence, or loading/error state.
Revision/status responses validate their returned Coworker identity before updating the
view; a confirmed but stale selection response clears only its exact request retry key.
Workspace-primary receipts validate their Workspace identity before updating the local
projection. Switching roster selection clears only Coworker-specific busy state, while an
in-flight Workspace-primary action remains serialized.
