## Acceptance facts proved by code

- **Secrets omitted.** A captured observation that lands in a sensitive region is
  persisted with `without_sensitive_fields()`: the observed value and the pointer hint
  are dropped and only the semantic kind and target survive. The derived draft body is
  scanned, and a body that still carries forbidden content makes the redaction status
  `FAILED`; `complete_demonstration` then refuses with `REDACTION_FAILED` and stores
  nothing.
- **Raw coordinates are not the sole authority.** The draft is reconstructed from the
  semantic steps. `derive_skill_proposal_draft` replaces an observed path, URL, or
  identifier with a typed `SkillPlaceholder` and never carries the original value.
  `without_sensitive_fields` removes the coordinate hint entirely.
- **Caps stop recording.** `evaluate_capture_append` refuses an append once the action
  count, the trace-byte budget, or the elapsed duration exceeds the immutable policy.
  The refusal is durable: the session keeps its counters and the observation is not
  appended.
- **A draft cannot enable itself.** `evaluate_skill_proposal_review` returns
  `activated_skill_id: None` on every path, and the storage `review_skill_proposal`
  writes only the status, the reviewer, and the audit record. A service, runtime, or
  agent principal is refused (`ReviewerNotHuman`); a reviewer who is not the Workspace
  owner is refused (`ReviewerNotOwner`); a proposal whose redaction did not pass, or
  that drifted, is refused. Approval records the decision only.

## Negative cases

| Negative case | Where it is refused | Evidence |
|---|---|---|
| 2FA / private screen (sensitive region) | `evaluate_capture_append` → `SensitiveRegionPaused` or `RecordedWithSensitiveFieldsOmitted` | `storage-core` tests `a_capture_pauses_on_a_detected_sensitive_region`, `a_capture_that_omits_sensitive_fields_keeps_recording_without_the_value` |
| Timeout bound | `evaluate_capture_append` → `CaptureDurationExceeded` | `storage-core` test `the_duration_cap_stops_recording` |
| Trace bound | `evaluate_capture_append` → `CaptureCapReached` | `storage-core` test `the_trace_byte_cap_stops_recording` |
| Action cap | `evaluate_capture_append` → `CaptureCapReached` | `storage-core` test `the_action_cap_stops_recording` |
| Replay drift | `detect_skill_drift` and `evaluate_skill_proposal_review` → `DriftDetected` with blocker `SKILL_DRIFT_DETECTED` | `storage-core` test `a_drifted_proposal_cannot_be_approved_without_review` |
| Missing publish contract | `evaluate_skill_proposal_review` sets `publication_blocker = LITESPOM_PACKAGE_SERVICE_NOT_QUALIFIED` | `storage-core` test `an_owner_approval_never_activates_or_publishes_a_skill`; `discover_operator` `connect-or-install` |
| Secret in the captured body | `derive_skill_proposal_draft` → redaction `FAILED` | `storage-core` test `a_capture_draft_whose_body_carries_a_secret_fails_redaction` |
| Observation from another Environment | `append_demonstration_action` → `ENVIRONMENT_MISMATCH` before the transaction; `evaluate_capture_append` → `CaptureEnvironmentMismatch` | `storage-core` test `an_observation_from_another_environment_is_refused` |
| Unapproved proposal | `evaluate_skill_proposal_review` refuses every non-`REVIEW` status | `storage-core` tests `a_draft_proposal_cannot_be_approved_before_review`, `an_approved_proposal_is_closed_for_further_review`, `a_rejected_proposal_is_terminal` |
| A service approving a learned skill | `evaluate_skill_proposal_review` → `ReviewerNotHuman` | `storage-core` test `a_service_may_never_approve_a_learned_skill` |
| Duplicate skill identity | `put_skill` rejects a second Skill claiming the same capability identity | `storage-sqlite` test `a_duplicate_skill_identity_is_rejected` |
| Foreign Workspace | `authorize_owner` in every capture and proposal transaction | `storage-sqlite` tests `a_foreign_workspace_never_reads_or_writes_a_skill`, `a_skill_proposal_only_accepts_same_workspace_references` |
| Stale revision | `review_skill_proposal` and `put_skill` version checks | `storage-sqlite` test `a_stale_skill_revision_is_rejected` |

## Known limitations and pending gates

- **Publication through LiteSPM is blocked.** LEARNING.md section 9 item 7 requires
  "LiteSPM owns the package lifecycle from that point onward", but
  `docs/CAPABILITY-FABRIC.md` does not publish the LiteSPM package API,
  authentication, manifest, or package model. An approval therefore reports
  `publication_blocker = LITESPOM_PACKAGE_SERVICE_NOT_QUALIFIED` and nothing is
  published. **The document line that must be published** is the LiteSPM package
  contract section of `docs/CAPABILITY-FABRIC.md` (the paragraph beginning "This
  architecture records the service selection and system boundary only.").
- **The isolated skill test fixture is not implemented.** LEARNING.md section 9 item 4
  requires "an isolated test fixture passes" before a proposal may be reviewed, and
  section 22 item 8 requires "SkillProposal redacts Task-specific paths/secrets and
  requires isolated tests". `docs/LEARNING.md` section 23 lists
  `crates/ports/skill_test_runner.rs` as an **uncreated, illustrative target path** (not a current crate, port or shipped runner) and no skill test runner
  contract is published. This slice implements the redaction and the owner-review gate
  but does not claim an isolated skill test fixture. The USER "review/test draft" step
  is therefore pending on that contract.
- **The qualified capture producer is the Environment computer-use provider.** The
  capture append path is the Environment-bound observation route plus the in-process
  `append_captured_action` provider seam. The Runtime's browser/computer-use provider
  is owned by E07 and is not wired in this slice, so the SYSTEM acceptance
  "teach sandbox browser task" is pending on that provider. The route's guards — owner
  authentication, Workspace scope, the Environment binding, and the caps — are
  implemented and tested independently of the provider.
- **USER acceptance is pending.** It needs the owner, a qualified browser App host, and
  a qualified LiteSPM package service.

## Rollback

The demonstration and SkillProposal routes are additive and stored in the shared
projection. Removing the route registrations reverts the served surface without a
schema change; the OpenAPI additions revert with the same commit. No rollback
migration is required.

## Telemetry

The capture and review paths emit audit records
(`DEMONSTRATION_STARTED`, `DEMONSTRATION_TRANSITIONED`,
`DEMONSTRATION_PAUSED_ON_SENSITIVE_REGION`, `DEMONSTRATION_CONVERTED`,
`SKILL_PROPOSAL_CREATED`, `SKILL_PROPOSAL_REVIEWED`) carrying only IDs, reason codes,
and counters. Event payloads carry IDs, digests, reason codes, and counters, never
the captured procedure body, never an observed value, and never a credential.
