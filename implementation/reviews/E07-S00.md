# E07-S00 partial CODE/SYSTEM review packet — Task-scoped local Environment isolation

**Status:** Partial CODE and lower-level Linux SYSTEM evidence only. E07-S00 remains
`IN_PROGRESS`; no production EnvironmentProvider is integrated and native Task dispatch
must remain disabled.

## Outcome and changed modules

The `local-environment-staging` crate validates exact Workspace/Resource/revision/digest
pins, size/count/path bounds, traversal and case-fold collisions, and creates a Unix
preview root with read-only inputs and separate writable outputs. A Task input adapter
resolves exact historical Resource revisions through `ResourceStore` and returns
`PreparedOnly`. It does not create an Environment record, reauthorize the owner through an
Operator flow, bind a provider to a Runtime incarnation, enforce process/filesystem/network
restrictions, or admit an Attempt/session/lease.

Separate `linux-process-scope` code uses Bubblewrap namespaces and systemd/cgroup process
scope primitives. It requires positive quiescence before writer release. This lower-level
primitive is not yet the complete E07-S00 provider.

## Runtime-local isolation evidence, output accounting, and provider probing — 2026-10-20

This slice adds the three contract pieces that the previous checkpoint said were missing
before an Environment could ever be admitted. It does **not** open the Task planning
isolation gate, and it does not create an Environment, Attempt, AgentSession, or lease.

### Isolation attestation and quiescence observation

`apps/litecoworkd/src/environment_isolation.rs` implements the exact
`IsolationAttestation` and `QuiescenceObservation` shapes from
[ENVIRONMENTS](../../docs/ENVIRONMENTS.md#local-task-execution-isolation), plus the
Runtime-local private store that may hold them.

* `build_attestation` binds an observation to the Environment, Workspace, Task, Runtime,
  Runtime incarnation, provider identity, OS build, the normalized policy digest, and
  the pinned-input/readable-root/writable-root digests. It carries no host filesystem
  path: the digests are the only root reference.
* `evaluate_isolation_admission` fails closed on every mismatch: missing attestation,
  environment/workspace/task/runtime/incarnation mismatch, policy/input/root-set digest
  mismatch, any enforcement dimension that is not `ENFORCED`, an expired attestation,
  and an observation dated in the future. `NOT_ENFORCED` and `UNKNOWN` are both
  refusals; neither is coerced into success.
* `evaluate_quiescence` releases a writer fence only for a positive `QUIESCENT`
  observation bound to the current Environment, Runtime incarnation, and exact private
  execution identity and process scope. `UNKNOWN` never releases a writer.
* `RuntimeLocalIsolationStore` keeps the evidence in a private, incarnation-scoped
  directory (owner-only permissions, real-directory check, unsafe identifiers
  rejected). A new Runtime incarnation gets a new directory, so a previous
  incarnation's evidence is not visible after a restart. Writes are compare-and-swap:
  older evidence never replaces newer evidence. The store is Runtime-local private
  state; it is not an event source, an aggregate snapshot, a backup, or an Operator
  projection.
* `probe_local_provider` and `facts_from_probe` make the fail-closed path explicit: a
  provider *probe* yields `EnforcementStatus::Unknown` for every dimension, so an
  attestation built from probe data is refused at admission. There is a regression test
  for exactly that.

### Bounded output accounting and honest file-root modes

`crates/local-environment-staging` gains an output budget
(`output_budget.rs`) and canonical digests (`isolation_digest.rs`).

* `measure_output_root` observes the bytes and entries in the staged writable-output
  root. It refuses a symlink (`OutputRootSymlink`) and a non-regular file
  (`OutputRootUnsupportedFile`) instead of following or skipping it, and it is bounded
  by `OutputScanLimits` (`OutputScanLimitExceeded`). `assert_output_quota` fails closed
  with `OutputQuotaExceeded` on the byte or file-count ceiling. This is an
  *observation*, not enforcement: a hostile same-user process can write between two
  observations, and aggregate output limits still need a qualified provider.
* `probe_root_mode_support` reports `FileRootMode::ReadWriteNoDelete` as
  `NotEnforced` on POSIX and Windows, because deletion permission is a property of the
  parent directory: a root that permits creating entries also permits removing them.
  LiteCowork has not qualified an ACL-bearing provider that could separate the two, so
  the mode is reported as a gap instead of being simulated with a weaker mode. Read-only
  and read/write are reported as `Enforced` on the qualified platforms.
* `PreparedEnvironment` now publishes `input_set_digest`, `readable_root_set_digest`,
  and `writable_root_set_digest`, and `digest_pinned_inputs`, `digest_root_set`, and
  `digest_of_canonical_json` are canonical, order-independent, and path-free.

### Linux provider probe

`crates/linux-process-scope/src/provider_probe.rs` adds the `probe` surface that
[ENVIRONMENTS](../../docs/ENVIRONMENTS.md#provider-result-and-isolation-rules)
requires: explicit feature flags and limits for the host mechanisms, with a stated
reason for every unmet requirement (trusted Bubblewrap binary, cgroup v2, systemd
system manager, unprivileged user namespaces). `host_mechanisms_present()` says
whether the host *exposes* the mechanisms; it never claims enforcement. The
Bubblewrap trust check now has one canonical implementation shared by the probe and
the launch path.
