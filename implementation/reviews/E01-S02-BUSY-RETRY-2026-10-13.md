## Contract and behavior exercised

The test uses the real on-disk SQLite adapter, bounded writer, `WorkspaceService`, and
idempotent replication-policy command. It holds an external SQLite writer lock with a
second connection (`BEGIN IMMEDIATE`), submits a version-1 policy command, and verifies the
adapter returns `StoreError::Busy`. After the rejection, it checks that the Workspace
projection still equals the original version, the event stream still has only its creation
event at origin sequence 1, projection replay returns the original state, and no
`request_dedup` receipt exists for the rejected request.

After releasing the lock, it retries the exact same principal, request ID, payload, and
command. The update commits at Workspace version 2 and origin sequence 2. Repeating the
same idempotent request returns the stored response without another event. The test checks
projection replay and verifies the persisted response digest against the response bytes.

This closes a CODE coverage gap for retrying an idempotent Workspace policy command after
SQLite's bounded busy timeout. It does not change or independently qualify production
storage behavior.
