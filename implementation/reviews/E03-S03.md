## Outcome and touched modules

The current source contains TaskSpec revision and initial plan service/storage paths,
PlanRevision/Step persistence and reads, Task detail projections, and a closed
`PinnedResourceRef` validator. The storage adapter rejects planner-session reservation and
activation with internal `TASK_PLANNING_ISOLATION_UNAVAILABLE` before session/event/
receipt writes or Task transition. This guard preserves the isolation boundary; it does
not produce an isolation attestation. The plan transaction validates DAG shape and
producer/session bindings and is intended to commit the PlanRevision, Steps, Task pointer,
events, snapshots, and idempotency receipt atomically, but its complete source path is
recorded as unbuilt/untested in the current epic.

Relevant code spans `crates/domain-task`, `crates/storage-core`, `crates/storage-sqlite`,
`apps/litecoworkd/src/operator.rs`, and Task composer/detail UI. The machine POST plan
route does not have authenticated producer-scoped session context; a caller-supplied
AgentSession ID is not authority. No native tool invokes `submit_initial_plan`.
