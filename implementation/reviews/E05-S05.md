## Implemented source

`crates/domain-task/src/delegation_benchmark.rs` provides strict JSON records for sanitized
B83 run measurements and aggregate reports. Inputs bind each sample to a case, task digest,
acceptance-oracle digest, arm configuration digest, provider/adapter/runtime/OS versions,
provider qualification reference, and runner-supplied evidence references. Unknown fields are
rejected; transcript, prompt, credential, and provider-private fields are not part of the
record. The bounded aggregator requires a common case/task/oracle for each paired sample,
rejects duplicate samples and arm/configuration ambiguity, and reports measured medians,
verification coverage and verified-success rate, handoff overhead, retries/recovery,
human rescue, usage, and cost. Missing observations and incomparable currencies remain
unknown. It produces paired latency and cost deltas without a speedup multiplier and always
sets `automatic_selection_qualified` to false.

This is an evidence ingestion and aggregation seam only. It does not run Codex, Claude,
OpenCode, Cline, a deterministic capability, or parallel workers; it does not capture
measurements from a live Task; it does not provide the fixed B83 task/oracle corpus; and it
does not persist or publish a benchmark packet. Synthetic unit fixtures verify arithmetic
and rejection behavior only.

## Source increment (2026-10-20): released-threshold benefit decision

`domain-task::decide_delegation_benefit` now consumes an aggregated
`B83BenchmarkReport` and a caller-supplied released `DelegationBenefitPolicy`. It returns
`STAY_WITH_CURRENT_OPTION` for an invalid policy, a missing lead-only comparison,
insufficient paired samples, insufficient verification coverage on either arm, a candidate
verified-success rate below the policy floor or below the lead-only rate, missing or
incomparable cost, or an improvement below the policy threshold. It returns `Delegate` only
with the measured improvement in basis points, the exact paired sample count and the
released policy version; it never returns or substitutes a profile, never overrides
`REQUIRE`, and never claims a speedup multiplier. Cost and latency objectives are evaluated
separately. Estimated cost cannot satisfy an exact-confidence policy. The aggregation's
`automatic_selection_qualified` flag is not used as authority; the thresholds come from the
released policy, not from one report.
