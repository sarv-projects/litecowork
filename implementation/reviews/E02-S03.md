### 1. Observed-file paging is bounded and fail-closed (UI)

The mounted `WorkspaceRootObservations` component appended every response and accepted any
`next_cursor`. A non-advancing or empty cursor powered an unbounded "Load more" loop, and a
repeated page produced duplicate React list keys. The wire decoder was also permissive: it
accepted any Resource ID, unparsable timestamps, duplicate identities, and unknown fields.

A new `src/workspaces/workspace-root-observations.ts` module now owns a closed decoder and
merge path, and the component consumes it:

- exact page keys, the selected Workspace and root, and a closed item shape;
- canonical `sha256:` + 64 lowercase hex observation identity and the producer's
  `res_file_` + 64 lowercase hex Resource ID (legacy `null` stays readable);
- bounded non-empty display name (1–1024 UTF-8 bytes, no NUL), safe-integer size, parsable
  `observed_at`/`modified_at`, and a closed freshness enum;
- no duplicate observation identity inside a page;
- `next_cursor` must be `null`, non-empty, at most 4096 UTF-8 bytes, and must differ from
  the cursor that produced the page;
- a page that advertises a continuation cursor must carry at least one row;
- a continuation appends unseen identities only, while a first page replaces the list, so a
  late or stale page cannot rewrite an already-rendered row;
- the submitted file-name query is trimmed, NUL-free and bounded to 256 UTF-8 bytes before
  any native request is sent; an over-bound query fails closed with a visible message.

**Correction made during verification.** The first cut also rejected a *continuation page
with no rows and no cursor*. That is a legitimate Operator answer, not a malformed page:
the last observed file can be renamed or removed between two pages, and the keyset read
then matches no further row, so the Operator reports an empty page and no cursor. The
decoder now accepts that end-of-list page and still rejects a cursor that is advertised
without any row.

The rendered fixture was also repaired. `tests/workspace-root-observations-rendered.test.mjs`
still supplied `resource_id: "resource-file-a"`, which the daemon never produces; the
producer commits `res_file_` plus 64 lowercase hexadecimal characters, and the tightened
decoder correctly refused the placeholder. The fixture now supplies the canonical shape, so
the rendered check exercises the same identity rule as the production bridge.

### 2. Folder-scan and Resource-dependents responses are always `no-store`

`POST /v1/workspace-roots/{id}/scan` and `GET /v1/workspace-roots/{id}/observations` set
`Cache-Control: no-store` only on their success path, and `GET
/v1/resources/{id}/dependents` had the same shape (the Resource archive-preview route was
already fully wrapped). Rejected reads therefore returned without the private-read policy:
invalid arguments, stale root version / admission failures, and non-owner denial.

Each router now applies a `no-store` middleware over every response the route itself
produces, including rejections:

- `workspace_root_scan_operator::routes()` → `root_scan_no_store`;
- `resource_dependencies_operator::routes()` → `dependents_no_store`;
- `needs_you_operator::routes()` (E02-S04) → `needs_you_no_store` (recorded in the S04
  packet).

The daemon-wide authentication middleware still runs outside every route, so an
unauthenticated peer is answered with a generic `401` carrying no Workspace content before
the route middleware runs. Every response produced after authentication — an authorized
page, an invalid filter, a malformed cursor, a stale root version, a non-owner denial,
and an unavailable-store error — carries the header.

Focused daemon evidence (`cargo test --locked --offline --jobs 2 -p litecoworkd --

`1.98.1` on Linux WSL2 x86_64): **26/26 passed** (377 filtered out). The new assertions

[operator-api.openapi.yaml](../../docs/schemas/operator-api.openapi.yaml). A fresh request
reopens the saved directory without following symlinks, compares its live raw and keyed

open through the atomic SQLite commit. The commit refreshes current-incarnation bindings,

directory after startup revalidation fails closed, removes that incarnation's invalid
binding pair, and records location UNAVAILABLE while preserving PAUSED intent. Restoring
the authorized folder is insufficient until another Runtime revalidation restores
availability; Resume then remains a separate owner action. Stale versions reject without
creating a receipt. Storage failure at receipt insertion rolls back root/location and
binding-observation projections, events (including their aggregate snapshot references),
