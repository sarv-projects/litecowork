OpenIntelligentUI is the UX/test reference at reviewed commit
[`f6e4388b26a64b9a0714943b08a1ce622b924eec`](https://github.com/CopilotKit/OpenIntelligentUI/tree/f6e4388b26a64b9a0714943b08a1ce622b924eec);
its root license at that revision is MIT. Study its prose/native/interactive selection,
streamed preview-to-final lifecycle, locally scoped controls, explicit follow-up, resize
validation, and bridge-failure tests. Its renderer executes generated HTML/CSS/JavaScript
in a Websandbox iframe, with CSP allowances including `unsafe-inline`, `unsafe-eval`, and
selected CDN script origins. That execution model and CSP are rejected as LiteCowork's
RichPresentation boundary. Do not import its runtime or code; LiteCowork requires closed,
bounded typed blocks and deterministic rendering with no arbitrary executable content or
model-owned host actions.

Speed comparison is not measured. Current hypothesis only: OpenIntelligentUI is likely
faster for a standalone generated-UI prototype; LiteCowork's native bounded renderer is
likely faster to ship inside this existing Tauri/React + `litecoworkd` product. Runtime
CPU, memory, latency, frame behavior and transfer cost are unknown. A matched comparison
must run the same prose, simple-card and richer interactive scenarios on the same device,
OS and WebView; hold content/provider/request/network/cache constant; separate model latency
from render time; measure first semantic text, first useful visual, completion, CPU, peak
memory, dropped frames, bytes/CDN requests, and cold/warm small/large output behavior.
Offline and renderer/bridge/reconnect failures are required. If the reference cannot run in
equivalent local conditions, record that limit and do not rank speed.
