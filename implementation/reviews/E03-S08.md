# E03-S08 partial CODE evidence — AgentControlDescriptor validation

**Status:** Partial CODE only. Descriptor parsing and structural/integrity validation
are implemented in the E03-owned agent module. No concrete AgentModule currently produces
this descriptor, so descriptor refresh/configuration routes remain unavailable and no
binding configuration is enabled by this slice.

## Implemented

[`control_descriptor.rs`](../../apps/litecoworkd/src/agents/control_descriptor.rs)
defines closed, typed projections for installation, authentication and credential slots,
non-secret configuration, session options, native input/surface metadata, and negotiated
capabilities. Parsing rejects payloads over 256 KiB before JSON decoding; validation
checks bounded collections/text/schema objects, unique IDs, exact registry/module identity,
SemVer module versions, RFC3339 observation windows, credential-slot ownership and
references, secret-shaped configuration field IDs, and a canonical SHA-256 digest over the
normalized descriptor without its digest field. Freshness is exposed separately and
requires both descriptor and nested installation observation windows to contain the
caller-provided current time.

The model does not infer native authentication, installation, provider entitlement, session
readiness, adapter support, or runtime qualification. It carries no credential bytes.
`AgentControlDescriptor` is not wired to a handler or a concrete provider; the existing
write-only SecretStore helper therefore has no trusted descriptor producer to call it.

## CODE evidence

Focused tests cover canonical wire keys/enum values, module SemVer, valid digest and
cross-reference checks, stale/tampered/unknown/oversized input, bounded parsing, freshness,
separator-obfuscated credential field names, and inline JSON Schema safety. Session option
and command schemas reject remote/file references and oversized content; inline fragment
references remain accepted, while `$id` is rejected so it cannot change the base of an
otherwise local reference. On Rust 1.98.1, Linux x86_64:


## CODE addendum — UI validation of native session option descriptors — 2026-10-18

The desktop descriptor parser now validates each session option's bounded identity,
semantic hint, and mutation scope; rejects duplicate option IDs; and rejects schemas larger
than 16 KiB, schemas deeper than 32 levels, excessive arrays/object members, `$id`, and
non-fragment `$ref`/`$dynamicRef`/`$recursiveRef`. This mirrors the daemon's existing
inline-schema boundary and avoids casting malformed provider-derived JSON into the
composer's generated descriptor type.

Test-first evidence: the new descriptor-panel test failed because an external `$ref`, a
base-changing `$id`, and an unknown option mutation scope were accepted. After the parser
change, on Linux WSL2 x86_64 with Node `24.21.0`:

```sh
  corepack pnpm@12.10.1 exec node --experimental-transform-types --test \
  tests/agent-control-descriptor-panel.test.mjs
./node_modules/.bin/tsc --noEmit
```

Observed: descriptor panel/parser tests **5/5 passed**; TypeScript `--noEmit` passed. No
trusted descriptor producer, configuration route, or native provider controls are connected;
this is UI-side contract validation only.

## CODE addendum — configuration default type validation — 2026-10-19

Descriptor validation now rejects a configuration default whose JSON type disagrees with
its declared field type: booleans, enum/string/path text, integers, and string lists are
checked explicitly. This validates typed defaults while leaving the adapter-defined
`constraints` object opaque; no undocumented constraint vocabulary is inferred.

On Rust/Cargo 1.98.1, Linux x86_64, the complete descriptor filter passed **17/17**:

```sh
cargo test --locked --offline -p litecoworkd --bin litecoworkd \
  agents::control_descriptor::tests:: -- --nocapture --test-threads=1
```

The new `configuration_defaults_must_match_the_declared_field_type` case covers valid
defaults for all six field types and malformed BOOLEAN, ENUM, INTEGER, and STRING_LIST
defaults. This focused run includes the prior descriptor cases. It is separate from the
earlier wider E03 `agent` filter result, which ran before this regression was added.
