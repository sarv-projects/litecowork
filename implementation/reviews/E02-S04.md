## Outcome and changed modules

The committed A08 fix scopes `loadingMore` to the request generation that owns it. A
refresh, reconnect, or Workspace invalidation resets the busy flag; a late completion from
an older generation cannot clear a newer request's busy state. The reducer is wired into
the Needs You Task-attention page. The existing page reads persisted `WAITING_USER`,
`NEEDS_USER`, and `BLOCKED` Task summaries with an independent cursor per status, validates
the returned status, deduplicates rows, and fences results by Workspace/request generation.
Opening a row navigates to Work for a fresh Task read and performs no mutation.

The full inbox projection and `GET /v1/needs-you` Operator handler are not implemented.
Approval and UserRequest actions are not connected; blockers without those records are not
resolved from this page. The UI explicitly labels this narrower scope. No API, event,
schema, or storage contract changed in the pagination fix.
