## Task-attention pagination, cursor, and accessibility CODE slice — 2026-10-14

The current UI source increment adds a synchronous generation gate around `loadMore`.
It rejects a second same-generation invocation before React can rerender, resets when a
refresh invalidates the generation, and prevents an older request's completion from
unlocking a newer generation. Each outstanding status page is handled independently: a
complete, validated successful page appends unseen Tasks and advances only that status's
cursor, while a failed or malformed page retains its prior cursor for retry. Empty or
repeated next cursors are rejected, including on the initial page. The page reports partial
status-page failure instead of discarding successful sibling pages. The load-more button
keeps its accessible label while busy, exposes `aria-busy`, and announces progress through
a status message. This remains the persisted Task-attention view; it does not implement or
claim the full Approval/UserRequest Needs You projection.

## Outcome and changed modules

The committed A08 fix scopes `loadingMore` to the request generation that owns it. A
refresh, reconnect, or Workspace invalidation resets the busy flag; a late completion from
an older generation cannot clear a newer request's busy state. The reducer is wired into
the Needs You Task-attention page. The existing page reads persisted `WAITING_USER`,
`NEEDS_USER`, and `BLOCKED` Task summaries with an independent cursor per status, validates
the returned status, deduplicates rows, and fences results by Workspace/request generation.
Opening a row navigates to Work for a fresh Task read and performs no mutation.

The full inbox projection and `GET /v1/needs-you` Operator handler are not implemented.
Approval and UserRequest actions are not connected; blockers without those records are not
resolved from this page. The UI explicitly labels this narrower scope. No API, event,
schema, or storage contract changed in the pagination fix.
