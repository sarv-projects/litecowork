# E05-S03 partial source review packet — Worker selection ranking

**Status:** Partial CODE source only. E05-S03 remains `IN_PROGRESS`. This implementation
orders already-qualified candidate projections; it does not create a child Attempt or
decide that delegation improves over the current lead.

## Implemented source

`domain-task` exposes a deterministic, versioned ranking function over candidate data
supplied by a trusted admission caller. It supports the existing `OptimizationPreference`
enum, `AUTOMATIC` / `PREFER` / `REQUIRE`, stable profile-ID tie-breaking, a minimum
qualified verification pass-rate floor, comparable currency-aware cost projections, and
qualified end-to-end latency projections. Cost observations carry source, confidence,
sample count, verifier coverage, observation time, and optional expiry. The ranking
projection excludes LOW-confidence, expired, future-dated, or older-than-90-day costs;
MEDIUM/HIGH thresholds follow the delegation projection contract. `REQUIRE` never substitutes another profile;
`PREFER` falls back only when the caller policy permits it. Unknown or incomparable cost
is kept unknown and ranks after known cost under `COST_FIRST`. A hard cost ceiling rejects
unknown/incomparable cost unless the candidate carries a provider-enforced ceiling that
meets the request. Results include the policy version, ranking rule, comparable cost and
the IDs whose cost remains unknown.
Each ranked candidate also carries a one-based position and a boolean showing whether it
matched the explicit preferred/required profile request. Together with the emitted
ranking rule and qualified candidate projections, these fields make the pure ordering
reproducible without claiming that ranking itself authorized admission.
Performance projections also carry their confidence. LOW-confidence verification and
latency values remain out of both ordering and the ranked metric projection; they cannot
outweigh MEDIUM/HIGH observations merely because their raw numbers look better.

The pure `aggregate_worker_performance` function aggregates an already owner-scoped
projection. It applies the inclusive 90-day terminal-time window, excludes
cancelled/abandoned/nonterminal Attempts, rejects duplicate Attempt IDs, computes
verifier pass rate only over terminal verifier results, uses terminal child Attempts for
retry/intervention denominators, preserves unknown or incompatible cost as null, and
labels usage sources/confidence. LOW-confidence metrics are not copied into the ranker's
ordering fields. A profile mismatch is rejected when applying a projection to a
candidate. The public projection/query/sample types are exported from `domain-task`.

The existing OpenAPI operation is now served by the authenticated
`GET /v1/delegation-profiles/{id}/performance?task_category=` Operator handler. Its
SQLite adapter checks Workspace ownership and profile membership, then loads only
terminal COMPLETED/FAILED child Attempts in the requested category whose settlement time
is within the rolling 90-day window. Task category comes from the pinned AgentSession
TaskSpecRevision, with the contract's `OTHER` default. Retry attribution uses a later
Attempt for the same Task/Step; human-intervention attribution uses an exact
`user_requests.attempt_id` link. A cost is included only for one exact Attempt-linked
COST observation within the window with a valid source, confidence, unit, and currency;
ambiguous/multiple rows remain unknown. The SQLite read runs on Tokio's blocking pool so
the bounded but potentially broad projection query does not occupy an async worker.
VerificationRun currently has no Attempt FK and
its subjects are Resource refs, so verifier outcomes are not inferred: verification
metrics are null, source completeness is false, and confidence remains LOW. The response
is Workspace-scoped and `Cache-Control: no-store`. `failure_categories` currently stays
empty because the current source does not define an attributable bounded failure-category
projection.

The existing `GET /v1/agent-bindings/{id}/quota-observation` OpenAPI operation is now
served by an authenticated route module. The handler checks selected Workspace ownership
and resolves the exact AgentBinding through `AgentCatalogStore` on a blocking worker;
foreign owners receive a denial and bindings outside the Workspace are hidden. Since no
AgentModule currently supplies a timestamped, source-attributed quota observation, the
contract-correct body is JSON `null`. The module does not probe a provider, infer quota
from a generic rate limit, or treat absence as budget/failover authority. All responses
carry `Cache-Control: no-store`. Router-level tests exercise the registered path,
authentication marker, null response, cache header, and foreign-owner denial. A fixed
Tauri bridge and typed UI consumer now connect this operation to each Workspace binding's
on-demand “View usage observation” disclosure. It displays explicit absence as “No
qualified usage observation,” keeps unknown distinct from zero, and shows provider source,
observation age, state, and quantified provider units only when supplied. Expired or
future-dated data is displayed as unknown and its remaining/reset values are suppressed;
the disclosure never creates a percentage meter or a lead-switch signal.

The selector is a pure projection. The caller must establish all hard eligibility facts
from current authoritative Task/Step/Attempt/lease, profile/binding, adapter, Runtime,
Environment, Trust/grant and budget state. There is no live candidate producer, quota or
usage observation source, BudgetReservation transaction, Task admission integration,
authoritative observation lookup/freshness recheck, or B83 benefit/confidence decision.
Caller-supplied timestamps are filtered but are not proven current by this pure projection.
Therefore it cannot dispatch work,
claim a candidate is cheaper/faster/better, or replace the current lead.

## Source increment (2026-10-19): provider-enforced cost ceiling and bounded projection query

A measured or estimated historical cost no longer satisfies a requested hard `max_cost`
ceiling. The candidate must carry a provider-enforced ceiling in the same currency whose
bound is at or below the request. Historical measurements remain available for ranking
when there is no hard ceiling; they do not become prospective budget authority.

`worker_performance_attempts` now loads the bounded terminal Attempt set and its cost
observations with one CTE/join query instead of issuing a second SQLite statement for
each Attempt. A cost is returned only when exactly one valid COST observation is linked;
missing, ambiguous, and malformed values remain unknown. The SQLite `COUNT(*)` is read as
signed `i64` and checked before conversion to the domain's unsigned count type.
