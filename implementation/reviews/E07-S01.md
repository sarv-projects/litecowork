## Provider capability, budget admission, and lifecycle guards — 2026-10-20

`apps/litecoworkd/src/environment_provider.rs` adds the decision layer for the parts of
E07-S01 that the previous checkpoint recorded as missing. It is a decision module, not a
provider: it provisions nothing, reserves nothing, and exposes no route.

**Provider classes, lifetime, and sharing.** `reuse_boundary` keeps the private
worktree and the retained browser apart. An `ATTEMPT` Environment is
`ReuseBoundary::SingleAttempt` and is never reused by a replacement Attempt. A
`TASK_RETAINED` Environment is `ReuseBoundary::OwningTask`. A `WORKSPACE_PERSISTENT`
browser or desktop surface is `ReuseBoundary::RetainedSurface`, while a
`WORKSPACE_PERSISTENT` non-surface Environment stays `OwningTask`. `USER_SHARED` is
`ReuseBoundary::Unavailable`, matching the v1 rule that cross-Workspace mounting is not
offered. Sharing scope is never treated as an authorization grant.

**Explicit provider capabilities.** `probe_environment_provider` reports the provider
classes, the supported lifetimes, checkpoint/restore support, the budget enforcement
mode, and a member bound, with a stated reason for every unimplemented capability. It
reports `BudgetEnforcement::Unavailable` and no checkpoint/restore support, because
this build implements neither. A lifetime that the provider does not support is
reported as unsupported rather than assumed.

**Budgets.** `admit_environment_use` enforces the cumulative-from-creation rule: a
ceiling that has been reached stops admitting new uses
(`BudgetLimitReached`), and there is no reset, top-up, or in-place budget change. Under
`BudgetEnforcementPolicy::RequireProviderEnforced`, a host-monitored or unavailable
provider is refused outright (`BudgetEnforcementUnavailable`). Under
`AllowHostMonitored`, the use is admitted but the result carries `may_overshoot: true`,
so a UI can state that the ceiling is a monitor that can overshoot while the host is
offline, suspended, or reporting charges late. It is never described as a hard cap.
`max_child_attempts` is enforced separately (`ChildAttemptLimitReached`).

**Archive and cleanup guards.** `assert_environment_may_be_archived` refuses an archive
while a durable reference exists (`Referenced`, covering active Attempt, unsettled
Invocation, active control lease, unresolved Effect, and checkpoint hold), refuses
unknown provider state (`ProviderStateUnknown`), and refuses a non-quiescent provider
(`NotQuiescent`). Unknown provider state blocks the archive instead of pretending a
background process stopped.

**Provisioning idempotency and recovery.** `classify_provisioning_response` recognises
a repeated request (same `request_id` and same `request_body_digest`) and returns the
existing provider handle (`AlreadyApplied`), and otherwise returns
`ReconciliationRequired`. A lost response is never treated as a failure, and a
non-idempotent allocation is never repeated without reconciling provider state first.
