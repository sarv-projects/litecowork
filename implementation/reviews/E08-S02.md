## Workspace-scoped UI response fences — 2026-10-16

`SuggestionsPage` now scopes asynchronous mutation UI effects to the Workspace that
admitted the request. This includes dismiss/snooze/unsnooze, Task acceptance, preference
changes, and retry of an ambiguous saved mutation. A confirmed receipt still clears its
matching process-local retry record, but a response from an old Workspace cannot announce,
navigate, reload, replace preferences, or clear pending state in the newly active
Workspace. Opening a Task from a card is guarded by the card's Workspace as well. Goal
create/revise/status and retry responses now follow the same rule; confirmed stale receipts
resolve only their original process-local retry record. Related Task/Artifact catalog
pagination cannot replace the new Workspace's options or busy/error state. Goal and
Suggestion load-more responses and their completion cleanup are also fenced to the
Workspace and list generation, so a late old page cannot append into the new roster or
leave its pagination control busy.

## Suggestion preference idempotency key boundary CODE slice — 2026-10-15

The preference mutation previously rejected keys between 129 and 200 bytes at multiple
layers despite the shared Operator contract. The OpenAPI operation now references the
reusable `IdempotencyKey` parameter. Daemon, domain, SQLite, and Tauri validation delegate
to their existing shared 1–200 printable-ASCII validators; no receipt, authorization, or
transaction semantics changed.

The mounted authenticated Axum route uses real SQLite and an active local binding. A 200-
byte key commits one preference, event, and receipt; the exact request replays the same
body, changed payload under that key returns `CONFLICT`, and a 201-byte key returns
`INVALID_ARGUMENT` without another commit. The focused daemon route, domain helper, SQLite
shared-bound test, and Tauri preference helper tests all pass 1/1.

This closes only the source-level preference key bound. Producer-backed idea generation,
the full Goal and Suggestion transaction/race suite, packaged desktop/runtime behavior,
SYSTEM and owner USER acceptance remain pending; E08-S02 remains `IN_PROGRESS`.
