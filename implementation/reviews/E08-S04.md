## Stream snapshot wins over an older unary refresh — 2026-10-16

Task Work's panel loads the saved presentation and progress together while a snapshot
stream may also deliver updates. A stream snapshot accepted after the unary read starts is
newer than that read's SQLite view. The panel now applies snapshot and progress only when
the captured stream epoch is still current; it also suppresses stale read errors after a
newer stream snapshot arrives. This prevents old progress or a misleading stale-refresh
notice from replacing newer live state.

## Refresh the paired snapshot after an accepted stream update — 2026-10-19

`TaskPresentationPanel` now schedules one 250 ms debounced refresh of the saved Task
presentation and progress projection after it accepts a stream snapshot. The refresh uses
the current callback and confirms the Task identity before requesting; effect cleanup clears
the pending timer. This reduces the wait for updated lane/Evidence presentation data from
the normal five-second poll. It remains a snapshot refresh. It does not establish provider
or Environment liveness, switch the presentation source to live execution state, or prove
