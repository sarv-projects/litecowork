## Outcome

The Operator server now settles shutdown through bounded stages. It stops accepting new
requests, drains admitted request workers for up to 60 seconds, and then attempts to abort
and join cancellable workers for up to five seconds. A handler deadline is recorded as
`MayStillBeRunning` because an awaited `spawn_blocking` operation can continue after its
caller times out. Dispatch failures, cancelled workers, endpoint listener/thread failures,
and unsettled work prevent a clean result. Tokio runtime teardown is capped at five seconds;
the endpoint thread is joined for at most 70 seconds. A missed bound returns an error and
detaches the remaining thread rather than waiting indefinitely.

Runtime persists `DRAINING` before waiting for admitted Operator handlers. It advances to
`STOPPING` only after `OperatorServer::stop` reports successful settlement. A failed drain
therefore leaves the durable lifecycle at `DRAINING` with `last_shutdown_clean=false`, so a
subsequent incarnation must recover it as unclean. A one-poll accept probe observes an
already-ready listener failure concurrent with the shutdown signal without waiting for a
new client connection.

This is bounded shutdown behavior in the daemon source and tests. It does not establish
that the Tauri/systemd service lifecycle can stop a real daemon within the configured
deadline on a qualified OS.
