## Behavior

Starting Edit or Restore moves keyboard focus into the newly mounted text editor. Discard
returns focus to the corresponding Edit or Restore action. Successful publication moves
focus to its confirmation status. If that target is no longer mounted, focus moves to the
stable Artifact heading. This covers the UI transition where the initiating action is
removed while the editor is open; it does not claim full Workbench or application focus
management.

### Behavior

- Quick Create and Edit move keyboard focus to the name field.
- Cancelling the editor returns focus to the control that opened it: the roster row of
  the edited Coworker, or the "+ New Coworker" action for a new identity. A successful
  save moves focus to the Coworker heading because the form is removed from the page.
- Escape inside the editor closes it only when the draft is unchanged. A dirty draft
  keeps its values and reports "Your unsaved changes are still here. Use Cancel to
  discard them.", so a keystroke cannot silently destroy typed input.
- The archive confirmation takes focus, and Escape or "Keep Coworker" returns focus to
  the Archive action.
- The roster status word is now derived by one helper so it is never carried by color
  alone.
- The Goals list and detail loading states are static text with `aria-busy="true"`. The
  continuous rotating spinner was removed because MOTION.md states that indeterminate
  work is shown with a static label/icon and an accessible busy state, not a decorative
  animation.

### What this slice does not prove

The helper tests verify the decisions, not the browser. Nothing here proves that a screen
reader announces the focus move, that the focus ring is visible at 200/400% zoom, that
high contrast holds, that the packaged Windows/macOS/Linux WebView behaves the same, or
that a keyboard-only owner can complete a Task, an approval, or a takeover. The rendered
Chrome suite was deliberately not run in this slice. E08-S05 therefore remains `PLANNED`.
