Tauri bundle output when it exists). It deliberately does not walk the whole
cargo `target` tree: that tree holds the compiler and dependency artifacts,
which are not shipped. `--scan-target-tree` and `--source` widen the scan
explicitly.

Known limitations, cost and measured performance:

1. **No installer, no signature, no notarization and no updater exist in this
   repository.** The G3 checklist item "Installer signature, upgrade,
   uninstall, restore and rollback verified on clean hosts" is therefore
   **NOT RUN**. The signing accounts, the Apple notarization and the Windows
   signing certificate are owner-only resources.
2. The systemd unit is shipped as an artifact and is validated by
   `systemd-analyze verify`, but it was **never installed or started by
   systemd** on this host. The unit's `ExecStart` path (`/usr/bin/litecoworkd`)
   is not installed on a developer host.
3. The secret scan only covers the artifacts that exist in this working tree.
   The release binary and the Tauri bundle were not built.
4. There is **no SBOM** and no dependency-licence report in this repository.
   `cargo`/`pnpm` can produce both, but they are not generated or checked here.
5. The daemon is not yet installable as a service on Windows or macOS; no
   LaunchAgent or Windows service definition exists.

Upgrade / rollback / demo instructions: see
[`implementation/RELEASE-RUNBOOK.md`](../RELEASE-RUNBOOK.md). The service unit
is installed by copying it to `/etc/systemd/system/litecoworkd.service` and
enabling it; the repository never installs it.
