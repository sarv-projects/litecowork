### E10-S01

Implemented:

- The MCP App sandbox boundary as a host-issued frame. The frame origin is host-assigned,
  the iframe sandbox is exactly `allow-scripts`, and the Content-Security-Policy applies
  `default-src 'none'` with only the exact declared domains. An absent or invalid
  declaration blocks every external connection and resource; the host never invents a
  fallback domain. The bridge guard refuses a wrong origin, a replayed host-issued
  nonce, an unknown method, an oversized payload, and a payload that carries a
  credential. The App never receives an Operator credential.
- MCP_SKILL manifest conformance. A duplicated entry, a malformed digest, an oversized
  tree, and a dynamic manifest that may never be activated are all refused.
- The Skill definition and revision surface (`GET/POST /v1/skills`,
  `GET/PUT /v1/skills/{id}`) with a fail-closed lifecycle guard: a new definition is
  always `DRAFT`, a revision may only narrow the lifecycle, and a Skill is loadable
  only through a scoped CapabilityGrant bound to the exact capability reference and
  manifest digest. A revision changes the manifest digest, so a grant that pinned the
  previous revision stops matching.
- The Discover catalog projection as a read-only projection over capabilities
  LiteCowork already owns. A catalog row is never authority, install/auth/compatibility
  are reported as observed, an unknown state is an error rather than "available", and
  the Runtime's observed capability hosts stay a separate observation stream.
- The desktop Discover catalog and Skill-proposal review surfaces.

Blocked / not claimed:

- The LiteSPM package path. `docs/CAPABILITY-FABRIC.md` publishes only the service base
  URL and defers the API, authentication, manifests, package taxonomy, and
  installation. The catalog therefore reports `package_service_qualified = false` with
  reason `LITESPM_PACKAGE_SERVICE_NOT_QUALIFIED`, `connect-or-install` returns
  `DEPENDENCY_UNAVAILABLE`, and the capability test returns health `UNKNOWN` without
  contacting any provider. **The contract that must be published** is the LiteSPM
  package API/authentication/manifest section of `docs/CAPABILITY-FABRIC.md`, currently
  the paragraph beginning "This architecture records the service selection and system
  boundary only."
- Rendering a real compatible MCP App. The frame route issues the sandbox contract
  and the host-issued nonce; a qualified browser App host is a separate slice, so the
  USER acceptance is pending.

### E10-S02

Implemented:

- Bounded semantic capture with explicit owner consent, an immutable capture policy
  that caps the duration, the recorded steps, and the recorded trace bytes, and a
  sensitive-region policy that either pauses the capture durably or omits the sensitive
  fields. Reaching a cap stops recording.
- Redaction and typed placeholders. A sensitive observation keeps only its semantic
  step, and the derived draft replaces an observed path, URL, or identifier with a typed
  placeholder. A body that still carries forbidden content is refused and never stored.
- The owner-review gate. A draft never enables itself: an approval records the
  decision only, never activates a Skill, never installs a package, and never grants
  authority. A service, runtime, or agent principal may never approve a proposal, and
  a failed or pending redaction, a drifted proposal, and a proposal that is not in
  review are all refused.
- The desktop Skill-proposal review surface, which shows the redaction state, the drift
  blocker, the typed placeholders, and the publication blocker.

Blocked / not claimed:

- Publication through LiteSPM. `docs/LEARNING.md` section 9 item 7 requires LiteSPM to
  own the package lifecycle, but the package contract is not published, so an approval
  reports the publication blocker instead of publishing anything.
- The isolated skill test fixture that `docs/LEARNING.md` section 9 item 4 and section
  22 item 8 require. `docs/LEARNING.md` section 23 lists
  `crates/ports/skill_test_runner.rs` as an **uncreated, illustrative target path** (not a current crate, port or shipped runner) and no skill test runner
  contract is published. The USER "review/test draft" step is pending on it.
- The qualified capture producer. The Runtime's browser/computer-use provider is owned
  by E07 and is not wired in this slice, so the SYSTEM "teach sandbox browser task"
  acceptance is pending on that provider.

### Migrations

No migration was added. The Skill, SkillProposal, demonstration, and MCP App frame
aggregates reuse the existing `aggregate_snapshots` / `domain_events` /
`idempotency_receipts` / `audit_records` projection, so `SCHEMA_VERSION` is unchanged
and no `docs/schemas/sqlite-vN.sql` is required.
