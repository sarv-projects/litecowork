## E05-S01 — DelegationProfile lifecycle and UI

Dependencies: E04-S05.

**Implement:** Versioned profile CRUD/duplicate/enable/archive, adapter option validation and Coworker assignment UI; same binding multiple profiles. Add versioned Workspace delegation settings with a workspace-owned worker-profile ceiling and native-child model policy. A Coworker selects the Workspace default or a narrower Coworker override; Task admission resolves and pins the exact policy into TaskSpecRevision. Settings edits affect future Task admissions only. Ordinary composer Send remains on the selected agent's native subagent mechanism; cross-agent workers dispatch only through an explicit durable Task or accepted plan. Each host worker uses its own eligible account route and authentication.

**Acceptance:** Disabled by default including lead; revision pin never mutates a running child; enable starts no process. Workspace settings use CAS/idempotent receipts and an immutable revision. Coworker overrides cannot widen the Workspace ceiling. A new Task pins the resolved settings/profile revisions; ordinary conversation submission cannot request a host route or per-Task route override. Settings changes do not silently reconfigure an active Task or native agent session.

**Negative/race cases:** Enable disconnected agent, stale profile/settings edit, archived or disabled binding/profile, unsupported model, override outside Workspace ceiling, concurrent settings revision, stale TaskSpec, unknown native control scope, worker auth/quota loss, attempted credential/session transfer, direct-conversation cross-agent dispatch, per-Task route override, silent fallback.

**E05-S01-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E05-S01-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E05-S01-USER:** Create fast and reviewer profiles on one installed harness. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.

TaskSpec, concurrency limits and unqualified candidates block escalation. The Coworker
settings editor exposes the selected fallback order with keyboard-operable reordering.
The owner-requested lead assignment path now has a typed domain command, authenticated
Operator route (`POST /v1/tasks/{task_id}/lead-agent`), a `TaskStore` commit seam and a
SQLite transaction implementation. That transaction currently permits only a `READY`

**Source increment (2026-10-20):** The canonical lead-change event is now the durable
