## E03-S01 — Harness qualification and bindings

Dependencies: E02-S04.

**Implement:** Run SP04; probe supported native descriptor/config digest/session options; implement discovery, auth readiness, enabled and lead_eligible.

**Acceptance:** Native config remains unchanged; unsupported overrides rejected; installed/connected/lead eligibility displayed independently.

**Negative/race cases:** Missing binary, expired auth, config drift, unavailable model, plugin conflict.

**E03-S01-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E03-S01-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E03-S01-USER:** Compare selected native agent with LiteCowork launched session using same config. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.
