## E06-S01 — Bounded archive and extraction provider

Dependencies: E04-S05.

**Implement:** ZIP manifest preview and extraction limits; isolated type parsing/OCR provider; exact Resource revisions and parse provenance; run SP06.

**Acceptance:** Path traversal/symlinks/bombs refused; original immutable; PDF/page/table references retained; failures visible per file.

**Negative/race cases:** Nested ZIP, encrypted ZIP, Unicode duplicate path, zip bomb, malformed PDF, OCR timeout.

**E06-S01-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E06-S01-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E06-S01-USER:** Import mixed folder and ZIP without escape; inspect extraction report. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.

**Current implementation boundary:** A Python ZIP parser and source-level fixture tests exist, but there is no supervised isolated worker, hard resource limit/cancellation boundary, Core member-Resource publication, or qualified desktop OS containment. The daemon readiness route, Tauri status bridge, and Library notice are mounted; readiness reports `UNAVAILABLE / ISOLATED_WORKER_NOT_QUALIFIED` and does not pass archive bytes to the parser. Normal upload stores ZIP bytes intact. This is not acceptance of E06-S01; parser isolation and Core integration remain required before its acceptance cases can pass.

## E06-S04 — Local-model harness UX and performance

Dependencies: E06-S03.

**Implement:** Run SP05; integrate qualified harness with local engine; endpoint/auth/model status, bounded context, tool tests, cancellation, warm hints and egress policy.

**Current support boundary:** No local inference endpoint registration/probe, model-catalog UI, local-model AgentBinding, or inference turn is implemented. Existing local lexical Resource indexing is not semantic RAG or local inference. Ollama, LM Studio, and llama.cpp remain candidates until SP05 records a selected exact protocol/version and passes its security and harness gates. Never show a candidate engine as connected or start an Agent from an endpoint-only catalog result.

**Admission gate:** Before endpoint readiness/model discovery can ship, define an owner-controlled endpoint record and exact local service binding through the trusted Runtime broker, with authenticated local transport, strict loopback/private-address and redirect policy, bounded connect/read/body/model-list limits, cancellation, sanitized errors, and no credential disclosure. If this gate is not satisfied, the UI must report `UNAVAILABLE`/`NOT_CONFIGURED`; it must not probe an arbitrary URL or silently use a cloud provider.

Add a read-only Context used disclosure from exact resolved attachments/retrieval receipts, with provenance, freshness, and provider-provenance limitations; this is not autonomous memory extraction.

**Acceptance:** Uploading != searchable; embedding egress shown; local-only resource blocks cloud resolution; owner can explicitly rebuild an exact pinned current Resource's encrypted lexical index, see typed not-indexable reasons, and safely retry an ambiguous response; cancel remains available only for operations that actually support cancellation.
