## E06-S01 — Bounded archive and extraction provider

Dependencies: E04-S05.

**Implement:** ZIP manifest preview and extraction limits; isolated type parsing/OCR provider; exact Resource revisions and parse provenance; run SP06.

**Acceptance:** Path traversal/symlinks/bombs refused; original immutable; PDF/page/table references retained; failures visible per file.

**Negative/race cases:** Nested ZIP, encrypted ZIP, Unicode duplicate path, zip bomb, malformed PDF, OCR timeout.

**E06-S01-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E06-S01-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E06-S01-USER:** Import mixed folder and ZIP without escape; inspect extraction report. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.

**Current implementation boundary:** The bounded Python parser now has a standalone Linux `ZipWorker` metadata-preview path. On the current Ubuntu development host, integration tests launch it through Bubblewrap with private user/PID/network/IPC/UTS/mount namespaces, read-only runtime and parser mounts, a 1 MiB private `/tmp`, inherited 8-second CPU and 512 MiB address-space limits, and a 12-second parent deadline that kills the process group. The worker accepts only a pinned source identity plus bounded archive bytes and returns a bounded metadata manifest; it does not extract files to disk or return member payloads. The parent streams request bytes and enforces the stdout ceiling while reading instead of buffering an unbounded child response; unused stderr is discarded. Tests cover output-flood process termination, traversal, Unicode duplicate paths, encrypted and symlink members, expanded-size bombs, unavailable Bubblewrap, non-Linux rejection, timeout termination, and a real parser round trip.

This is a development qualification slice for metadata preview, not Runtime integration or E06-S01 acceptance. `litecoworkd` does not package or invoke this Python worker, there is no Resource-pinned preview endpoint, no explicit user cancellation API, no member extraction in the sandbox, and no Core child-Resource/provenance/deletion transaction. The existing daemon readiness route therefore remains `UNAVAILABLE / ISOLATED_WORKER_NOT_QUALIFIED`; normal upload stores ZIP bytes intact. Only the current Linux development host has been exercised; other Linux distributions and desktop OSes are unqualified. Parser isolation and Core integration remain required before E06-S01 acceptance cases can pass.

## E06-S05 — Knowledge UI and placement

Dependencies: E06-S04.

**Implement:** Upload/folder/ZIP progress, extraction errors, index ready/stale states, citation viewer, source scope, retention and local/cloud availability. Add a read-only Context used disclosure from exact resolved attachments/retrieval receipts, with provenance, freshness, and provider-provenance limitations; this is not autonomous memory extraction.

**Acceptance:** Uploading != searchable; embedding egress shown; local-only resource blocks cloud resolution; owner can explicitly rebuild an exact pinned current Resource's encrypted lexical index, see typed not-indexable reasons, and safely retry an ambiguous response; cancel remains available only for operations that actually support cancellation.

**Negative/race cases:** Partial folder permissions, removed drive, disconnected provider, repeated submit, Resource head changes after the Library row was loaded, same idempotency key reused with a different pin, unsupported/oversized/invalid UTF-8/control-character/over-term-limit source, response lost after projection commit, archived Workspace retry.

**E06-S05-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E06-S05-USER:** Drag a ZIP, inspect readiness and citation, rebuild the local lexical index for a supported text Resource, observe a typed not-indexable result for ZIP, inspect Context used for a grounded Task, verify exact source revisions, and attempt a disallowed cloud Task. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Current local lexical-index control source:** The desktop Library submits an owner-triggered rebuild command pinned to the listed ResourceRevision ID and SHA-256 digest. The authenticated local Operator route and SQLite implementation return `INDEXED` or a typed `NOT_INDEXABLE` reason; a successful projection update and its principal-scoped idempotency receipt commit together. This is deterministic lexical indexing only. It does not implement embeddings, semantic RAG, ZIP extraction, parser expansion, or background indexing. The E06 file-intake slice's UI build does not verify the lexical-index daemon/storage path; its endpoint, storage transaction, and real desktop acceptance still require explicit focused verification. E06 acceptance remains open.

**Desktop one-time file intake source path:** The Library exposes the WebView's native file chooser for multiple files, a directory chooser through the platform-supported `webkitdirectory` attribute, drag-and-drop, and Workspace-note creation. The intake submits selected bytes through the authenticated local IPC Operator bridge and the existing resumable upload session/chunk/commit routes; it does not send absolute selected paths to the daemon. Folder files retain only normalized relative-path provenance and remain one-time Resources, not persistent WorkspaceRoot grants. After commit, Resource metadata enters the Workspace-scoped catalog and eligible plain text can be previewed by exact ResourceRevision through the authenticated local route. ZIP files remain opaque original-byte Resources; upload completion does not mean extraction or indexing.

The UI now reports the current file being digest-checked before it starts/resumes transfer, then reports accepted byte ranges and commit status. Folder paths are validated without rewriting unsafe separators. Code-level coverage is in `apps/litecowork-ui/tests/resource-intake.test.ts` for traversal/absolute/drive/control/length rejection, secret/generated-path filtering, nested relative-name preservation, and per-file/count/aggregate-size bounds. UI TypeScript/production build and UI unit tests pass in the current development environment. These checks do not exercise an actual Tauri OS chooser, daemon IPC peer authentication, multi-chunk upload/restart recovery, real folder permissions, or owner acceptance on a packaged desktop. Those are still required by E06-S05-SYSTEM and E06-S05-USER. WorkspaceRoot watching, recursive indexing, archive extraction, PDF/Office parsing, OCR, embeddings, semantic/local-model RAG, and automatic/background indexing remain unimplemented.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.
