## E09-S02 — Automation and occurrences

Dependencies: E09-S01.

**Implement:** Pinned Routine/Coworker Automation revisions, schedule/manual/webhook/file/poll/provider trigger conformance, cursor/misfire/dedupe/concurrency. Source supports paused definition create/revise plus an authenticated local owner ManualTrigger path. That path requires an active local TRIGGER_HOST binding, atomically commits occurrence PENDING v1 → CLAIMED v2 → STARTED v3 and an ordinary READY Task, and resolves same-request receipts before mutable Resource/Coworker/host admission checks. It creates no Plan or execution records. The desktop editor now offers an explicit Manual trigger, bounded TEXT and exact same-Workspace ResourceRef inputs for the pinned Routine, in-process exact retry across route unmount/re-entry, receipt validation, and Task detail navigation. Ambiguous request envelopes are bounded and volatile, keyed by Workspace/Automation/revision/trigger; no Resource bytes are stored. Scheduled/provider trigger hosting, cursor/misfire settlement, end-to-end acceptance, and all build/test/OS verification remain open.

**Manual-trigger limits:** The owner-issued one-shot ManualTrigger does not activate
recurring hosting. It is allowed for PAUSED and ENABLED definitions with a ManualTrigger,
but rejects DISABLED definitions. Occurrence `STARTED` means a READY Task was linked, not
that planning or agent execution began. The desktop exposes this as a one-shot Task
materialization action. An ambiguous response keeps its exact request in a bounded volatile
process registry across UI route changes; registry exhaustion fails closed rather than
evicting an unresolved request. Explicitly discarding a retry record warns that a duplicate
Task may result if the original committed. Process restart recovery, scheduled hosting,
cursor recovery, Task execution, and production qualification are not established.

**Acceptance:** Every occurrence ordinary Task; edit never resets logical cursor; current Coworker ACTIVE checked; local unavailable waits.

**Negative/race cases:** DST gap/fold, restart catch-up, duplicate webhook, no-change poll, cursor race, Coworker selection changes before recheck, missing/cross-Workspace revision, exact pin preserve/change/clear, idempotent replay, paused-only definition writes, ambiguous response followed by route unmount/re-entry, Workspace switch, changed inputs under the same request identity, multiple unresolved runs, registry capacity, explicit retry-record discard, and process restart (unsupported).

**E09-S02-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E09-S02-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E09-S02-USER:** Save a paused Automation with one ManualTrigger pinned to a Coworker and Routine revision, create a READY Task from supported TEXT and exact ResourceRef inputs, open it in Work, and verify no planning/agent execution starts and recurring status remains PAUSED. After that, edit the Coworker and verify the Automation pin stays unchanged until explicitly revised. Scheduled local execution across daemon restart and all OS/runtime acceptance remain open. Owner checks expected outputs and permissions against a prepared oracle. A mock-only run does not satisfy real-provider acceptance.

**Manual-run recovery source note:** An ambiguous `/run` outcome preserves the exact
RequestId, Automation/Routine snapshots, trigger identity, and bounded input object only in
process memory. Navigating away and back in the same Workspace/process restores the retry
card. Another Workspace cannot display or submit the request. A second Run for that
Automation is blocked until the owner retries to a confirmed receipt or explicitly
discards the retry record. The client never silently generates a replacement RequestId.
Closing/restarting the process can still lose the retry key; this source change does not
establish restart-safe recovery or production readiness.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.

## E09-S05 — Manual Routine run creates an ordinary READY Task

same-transaction SQLite Routine/current-revision and Resource checks, Tauri bridge, desktop
schema-generated TEXT and exact same-Workspace ResourceRef selectors, identity-checked Task
detail navigation, and API/event/flow documentation are now authored. The Task remains READY
with no Plan or execution records. Scheduled execution and verification remain open.

**Implement:** Exact active/current RoutineRevision pinning, supported bounded input
rendering, owner/Workspace/RequestId idempotency, TaskStore atomic Routine revalidation,
TaskSpec projection, conditional event provenance, desktop Run now state, and failure UX.

**Acceptance:** One ordinary READY Task and TaskSpec(1), pinned to the selected revision;
no Plan/Step/AgentSession/Attempt/lease/Environment/Effect/grant; unchanged exact retry

**Negative/race cases:** unsupported schemas rejected at revision admission; extra or

or head change racing commit; unavailable/ineligible lead; Conversation ID; Workspace

**E09-S05-CODE:** Domain materialization/source regression cases plus storage transaction
checks for ACTIVE/current revision, no partial commit, Resource/lead guards, idempotency,

**E09-S05-SYSTEM:** Exercise the authenticated daemon API through local IPC and the actual

**E09-S05-USER:** Owner creates a Routine with required/optional text and Resource inputs,
