## E09-S01 — Routine creation/revision and reusable work

Dependencies: E07-S05, E08-S05.

**Implement:** Create Routine from verified Task, typed inputs/criteria/pinned skills, revision lifecycle/health and reviewable extraction.

**Acceptance:** Incidental paths/secrets removed; Routine what differs from Skill how; dependencies/pins visible and edits future-only.

**Negative/race cases:** Invalid input schema, drifted skill, unverified source task, archived routine.

**E09-S01-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E09-S01-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E09-S01-USER:** Turn verified weekly research into parameterized Routine. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.
