## E01-S02 — Transactional persistence

Dependencies: E01-S01. E01-S01 remains `IN_REVIEW`; this implementation is an
owner-directed continuation and does not satisfy or waive that prerequisite.

**First vertical slice:** Implement `StateStore`, `EventStore`, and `BlobStore` ports;
`WorkspaceService` create/policy-update commands; a bounded SQLite writer; versioned
baseline migration and schema fingerprint; encrypted content-addressed file blobs behind
an injected key-provider port; atomic Workspace projection/event/origin-sequence commits;
restart and projection replay. This slice has no Operator API/UI. The desktop OS
credential-store provider is implemented behind `WorkspaceBlobKeyProvider`. Rotation
retains prior versions, resumes a validated staged next version after a failed pointer
write, reconciles ambiguous pointer-write results by reading back the active version, and
fails closed on malformed staged or missing active key material. Key initialization and
rotation share an OS file lock across processes. Unix lock-directory ownership and mode
are checked. Windows uses `LOCALAPPDATA`, rejects reparse points, and now applies a
protected persistent-owner/SYSTEM DACL to the mutation-lock directory and an existing lock
file. A Windows 11 PowerShell probe verified the ACL reset against a deliberately broad
legacy lock-file ACL, and the Windows security crate cross-check passed; the storage-sqlite
Windows target check is blocked by missing MinGW before compiling its caller. Actual
Windows Credential Manager key creation/rotation and packaged qualification remain open;
other non-Unix targets are unqualified. Linux constructs the persistent Secret Service
credential directly instead of using the keyutils cache. Injected
credential-store CODE tests cover recovery; a child-process test exercises the shared file
lock, and a backend-contract test checks the Linux credential type without connecting to
Secret Service. Actual OS keychain qualification and cryptographic review remain open.
`rusqlite` is provisional pending completion of SP02.

**Acceptance:** Real SQLite and filesystem adapters commit Workspace state, event, and
per-origin sequence atomically; competing writes at one expected version have one winner;
restart/replay produces the same Workspace state; migration drift, unsupported schema,
missing encryption keys, and blob authentication failures fail closed.

**Negative/race cases:** Concurrent stale writes; injected rollback at aggregate/sequence/
event/pre-commit points; external writer busy timeout; migration interruption and retry;
schema fingerprint drift; wrong Workspace/purpose; ciphertext corruption; broad blob
directory permissions; blob commit failure; idempotent deletion of missing objects;
refusal to delete symlink/non-regular objects; and refusal to follow symlinked BlobStore
root or Workspace/purpose directories outside the configured root. Actual database/file-system disk exhaustion
and OS keychain integration remain unqualified and must not be claimed covered.

**E01-S02-CODE:** `cargo test --locked --workspace` exercises the real SQLite actor and
file-backed encrypted BlobStore using test-only keys, Workspace service validation,
JCS serialization, migration metadata, optimistic concurrency, rollback, replay, and
failure paths. The OS key-provider unit tests inject failures at the credential boundary
and verify staged-key retry, ambiguous pointer-write reconciliation, retained-version
reads, malformed-stage and malformed-pointer refusal, orphaned-first-key recovery-required
refusal, missing
active-key refusal, version exhaustion, staged-write failure, ambiguous-read failure,
changed-key detection, and Workspace/purpose scope. A separate child-process test checks
OS file-lock exclusion; Linux backend selection is checked without connecting to an actual
OS credential service. BlobStore tests also prove missing-object deletion is idempotent
and symlink/directory objects are rejected without modifying the symlink target. A SQLite `max_page_count`
fixture must cause SQLite itself to return
`SQLITE_FULL` through the real transaction function and prove aggregate/event/sequence
rollback; this is not physical filesystem exhaustion. Deterministic storage tests use a
fixed-key provider; the OS-backed provider requires separate platform qualification.

**BlobStore directory-boundary CODE evidence (2026-10-11; descriptor-relative hardening

through held directory descriptors opened without following symlinks. Reads, temporary
writes, no-clobber publication, deletion, and directory sync are relative to the opened
purpose descriptor. Existing adversarial tests reject symlinked roots, Workspace and
purpose directories for `put`, `get`, and `remove`; deterministic replacement tests also

`put` must not write through the replacement, and `remove` must preserve an outside object.

ancestors sync before the first mutation per store instance (and after root recreation),
while successful writes/deletes re-sync the Workspace and purpose parents plus the held
purpose directory. This includes idempotent publish, concurrent `EEXIST`, and missing-object
delete retries. Deterministic CODE tests inject root, Workspace, publish, competing-publish,
and unlink sync failures; retries must sync the affected namespace before reporting success.
Unix CODE tests do not qualify crash durability or defend against a compromised same-UID
process modifying entries inside the private store. Windows remains path-based and requires
separate reparse-safe implementation and platform qualification; no Windows race guarantee
is claimed. See `docs/STORAGE.md` and the E01-S02 review packet.

## E01-S03 — Independent Runtime lifecycle

Dependencies: E01-S02.

**Implemented slice:** `litecoworkd run --data-dir` creates/restricts a local state
directory, holds a cross-process single-instance lock, persists Runtime/incarnation
bootstrap state, opens `LocalWorkspaceStorage`, and reports truthful `DEGRADED` blockers
until Task recovery and execution services exist. It validates an installation-scoped
OS-principal binding before serving the local Operator endpoint. The shared
`operator-ipc` crate provides bounded framing, owner-only Unix socket lifecycle, peer UID
checks, and source-integrated Windows named-pipe lifecycle with current-logon-SID/SYSTEM
DACL and remote-client rejection; both adapters share connection/body budgets and I/O
deadlines. The daemon adapts authenticated frames to the same Axum routes with a private
process-local peer marker; Tauri uses the framed client and performs authenticated
readiness checks against daemon Runtime/incarnation status. Authenticated
`GET /v1/runtime-lifecycle` now projects the persisted startup policy and exact current
incarnation with sanitized blockers; the native Tauri bridge fences the response against
the readiness Runtime/incarnation, and Settings displays persisted availability, recovery
state, and safe resolution hints. The response is no-store, read-only, and does not claim
execution readiness or synthesize dependent Task/Automation inventories. The old desktop bearer/loopback
descriptor path has been removed. Workspace creation remains idempotent in the same
storage transaction as its aggregate/event commit. Windows source support is present, but
full Windows application cross-compilation and OS qualification remain open. The bounded
Operator drain, Runtime unclean-state behavior, and durable lifecycle transitions pass the
local workspace CODE gate. Linux systemd stop/expiry behavior, other-OS qualification, Task
recovery/execution, event streaming, package service-manager integration, and sleep/wake
behavior remain open.

If the authenticated Operator endpoint fails to initialize after Runtime registration,
the catalog incarnation is already `DEGRADED`; startup now records
`OPERATOR_API_START_FAILED` in private local status and exits nonzero instead of retaining
the single-instance lock in a signal wait with no usable endpoint. A service manager may
apply its configured bounded restart policy; manual startup reports failure and can be
retried. The catalog remains `DEGRADED` but does not store this specific local blocker.
This source change passes the local daemon/workspace CODE checks; no service-manager
restart experiment has been run, and this does not claim the endpoint failure itself is
recoverable or that repeated retries will succeed.

After the endpoint is ready, Runtime also supervises its endpoint thread. An unexpected
listener/thread exit signals active stream handlers, settles the existing bounded request
drain, and returns an error so `litecoworkd` exits nonzero and releases its instance lock.
If this occurs before a supervisor shutdown signal, local and catalog state remain
`DEGRADED` and unclean; the next incarnation reports unclean recovery. If it races with
supervisor shutdown, the existing failed-settlement guard prevents `STOPPING` or `STOPPED`.
The spawned-daemon CODE regression injects a post-readiness endpoint failure, checks the
unclean durable state and nonzero error, and starts a new incarnation against the same
store. It is a test seam, not a live OS listener-failure or service-manager experiment.

**Additional Linux lifecycle slice (source-integrated, OS-unqualified):** Tauri now installs or
refreshes a user-owned `litecoworkd.service` with restrictive permissions, absolute escaped
`ExecStart` arguments, `Delegate=yes`, `KillMode=control-group`, `Restart=on-failure`, and
`TimeoutStopSec=90s`. The 90-second service-manager deadline exceeds the daemon's 60-second
bounded in-flight Operator drain and leaves a 30-second margin for final lifecycle writes;
it is not a guarantee against a stalled store, and expiry remains an unclean forced stop.
Linux startup requests this service and has
no direct `litecoworkd run` fallback; macOS/Windows retain the prior startup behavior. The
unit is not enabled at login. Each Operator launch refreshes the unit to the currently
resolved packaged daemon path; an already active service is not restarted to apply that
refresh, so the new `ExecStart` applies the next time systemd starts the service. A conflicting
non-LiteCowork unit, unsafe config path, missing `/usr/bin/systemctl`, or unavailable user
manager fails closed for managed startup. Status checks the exact managed unit body, active
unit properties, and `/proc` executable plus arguments against the selected daemon and data
directory; a mismatch marks the displayed Runtime `DEGRADED` without conflating it with
authenticated Operator API readiness. This lifecycle unit is separate from the new
Linux-only `linux-process-scope` source primitive. That primitive runs a trusted launch gate
inside a transient per-Attempt cgroup, checks its cgroup membership and configured kernel
limits before native-agent exec, and can observe recursive cgroup-v2 quiescence. It is not
wired into Attempt admission, remains unbuilt/OS-unqualified, and does not restrict the
same-user worker's filesystem or access to the user systemd control bus. It is therefore not
a hostile-code sandbox or production-safe switching proof; a separate Environment boundary
is still required. Package uninstall cleanup is not wired;
the package integration must remove only this marked unit after safe drain and add that path
to the release gate. No uninstaller may terminate active work.

**Remaining implementation:** Durable Runtime/RuntimeIncarnation registration after
Workspace bootstrap, recovery gates, authenticated operator stop/start control, safe package
update/uninstall lifecycle, suspend/resume, dependency-aware drain preview, and process
worker process identity reconciliation. Linux scope/gate startup, pipe behavior, delegated
cgroup availability, recursive quiescence and limit enforcement still require systemd OS
qualification; filesystem isolation and same-user systemd-bus restriction need an Environment
provider before Attempt admission.

**Acceptance:** Closing Operator leaves daemon running; reboot changes incarnation; stale process cannot own a lease; workers lazy-start.

**Negative/race cases:** Duplicate startup, SIGKILL/restart, state-file corruption or
symlink, lock-file symlink/broad permissions, sleep during write, invalid state-directory
permissions, database/key-store recovery failure, and shutdown signal during drain.
An Operator request-task failure, ambiguous handler timeout, unexpected listener exit,
endpoint-thread join timeout/failure, or expired request drain must not persist `STOPPING`
or `STOPPED`; after `DRAINING` is durable, preserve that unclean lifecycle record so the
next incarnation runs recovery. Admission-stop failure must preserve the prior state as
unclean. The OperatorServer allows 60 seconds for request settlement, then up to five
seconds each for cancellation settlement and Tokio runtime teardown. On Linux, the
managed systemd stop deadline must exceed this bounded endpoint shutdown and leave room
for Runtime lifecycle persistence; a forced kill after that deadline must be reported as
an unclean restart, never a clean stop.
Operator startup also covers lock-held-before-listener, listener initialization failure,
stale/mismatched OS peer, unsafe/stale socket, unsupported API contract version,
API-serving while Runtime execution remains DEGRADED, startup timeout, and daemon restart
invalidating the old per-incarnation connection. Linux scope qualification additionally
must prove that a duplicate Attempt unit fails closed; the gate cannot release the worker
before exact cgroup membership and all requested kernel limits are observed; mismatched or
missing cgroup/controller evidence never sends GO; READY/GO markers are removed from the
agent's native stdio; and an unsupported OS returns `Unsupported`. Before GO, successful
cleanup requires a reaped launcher plus positive proof that the exact unit is inactive/dead
or its known cgroup-v2 `populated` value is zero; failed kill, unobservable evidence, or
timeout must retain `PendingCleanup`. Inject gate timeout,
exec failure, cgroup disappearance, systemd kill failure, and direct-child reap failure;
verify that cleanup returns and retains the appropriate `PendingCleanup` handle. A test
must demonstrate that same-UID systemd-bus/filesystem escape is outside this primitive's
security claim and does not make Attempt admission eligible.
