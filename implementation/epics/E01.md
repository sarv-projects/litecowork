## E01-S01 — Contract/toolchain baseline

Dependencies: none.

**Implement:** Pin the Rust and architecture-check Python toolchains with lockfiles; add one reproducible check command and CI job; create a minimal `litecoworkd` CLI that supports help/version only. Do not start a listener, open storage, or launch an agent. Pin Node/TypeScript/pnpm with the first desktop shell in E02-S01.

**Acceptance:** On a clean checkout, `scripts/check.sh` reports the pinned tool versions, verifies formatting/lints/tests/build, and runs architecture plus implementation-plan validation without floating Python installs. The CLI help/version commands exit successfully; unsupported options fail. No product Runtime behavior is claimed.

**Negative/race cases:** Missing pinned toolchain, malformed JSON schema, unsupported CLI option. Generated-client freshness and dependency-license policy are deferred until those contracts/dependencies exist.

**E01-S01-CODE:** Execute the real CLI binary for help, version, no-argument, and unsupported-option behavior; prove secret-shaped argument values are not echoed; test the architecture validator with valid and malformed schema fixtures; verify wrong Rust/Python/uv versions fail early; run Rust format, Clippy, build and unit/integration tests. No storage transaction behavior is part of this story.

**E01-S01-SYSTEM:** Run `scripts/check.sh` from a clean checkout on the reference development OS and in GitHub Actions. Confirm it rejects a missing/wrong uv version and malformed schema fixture, and that CLI help/version do not open a listener or database. Record OS and exact tool versions; there is no Runtime transport/provider in this story.

**E01-S01-USER:** Owner clones the committed repository on the reference development machine, follows the documented toolchain setup, runs `scripts/check.sh`, then runs `cargo run --locked -p litecoworkd -- --help` and `cargo run --locked -p litecoworkd -- --version`. The owner confirms the output is reproducible and does not imply unimplemented daemon behavior. Store exact commands, versions, output and failures; provider acceptance is not applicable yet.

**Review gate:** Changed paths, exact commands, tool versions, tests, CI result, limitations and owner acceptance evidence must appear in the review packet. Decompose further only if this cannot be demonstrated in one review cycle.

## E01-S02 — Transactional persistence

Dependencies: E01-S01. E01-S01 remains `IN_REVIEW`; this implementation is an
owner-directed continuation and does not satisfy or waive that prerequisite.

**First vertical slice:** Implement `StateStore`, `EventStore`, and `BlobStore` ports;
`WorkspaceService` create/policy-update commands; a bounded SQLite writer; versioned
baseline migration and schema fingerprint; encrypted content-addressed file blobs behind
an injected key-provider port; atomic Workspace projection/event/origin-sequence commits;
restart and projection replay. This slice has no Operator API/UI. The desktop OS
credential-store provider is implemented behind `WorkspaceBlobKeyProvider`; platform
qualification, rotation/recovery tests, and cryptographic review remain open. `rusqlite`
is provisional pending completion of SP02.

**Acceptance:** Real SQLite and filesystem adapters commit Workspace state, event, and
per-origin sequence atomically; competing writes at one expected version have one winner;
restart/replay produces the same Workspace state; migration drift, unsupported schema,
missing encryption keys, and blob authentication failures fail closed.

**Negative/race cases:** Concurrent stale writes; injected rollback at aggregate/sequence/
event/pre-commit points; external writer busy timeout; migration interruption and retry;
schema fingerprint drift; wrong Workspace/purpose; ciphertext corruption; broad blob
directory permissions; blob commit failure. Actual database/file-system disk exhaustion
and OS keychain integration remain unqualified and must not be claimed covered.

**E01-S02-CODE:** `cargo test --locked --workspace` exercises the real SQLite actor and
file-backed encrypted BlobStore using test-only keys, Workspace service validation,
JCS serialization, migration metadata, optimistic concurrency, rollback, replay, and
failure paths. A SQLite `max_page_count` fixture must cause SQLite itself to return
`SQLITE_FULL` through the real transaction function and prove aggregate/event/sequence
rollback; this is not physical filesystem exhaustion. The test key provider is not a
production implementation; the OS provider requires separate platform qualification.

**E01-S02-SYSTEM:** Run the storage adapter against a disposable on-disk SQLite database
and blob directory. Restart the adapter, inspect the committed Workspace/event sequence,
and rebuild state from immutable event-referenced blobs. Execute the `SQLITE_FULL` capped
database fixture against a disposable on-disk database and inspect transaction rollback;
restore capacity, retry the same revision, and verify the failed commit consumed no origin
sequence.
This remains a controlled SQLite capacity failure, not a full filesystem or daemon/
transport/provider integration; those do not exist in this slice.

**E01-S02-USER:** Owner runs the replay test and full `scripts/check.sh`, confirms the
printed Workspace/version/policy/event/replay summary, then reviews the exact changed
paths and limitations in [the E01-S02 review packet](../reviews/E01-S02.md). Record the
owner's OS and decision there. Do not claim acceptance from agent-run tests.

**Review gate:** Record exact commands/tool versions, storage/schema/event references,
test output, rollback/failure coverage, upgrade/rollback behavior, SP02 status, production
key-provider status, and the still-pending E01-S01 prerequisite. Decompose before claiming
production readiness if remaining migration, encryption, telemetry, or disk-full evidence
cannot be demonstrated.

**Current additive schema work:** SQLite v3 now defines `runtime_workspace_bindings`,
backfills existing Runtime/Workspace pairs, and requires an active binding in Attempt /
Environment admission. The migrator includes fresh-install, v1→v2→v3, and v2→v3 paths.
This is source-only and unverified. The daemon does not yet persist its device identity or
create/query these bindings. Four v1 composite foreign keys continue to restrict one
Runtime row to one Workspace; multi-Workspace support requires a later dependency-aware
table rebuild. Do not infer that folder roots or production IPC are ready from this schema.

## E01-S03 — Independent Runtime lifecycle

Dependencies: E01-S02.

**Implemented slice:** `litecoworkd run --data-dir` creates/restricts a local state
directory, holds a cross-process single-instance lock, persists Runtime/incarnation
bootstrap state, opens `LocalWorkspaceStorage`, and reports truthful `DEGRADED` blockers
until Task recovery and execution services exist. It validates an installation-scoped
Linux/macOS OS-principal binding before serving the local Operator endpoint. The shared
`operator-ipc` crate provides bounded framing, owner-only Unix socket lifecycle, peer UID
checks, connection/body budgets and I/O deadlines. The daemon adapts authenticated frames
to the same Axum routes with a private process-local peer marker; Tauri uses the framed
client and performs authenticated readiness checks against daemon Runtime/incarnation
status. The old desktop bearer/loopback descriptor path has been removed. Workspace
creation remains idempotent in the same storage transaction as its aggregate/event commit.
Windows fails closed pending named-pipe identity/ACL support. This code has not been built,
tested, or OS-qualified. Task recovery/execution, event streaming, cross-platform/package
service-manager integration, sleep/wake behavior, and production transport qualification
remain open.

If the authenticated Operator endpoint fails to initialize after Runtime registration,
the catalog incarnation is already `DEGRADED`; startup now records
`OPERATOR_API_START_FAILED` in private local status and exits nonzero instead of retaining
the single-instance lock in a signal wait with no usable endpoint. A service manager may
apply its configured bounded restart policy; manual startup reports failure and can be
retried. The catalog remains `DEGRADED` but does not store this specific local blocker.
This source change is unbuilt and unverified, and does not claim the endpoint failure
itself is recoverable or that repeated retries will succeed.

**Additional Linux lifecycle slice (source only, unverified):** Tauri now installs or
refreshes a user-owned `litecoworkd.service` with restrictive permissions, absolute escaped
`ExecStart` arguments, `Delegate=yes`, `KillMode=control-group`, `Restart=on-failure`, and
`TimeoutStopSec=90s`. The 90-second service-manager deadline exceeds the daemon's 60-second
bounded in-flight Operator drain and leaves a 30-second margin for final lifecycle writes;
it is not a guarantee against a stalled store, and expiry remains an unclean forced stop.
Linux startup requests this service and has
no direct `litecoworkd run` fallback; macOS/Windows retain the prior startup behavior. The
unit is not enabled at login. Each Operator launch refreshes the unit to the currently
resolved packaged daemon path; an already active service is not restarted to apply that
refresh, so the new `ExecStart` applies the next time systemd starts the service. A conflicting
non-LiteCowork unit, unsafe config path, missing `/usr/bin/systemctl`, or unavailable user
manager fails closed for managed startup. Status checks the exact managed unit body, active
unit properties, and `/proc` executable plus arguments against the selected daemon and data
directory; a mismatch marks the displayed Runtime `DEGRADED` without conflating it with
authenticated Operator API readiness. This lifecycle unit is separate from the new
Linux-only `linux-process-scope` source primitive. That primitive runs a trusted launch gate
inside a transient per-Attempt cgroup, checks its cgroup membership and configured kernel
limits before native-agent exec, and can observe recursive cgroup-v2 quiescence. It is not
wired into Attempt admission, remains unbuilt/OS-unqualified, and does not restrict the
same-user worker's filesystem or access to the user systemd control bus. It is therefore not
a hostile-code sandbox or production-safe switching proof; a separate Environment boundary
is still required. Package uninstall cleanup is not wired;
the package integration must remove only this marked unit after safe drain and add that path
to the release gate. No uninstaller may terminate active work.

**Remaining implementation:** Durable Runtime/RuntimeIncarnation registration after
Workspace bootstrap, recovery gates, authenticated operator stop/start control, safe package
update/uninstall lifecycle, suspend/resume, dependency-aware drain preview, and process
worker process identity reconciliation. Linux scope/gate startup, pipe behavior, delegated
cgroup availability, recursive quiescence and limit enforcement still require systemd OS
qualification; filesystem isolation and same-user systemd-bus restriction need an Environment
provider before Attempt admission.

**Acceptance:** Closing Operator leaves daemon running; reboot changes incarnation; stale process cannot own a lease; workers lazy-start.

**Negative/race cases:** Duplicate startup, SIGKILL/restart, state-file corruption or
symlink, lock-file symlink/broad permissions, sleep during write, invalid state-directory
permissions, database/key-store recovery failure, and shutdown signal during drain.
On Linux, the managed systemd stop deadline must exceed the OperatorServer's bounded
60-second in-flight drain and leave room for final Runtime lifecycle persistence; a forced
kill after that deadline must be reported as an unclean restart, never a clean stop.
Operator startup also covers lock-held-before-listener, listener initialization failure,
stale/mismatched OS peer, unsafe/stale socket, unsupported API contract version,
API-serving while Runtime execution remains DEGRADED, startup timeout, and daemon restart
invalidating the old per-incarnation connection. Linux scope qualification additionally
must prove that a duplicate Attempt unit fails closed; the gate cannot release the worker
before exact cgroup membership and all requested kernel limits are observed; mismatched or
missing cgroup/controller evidence never sends GO; READY/GO markers are removed from the
agent's native stdio; and an unsupported OS returns `Unsupported`. Before GO, successful
cleanup requires a reaped launcher plus positive proof that the exact unit is inactive/dead
or its known cgroup-v2 `populated` value is zero; failed kill, unobservable evidence, or
timeout must retain `PendingCleanup`. Inject gate timeout,
exec failure, cgroup disappearance, systemd kill failure, and direct-child reap failure;
verify that cleanup returns and retains the appropriate `PendingCleanup` handle. A test
must demonstrate that same-UID systemd-bus/filesystem escape is outside this primitive's
security claim and does not make Attempt admission eligible.

**E01-S03-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above. The Linux unit-rendering test checks that `TimeoutStopSec` exceeds the 60-second Operator drain bound and preserves `KillMode=control-group`.

**E01-S03-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. On Linux, request systemd stop while a bounded Operator handler is in flight and prove the daemon's stop sequence can complete before systemd's 90-second kill deadline; separately force expiry and prove the next incarnation is classified unclean. Record OS/build/provider versions.

**E01-S03-USER:** Close app, reopen, kill daemon, recover same durable records. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.

## E01-S04 — Authenticated Operator boundary

Dependencies: E01-S03.

**Implemented slice:** The daemon exposes local Operator routes through OS-peer-authenticated Unix IPC on Linux/macOS. The Tauri native client derives the same installation endpoint, authenticates the daemon peer before frame I/O, preserves query parameters, allowed headers, idempotency keys and response status, and checks readiness against daemon Runtime/incarnation status. The frame adapter dispatches through the existing Axum handlers and retains Workspace-owner checks. The previous bearer/loopback descriptor path is removed. The Linux development build and selected code-level tests have passed; macOS and Windows, packaged desktop-to-daemon operation, and separate-identity behavior remain unqualified. Windows still fails closed. Other Operator command routes, pagination, stream replay/backpressure, generated client, and OS qualification remain open.

**Focused code evidence (2026-10-09):** `cargo test -p litecoworkd operator_ipc_tests -- --nocapture` passed three tests covering the shared auth middleware's missing-marker rejection, a same-UID Unix socket exchange through `dispatch_ipc_exchange` into an auth-protected readiness handler, and rejection of a caller-supplied bearer header by IPC frame validation. This exercises the in-process Linux Unix transport/auth seam; it is not a separate-OS-identity test, full daemon-process test, or platform qualification.

**Remaining implementation:** Add authenticated Windows named-pipe transport and per-logon DACL; qualify Linux/macOS/Windows peer authentication, socket lifecycle, timeouts, cancellation and crash recovery; add the typed Operator command envelope, remaining Workspace policy/Resource routes, event cursor replay/stream backpressure, generated TypeScript client, and authenticated lifecycle controls. There is no desktop HTTP/bearer fallback.

**Acceptance:** IPC rejects another OS user on Unix and Windows and another Windows
logon session for the same account; separate Unix sessions sharing a UID are treated as
the same OS-user boundary. Bad peer/frame and failed DACL are rejected before dispatch;
the listener enforces the shared body-memory and connection-count budgets plus I/O
deadlines; replay returns the same command result; daemon restart requires authenticated
readiness; no bearer/HTTP fallback is used; reconnect fills missed events before live updates.

**Negative/race cases:** Malformed ID, cross-Workspace request, reused RequestId with changed payload, slow stream.

**E01-S04-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E01-S04-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E01-S04-USER:** Use the desktop client and an adversarial local IPC client under a different OS identity against the same daemon. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.
