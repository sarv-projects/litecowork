## E02-S01 — Desktop shell/onboarding

Dependencies: E01-S04.

**Implement:** Pin Node/TypeScript/pnpm and lockfiles; build the Tauri React shell, theme tokens, routes, keyboard navigation, primary empty states, and daemon connection/tray; run SP01.

**Acceptance:** Fresh install creates local Workspace; no fake worker card; daemon offline is explicit; native shell survives reconnect. Node/TypeScript/pnpm versions are pinned and the UI lockfile reproduces the build.

**Negative/race cases:** Webview missing, daemon unavailable, repeated submit, resize/200% zoom.

**E02-S01-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E02-S01-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E02-S01-USER:** Install on reference OS, create Workspace and close/reopen Operator. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.
