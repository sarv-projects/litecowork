## E02-S03 — Resource intake and factual index

Dependencies: E02-S02.

**Implemented slices (unverified):** The desktop Library can select multiple files or a folder and submit files up to 10 MiB each (100 files/100 MiB per selection). Folder imports retain safe relative paths as Resource display names; excluded secret/generated paths are filtered before reading. ZIPs are stored as opaque file Resources. The authenticated Operator validates Workspace ownership, stores bytes in the encrypted local BlobStore, creates Resource + initial ResourceRevision + ResourceLocation and records events/idempotency receipt in SQLite, then lists Resource metadata back to the desktop. F86 adds authenticated current-revision content retrieval with BlobStore digest/length verification and a Tauri plain-text preview capped at 1 MiB. These slices have not been built or tested.

**Additional implemented slice (unverified):** Resource catalog listing now uses keyset pagination ordered by `(created_at DESC, resource_id DESC)`. The authenticated Operator validates the selected Workspace, accepts limits from 1–100, and issues an opaque Workspace-bound cursor. SQLite reads `limit + 1` rows without a fixed catalog ceiling. Tauri requests one page at a time; Library exposes “Load older files”, appends only unseen Resource IDs, and rejects empty/repeated next cursors.

**Additional implemented slice (unverified):** Library search now requests a Workspace-wide, server-side metadata page instead of filtering only loaded rows. The authenticated Operator validates Workspace ownership and bounds query/kind/freshness and pagination; its cursor is bound to the exact Workspace and filters. SQLite searches the current managed Resource revision using literal display-name/media-type substring matching and optional exact Resource-kind/freshness filters, returning the pinned ResourceRef, managed encrypted-blob location and match reasons. Tauri exposes only fields needed by the Library. The UI debounces search, rejects repeated pages, reports freshness, and previews a selected result. This is metadata-only: no extracted content, RAG, ZIP-member or folder-root search, and no result is implicitly attached to a Task. No plaintext search index is created. This slice has not been built or tested.

**Additional implemented slice (unverified):** Library can explicitly opt into `ON_DEMAND_CONTENT` search over current managed Resources. The authenticated Operator reads/decrypts at most 20 candidates, 1 MiB per Resource and 8 MiB total, scans only allowlisted UTF-8 plain text in request memory, rechecks the candidate revision/digest, and returns at most one 320-character text excerpt with a pinned ResourceRef. Metadata-only mode remains the default. Extracted text, query terms, and snippets are not stored; no SQLite migration or durable index was added. ZIP members, rich documents, WorkspaceRoots, and semantic RAG remain unsupported. The UI labels the scan and its limits. This source slice has not been built or tested.

**Additional implemented slice (unverified):** Library catalog/search results can be explicitly added to a pending Task as exact `PinnedResourceRef`s. The Home composer shows names and allows removal; selection is kept per Workspace. Tauri includes the refs in the existing `POST /v1/tasks` body, validates Workspace/ID shape, and verifies the returned TaskSpec input list. The Task detail reads persisted pinned refs and displays the exact revision, resolving a name from the local presentation cache where available. Operator/SQLite already validate same-Workspace resource and revision existence atomically with Task creation. This does not fetch Resource bytes, create an access grant, or start execution; it remains a save-only Task flow. No test/build/validator was run for this slice.

**Additional implemented slice (unverified):** Desktop Library now uses authenticated resumable uploads for files up to 100 MiB each, 100 files/100 MiB per selection, fixed 4 MiB chunks, and 24-hour sessions. Chunk content is stored in encrypted purpose-scoped blobs; SQLite persists indexed receipts and progress. The desktop stores session/request/file metadata only, and computes a required full-file SHA-256 before session creation and verifies it against the pinned session plus acknowledged chunk digests before resuming. Empty files skip chunk PUTs and commit directly. Finalization verifies chunk coverage, declared size, and the required full-content digest and atomically writes the initial Resource/revision/location, Resource-created event, commit receipt, and upload-session COMMITTED state. Upload-session creation now records its aggregate state and `resource.upload.created.v1` event atomically with the session and idempotency receipt. A bounded daemon sweep durably transitions elapsed sessions to EXPIRED with progress-version fencing and a status event. The final accepted chunk atomically emits OPEN -> CONTENT_RECEIVED; Resource commit emits CONTENT_RECEIVED -> COMMITTED; definite stored-content integrity failure emits CONTENT_RECEIVED -> FAILED. Each transition shares its aggregate snapshot and projection transaction. Lifecycle `version` is separate from chunk `progress_version`, preserving contiguous aggregate event revisions. Before BlobStore writes, durable operational reservations are recorded; accepted chunk receipts consume them transactionally. The single-instance daemon runs bounded orphan collection under durable GC fences and retries DELETING candidates after restart, retaining any shared digest with an accepted reference. This slice has not been built or tested; concurrency/crash recovery and provider deletion semantics still require verification. Safe encrypted-orphan collection is implemented in source but not production-qualified.

**Additional implemented slice (unverified):** Folder-selected uploads now pin typed `folder_import.relative_path` metadata in the resumable upload session, durable SQLite projection, aggregate-state snapshot, and idempotency payload; non-folder requests retain their prior canonical payload shape. The daemon validates normalized relative paths and requires the path to match the existing display name; Tauri checks the returned session metadata and the desktop includes the path in resume identity, including retry rewrites. Commit derives Resource provenance from the pinned session, not a second client value. Folder-derived Resources emit `resource.created.v2` so the closed v1 event/provenance contract remains unchanged. SQLite v1 is immutable; v2 additively adds upload lifecycle/progress and folder-provenance fields, chunk request/blob-GC recovery tables, and guards. Committed Resource IDs are recovered from status events where possible. Legacy digest-less sessions remain readable as history but cannot be resumed or committed; no path is inferred from legacy display names. The relative path is never used as a locator or authority. This source slice is not built or tested.

**Additional implemented slice (unverified):** The Library exposes a client-side **Pause upload** action for resumable multi-file imports. It waits for the current authenticated Operator request to settle, then starts no further chunk, file, or commit request; it does not send a server cancellation, mutate upload state, or delete accepted chunks. The UI retains its upload/request metadata and explains that the same unchanged file must be reselected to resume before the 24-hour session expiry. A commit already in flight is reported as committed. This is UI-only source and remains unbuilt/untested.

**Additional source-only slice (unverified):** Library search now exposes the existing server-side exact Resource `kind` and `freshness` filters. Tauri validates supported filter values and passes them to the authenticated Operator search route; changing a filter clears prior results/cursor and queries again, while load-more retains the same filters. Metadata mode can browse with an empty query using filters alone; content modes require search terms. Filters refine the chosen mode and do not bypass content limits, return implicit Task inputs, or grant Resource access. This source is unbuilt/untested.

selected path bytes only through the reserved authenticated Unix IPC operation; the
