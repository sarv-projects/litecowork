## E12-S01 — Remote installation and enrollment

Dependencies: E11-S05.

**Implement:** Headless service package/bootstrap/health, pairing/grants/OS capability descriptor and revocation; no separate remote task engine.

**Acceptance:** Same API/domain semantics; remote files require explicit roots; service identity isolated; least-privilege enrollment documented.

**Negative/race cases:** Unreachable host, wrong identity, outdated version, revoked principal.

**E12-S01-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E12-S01-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E12-S01-USER:** Enroll second workstation/server and inspect its actual capabilities. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.

## E12-S02 — Remote placement/continuation tests

Dependencies: E12-S01.

**Implement:** Resource freshness, environment/auth/dependency placement, remote leases and portable handoff with fencing.

**Acceptance:** Only eligible steps remote; results verified; local-only resources stay blocked; connectivity loss obeys recovery policy.

**Negative/race cases:** Remote partition during Effect, host reboot, provider auth expires, worktree unavailable.

**E12-S02-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E12-S02-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E12-S02-USER:** Execute code task remotely, disconnect mid-run and reconcile on reconnect. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.
