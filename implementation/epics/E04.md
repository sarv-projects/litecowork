## E04-S06 — Cross-agent LiteSPM capability bridges

Dependencies: E04-S04, E03-S11.

**Implement:** Implement AgentCapabilityBridge route qualification for LiteSPM-managed connector/MCP/plugin/skill capability packages. Route each exact capability for each agent as DIRECT_NATIVE_ATTACHMENT, LITECOWORK_GATEWAY, HOST_CONTEXT_ONLY, or UNSUPPORTED while preserving native-only extensions separately. Reuse one LiteSPM installation across agents when qualified.

**Acceptance:** One qualified LiteSPM package can be used through at least two compatible agents without duplicate per-agent install; grants/effects never widen; unsupported agent is explicit; native extension config is never rewritten to fake parity.

**Negative/race cases:** Package updated during active Task, bridge route differs after agent update, direct path cannot enforce grant, native MCP with same name as LiteSPM capability, package unavailable, agent B unsupported, malicious package metadata.

**E04-S06-CODE:** Unit/property/contract tests for every stated validation, state transition, stale-version guard, secret-redaction rule, and negative case. Validate exact API/schema/event/SQL fixtures and assert no extra authority is created.

**E04-S06-SYSTEM:** Execute the real lifecycle/protocol/package path on qualified OS/agent versions. Inject interruption/drift/restart/auth-expiry failures at meaningful boundaries; verify durable/local operational truth after restart. Record exact agent/module/OS/build versions.

**E04-S06-USER:** Install one real LiteSPM-managed package once, use it from two qualified agents with exact provenance, then switch to an unsupported agent and verify explicit incompatibility with no native-config mutation. Owner compares behavior with a prepared oracle/native harness where applicable and stores a sanitized review packet. Mock-only evidence cannot satisfy real-provider/lifecycle acceptance.

**Research/qualification gate:** Resolve every external behavior named by the story against current upstream protocol/package documentation and observed versioned behavior before claiming support. Record unsupported/unknown cells explicitly instead of inferring parity.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback/recovery, security review and CODE/SYSTEM/USER evidence must appear in the review packet. Decompose further if one review cycle cannot prove the whole story.
