## E04-S01 — Trust evaluation and credential boundary

Dependencies: E03-S05.

**Implement:** Implement PolicyEngine/Approval/grants/SecretLease/credential/egress ports under TrustService; OS secret store integration.

**Acceptance:** Approval != grant; delegated authority cannot exceed parent; secrets injected only at authorized boundary; audit redacted.

**Negative/race cases:** Approval replay, SSRF/DNS rebinding, expired SecretLease, malicious tool input.

**E04-S01-CODE:** Unit/property tests for the stated guards; contract request/response/event payload fixtures; real storage transaction checks. Assert the acceptance facts and rejection of every negative case above.

**E04-S01-SYSTEM:** Execute the implementation using its actual process/transport/provider. Inject the listed failures at before-admission, after-persist and before-response boundaries where meaningful; assert durable/UI/authority truth after restart. Record OS/build/provider versions.

**E04-S01-USER:** Prepare a connector action, deny/approve it and inspect audit without secret bytes. Owner checks expected outputs and permissions against a prepared oracle. Store a sanitized review packet. A mock-only run does not satisfy real-provider acceptance.

**Review gate:** Exact API/events/schema/SQL/projection references, changed paths, tests, telemetry, rollback and evidence must appear in the review packet. Decompose into smaller child stories if this cannot be demonstrated in one review cycle.
