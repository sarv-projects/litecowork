# LiteCowork Agent Portfolio — 2026-10-21 (roster revision)

**Status:** owner-directed roster revision. It supersedes
[`AGENT-PORTFOLIO-2026-10-16.md`](AGENT-PORTFOLIO-2026-10-16.md), which is kept as the
historical 15-entry snapshot. Scope references in
[`SCOPE.md`](SCOPE.md) and [`../docs/AGENT-CONTROL.md`](../docs/AGENT-CONTROL.md) point
here.

## What changed and why

- **Gemini CLI is not in the roster.** Google stopped serving Gemini CLI to consumer and
  free users on 2026-06-18 and moved that path to **Antigravity CLI**, which is the
  Google's own terminal agent (binary `agy`) and is the free entry point; the Antigravity
  IDE remains a separate product. Antigravity CLI replaces the Gemini CLI row.
- **OpenCode is tracked as the v2 line.** The ACP Registry still advertises OpenCode
  `1.18.34`, but LiteCowork's own probe qualifies the **v2** Server protocols
  (`2.0.26`, `2.0.28`; see [`../docs/AGENT-FABRIC.md`](../docs/AGENT-FABRIC.md) §probe
  contract) and the roster entry is written against v2. The registry's v1 line is not the
  LiteCowork qualification target.
- **The roster grew from 15 to 25 entries** at owner direction: the previously listed
  harnesses plus Command Code, Aider, Pi, Oh My Pi, Muse Code, Grok Build, MiMo Code,
  Devin CLI, Antigravity CLI, MiniMax Code, and Amp.

The **qualification-first set is unchanged** — Claude Code, Codex CLI, OpenCode, and Cline
CLI remain the agents explicitly named for qualification in
[`SCOPE.md`](SCOPE.md) — with Antigravity CLI as the Google slot. Every other entry is a
roster target whose adapter path is named below.

The status vocabulary is unchanged and still binds
([`AGENT-PORTFOLIO-2026-10-16.md`](AGENT-PORTFOLIO-2026-10-16.md) §Status vocabulary):
**Discovered** → **Profile observed** → **Module implemented** → **Protocol handshake** →
**Qualified support** (exact agent/module/version/OS with CODE + SYSTEM + owner USER
evidence). An entry in this roster is an implementation target, never a support claim.

## Axis B — hosted agent providers (the cloud volume)

The table above is **Axis A**: harnesses LiteCowork launches locally. Most users
actually buy **Axis B**: a provider that runs the agent in its own cloud. LiteCowork
connects the owner's account, leases the authority it needs, sends only what the owner
approved, and receives only what the provider exposes
([`../docs/AGENT-CONTROL.md`](../docs/AGENT-CONTROL.md) §Hosted agent providers). A
hosted provider is never a local `AgentModule` and never gets a local session locator.

| Provider tier | What LiteCowork would need to qualify it | Notes |
|---|---|---|
| Anthropic Claude Code (hosted) | account `Connection`, model/plan selection, hosted session + stream contract, file/patch return, and an effect-receipt contract equal to our own | Local `claude` CLI is Axis A; the hosted tier is a separate qualification |
| OpenAI Codex (hosted) | hosted task/session contract, artifact return, receipt equivalence | Local `codex` CLI / App Server is Axis A |
| GitHub Copilot cloud agents | connection, agent selection, async task/result contract | Local `copilot --acp` is Axis A |
| Cursor (cloud Composer/agents) | connection, agent/task contract, diff/artifact return | Local `cursor-agent acp` is Axis A |
| Cognition Devin (cloud) | connection, session/handoff contract, PR/artifact return, receipt equivalence | Devin CLI is Axis A with a cloud handoff |
| xAI Grok Build (hosted) | connection, model/plan selection, remote run contract | Data boundary applies to the hosted tier too |
| Google Antigravity (hosted) | connection, subagent/plan contract, artifact return | Local `agy` CLI is Axis A |
| Moonshot Kimi, MiniMax Code, Qwen Code (hosted) | connection, model selection, session contract | Each provider is qualified separately |
| Meta Muse Code (hosted) | connection, model selection, background-agent contract | Local `muse` CLI is Axis A |

Axis B is **not** yet qualified for any provider: no provider conformance record exists, so
the qualification matrix carries a hosted-provider axis with no passing row. That is a
build target, not a support claim.

## Checked, considered, and not added

These were checked during this revision and deliberately stay out of the roster. They remain
**discoverable in the catalog**; a registry row is not a support claim.

- **Gemini CLI** — dropped by owner direction; Google's own path moved to Antigravity CLI
  after consumer free serving ended on 2026-06-18.
- **Windsurf** — renamed **Devin Desktop** on 2026-06-02 and now hosts third-party agents
  (Codex, Claude Agent, OpenCode) over ACP, so it is covered by the Devin row and by the
  ACP module framework rather than a separate harness.
- **Zed, Continue.dev, Kilo Code, Roo Code, Replit Agent, Warp, Qoder CLI, CodeBuddy Code,
  OpenClaw, Hermes Agent, DimCode, Dirac, fast-agent, Minion Code, Nova, Poolside,
  Autohand Code, the Claude Agent ACP wrapper, the Codex ACP bridge, and the Muse ACP
  adapter** — IDE hosts, cloud products, ACP wrappers, or registry-only entries without a
  native local CLI contract verified in this pass. They are catalog candidates; a wrapper
  around another agent is never the native module for that agent.
- **Antigravity IDE, Cursor IDE, Devin Desktop** — IDE products, not local CLI harnesses;
  they are not AgentModule launch targets, and the same agent's CLI is the module.

## Consequences for the implementation queue

- The framework (AgentModule, AgentControlDescriptor, install/update/repair, credential
  slots, session-adapter interface) is the unit of work; each roster row is a thin adapter
  with its own version matrix, not a Core branch
  ([`../docs/AGENT-CONTROL.md`](../docs/AGENT-CONTROL.md) §18).
- The qualification-first set stays **Claude Code, Codex CLI, OpenCode (v2), Cline CLI**,
  plus **Antigravity CLI** as the Google slot.
- [`QUALIFICATION-MATRIX.md`](QUALIFICATION-MATRIX.md) must carry one row per roster entry;
  a row records an observation, never a qualification.
- Harnesses with a cloud or provider data boundary (Grok Build, Devin CLI, and any agent that
  transmits workspace context) are qualified as **provider egress** under the Trust and
  credential rules, not as local-only tools.
